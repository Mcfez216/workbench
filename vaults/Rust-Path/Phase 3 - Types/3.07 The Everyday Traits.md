# 3.07 The Everyday Traits

> [!abstract] Why this matters
> A handful of standard traits come up all the time. They decide whether a type can be printed, copied, compared or used as a key. Most can be added with one `#[derive(...)]` line.

## The ones you'll derive most

| Trait | Lets you | Derive it? |
|---|---|---|
| `Debug` | Print with `{:?}` | Almost always |
| `Clone` | Make a copy with `.clone()` | When copies make sense |
| `Copy` | Copy on assignment, like a number | Only for small, simple types |
| `PartialEq` | Compare with `==` | Usually |
| `Eq`, `Hash` | Use it as a `HashMap` key | For keys |
| `PartialOrd`, `Ord` | Compare with `<`, and sort | When there's a natural order |
| `Default` | Make a default value with `Default::default()` | Often |
| `Display` | Print with `{}` | Written by hand, not derived |

## An example

```rust
use std::collections::HashMap;
use std::fmt;

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
enum Rank {
    Recruit,
    Pilot,
    Commander,
}

#[derive(Debug, Clone, PartialEq, Default)]
struct Crew {
    name: String,
    missions: u32,
}

// Display is written by hand: it's how a person reads it
impl fmt::Display for Crew {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{} ({} missions)", self.name, self.missions)
    }
}

fn main() {
    let han = Crew { name: String::from("Han"), missions: 12 };
    let copy = han.clone();
    println!("{han} == {copy:?}? {}", han == copy);
    println!("default: {:?}", Crew::default());

    let mut ranks = vec![Rank::Commander, Rank::Recruit, Rank::Pilot];
    ranks.sort();                           // needs Ord
    let mut count: HashMap<Rank, u32> = HashMap::new();   // needs Eq and Hash
    *count.entry(Rank::Pilot).or_insert(0) += 1;
    println!("{ranks:?} {count:?}");
}
```

## Clone and Copy

`Clone` makes an explicit copy, with `.clone()`. It can be expensive, like copying a whole `Vec`.

`Copy` makes assignment copy instead of move. It's only allowed for types that are cheap and simple to copy, like numbers. A type with a `String` inside can't be `Copy`.

> [!sith] The dark side
> Deriving `Copy` on a big struct, so you don't have to think about moves. Every assignment then silently copies the whole thing. Keep `Copy` for small values.

## Check yourself

> [!question]- What do you need to derive to use a type as a HashMap key?
> PartialEq, Eq and Hash.

> [!question]- What's the difference between Clone and Copy?
> Clone makes a copy when you call .clone(), and it can be expensive. Copy makes assignment copy automatically, and it's only allowed for cheap, simple types.

> [!question]- Why is Display written by hand instead of derived?
> It's how a person should read the value, and only you know how that should look.
