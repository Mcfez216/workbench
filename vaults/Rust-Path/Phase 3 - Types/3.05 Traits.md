# 3.05 Traits

> [!abstract] Why this matters
> A **trait** is a set of methods that a type promises to have. It's how Rust says "anything that can be described" or "anything that can be compared". Traits replace C++'s base classes and interfaces, without inheritance.

## An example

```rust
trait Ship {
    fn name(&self) -> String;
    fn speed(&self) -> u32;

    // a default method: types get it for free, and can replace it
    fn describe(&self) -> String {
        format!("{} at {} MGLT", self.name(), self.speed())
    }
}

struct XWing;
struct Falcon {
    tuned: bool,
}

impl Ship for XWing {
    fn name(&self) -> String { String::from("X-wing") }
    fn speed(&self) -> u32 { 100 }
}

impl Ship for Falcon {
    fn name(&self) -> String { String::from("Millennium Falcon") }
    fn speed(&self) -> u32 { if self.tuned { 105 } else { 75 } }
    fn describe(&self) -> String { format!("the fastest hunk of junk: {} MGLT", self.speed()) }
}

// works with any type that has the Ship trait
fn race(a: &impl Ship, b: &impl Ship) -> String {
    if a.speed() >= b.speed() { a.name() } else { b.name() }
}

fn main() {
    let x = XWing;
    let f = Falcon { tuned: true };
    println!("{}", x.describe());
    println!("{}", f.describe());
    println!("winner: {}", race(&x, &f));

    // different types in one list: Box<dyn Ship>
    let fleet: Vec<Box<dyn Ship>> = vec![Box::new(XWing), Box::new(Falcon { tuned: false })];
    for s in &fleet {
        println!("- {}", s.name());
    }
}
```

## Two ways to use a trait

| Write | What it means |
|---|---|
| `&impl Ship` | Any one type with the trait. The compiler makes a version of the function for each type. |
| `&dyn Ship`, or `Box<dyn Ship>` | Any type with the trait, chosen while the program runs. This lets one list hold different types. |

## Try it

1. Click **Try in sandbox**, and run it.
2. Add a `struct TieFighter;` and `impl Ship for TieFighter`. Add one to the fleet.
3. Remove the `speed` method from `XWing`. Read the error: it says which method is missing.

> [!sith] The dark side
> Making one huge trait with ten methods. Every type then has to write all ten. Keep traits small, with one job each. A type can have as many traits as it needs.

## Check yourself

> [!question]- What is a trait?
> A set of methods that a type promises to have. Functions can then accept any type with that trait.

> [!question]- What is a default method in a trait?
> A method with code in the trait itself. Types get it for free, and can replace it with their own.

> [!question]- When do you need Box<dyn Trait> instead of impl Trait?
> When you need different types together, like in one Vec. impl Trait means one type, chosen while compiling.
