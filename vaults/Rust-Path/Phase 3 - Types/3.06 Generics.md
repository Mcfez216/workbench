# 3.06 Generics

> [!abstract] Why this matters
> **Generics** let you write one function or type that works with many types. `Vec<T>` works for any `T`. Your own code can do the same, and traits say what the type must be able to do.

## An example

```rust
// any type T that can be compared and copied
fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

// a generic struct
#[derive(Debug)]
struct Pair<T> {
    first: T,
    second: T,
}

impl<T: std::ops::Add<Output = T> + Copy> Pair<T> {
    fn sum(&self) -> T {
        self.first + self.second
    }
}

fn main() {
    println!("{}", largest(&[3, 9, 2]));
    println!("{}", largest(&['x', 'b', 'q']));
    println!("{}", largest(&[1.5, -2.0]));

    let p = Pair { first: 1.5, second: 2.25 };
    println!("{p:?} sums to {}", p.sum());
}
```

## Reading generic code

- `<T>` introduces a type name, like a variable for types.
- `T: PartialOrd + Copy` is a **trait bound**. It says `T` must have both traits. `PartialOrd` lets you compare with `>`. `Copy` lets you copy values out of the list.
- For a long list of bounds, you can write them after the signature, in a `where` clause.

## No cost while running

Like C++ templates, Rust makes a separate copy of the function for each type you use. So generic code runs as fast as code written for one type.

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove `+ Copy` from `largest`. Read the error: it can't move a value out of a borrowed list.
3. Call `largest` with an empty list, `&[] as &[i32]`. It panics. Change it to return `Option<T>` instead.

> [!sith] The dark side
> Making everything generic "just in case". Generic code is harder to read, and its errors are longer. Start with a concrete type, and make it generic when a second type really needs it.

## Check yourself

> [!question]- What does T: PartialOrd + Copy mean?
> T can be any type that can be compared with < and >, and copied.

> [!question]- Are generics slower than normal functions?
> No. Rust makes a separate copy of the code for each type, like C++ templates.
