# 3.04 Result and Errors

> [!abstract] Why this matters
> Programs fail: files go missing and people type the wrong thing. In Rust, a function that can fail says so in its type: it returns a `Result`. The `?` operator then passes errors up in one character. There are no exceptions to forget about, and no error codes to ignore.

## What Result is

`Result<T, E>` is an enum with two choices:

- `Ok(value)` when it worked,
- `Err(error)` when it didn't.

## An example

```rust
use std::num::ParseIntError;

fn parse_fuel(text: &str) -> Result<u32, ParseIntError> {
    let n: u32 = text.trim().parse()?;      // ? returns the error straight away
    Ok(n * 10)
}

fn total_fuel(items: &[&str]) -> Result<u32, String> {
    let mut total = 0;
    for item in items {
        total += parse_fuel(item).map_err(|e| format!("{item:?}: {e}"))?;
    }
    Ok(total)
}

fn main() {
    match parse_fuel(" 12 ") {
        Ok(f) => println!("fuel: {f}"),
        Err(e) => println!("not a number: {e}"),
    }
    println!("{:?}", total_fuel(&["1", "2", "3"]));
    println!("{:?}", total_fuel(&["1", "two", "3"]));
}
```

## The ? operator

In a function that returns a `Result`, `?` after a `Result` means:

- if it's `Ok(value)`, give me the value and carry on,
- if it's `Err(e)`, return `Err(e)` from this function, now.

`map_err` changes the error into another type first. Here it turns it into a `String` that says which item failed.

## panic or Result?

| Use | When |
|---|---|
| `Result` | Failure is normal and expected: bad input, a missing file. |
| A panic | Something that should be impossible happened: a bug. |

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `"two"` to `"2"`. Now the total works.
3. Remove the `?` after `.parse()`. Read the error: the types don't match, because it's still a `Result`.

> [!sith] The dark side
> `let _ = might_fail();`, which throws the `Result` away. The compiler warns when you ignore a `Result`, because ignoring an error is how bugs start. Handle it, or pass it on with `?`.

## Check yourself

> [!question]- What are the two choices of Result<T, E>?
> Ok(value), when it worked, and Err(error), when it didn't.

> [!question]- What does ? do with an Err?
> It returns that error from the current function straight away.

> [!question]- When should you panic instead of returning a Result?
> When something that should be impossible happens, meaning a bug. Normal failures, like bad input, should be a Result.
