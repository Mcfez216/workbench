# 3.03 Option

> [!abstract] Why this matters
> Rust has no null pointer. When a value might be missing, the type says so: `Option<T>`. The compiler then makes you handle the missing case before you can use the value. The "billion-dollar mistake" of null pointers simply can't happen.

## What Option is

`Option<T>` is an enum with two choices:

- `Some(value)` when there is a value,
- `None` when there isn't.

## An example

```rust
fn find_pilot(crew: &[&str], letter: char) -> Option<usize> {
    for (i, name) in crew.iter().enumerate() {
        if name.starts_with(letter) {
            return Some(i);
        }
    }
    None
}

fn main() {
    let crew = ["Han", "Leia", "Luke"];

    match find_pilot(&crew, 'L') {
        Some(i) => println!("first L at position {i}: {}", crew[i]),
        None => println!("no L"),
    }

    if let Some(i) = find_pilot(&crew, 'Z') {
        println!("found Z at {i}");
    } else {
        println!("no Z in the crew");
    }

    // handy methods
    let pos = find_pilot(&crew, 'Z').unwrap_or(0);
    let name = crew.first().copied().unwrap_or("nobody");
    let doubled = Some(21).map(|x| x * 2);
    println!("{pos} {name} {doubled:?}");
}
```

## The useful methods

| Method | What it does |
|---|---|
| `unwrap_or(x)` | The value, or `x` if it's `None` |
| `map(f)` | Changes the value inside, if there is one |
| `is_some()`, `is_none()` | Checks which it is |
| `unwrap()` | The value, or a panic if it's `None` |
| `expect("why")` | Like `unwrap`, with your message in the panic |

## Try it

1. Click **Try in sandbox**, and run it.
2. Add `let x = find_pilot(&crew, 'Z').unwrap();`. Run it. It panics: "called `Option::unwrap()` on a `None` value".
3. Click the **?** next to the panic, for an explanation.

> [!sith] The dark side
> Calling `.unwrap()` on every `Option`. It turns the compiler's safety back into a crash. Use `match`, `if let` or `unwrap_or` unless a missing value really is impossible.

## Check yourself

> [!question]- What are the two choices of Option<T>?
> Some(value), when there is a value, and None, when there isn't.

> [!question]- Why can't you forget to check for None?
> The value is inside the Option. You can't use it as a plain value until you've taken it out, and that means handling None.

> [!question]- What does unwrap_or(0) do?
> It gives the value if there is one, or 0 if it's None.
