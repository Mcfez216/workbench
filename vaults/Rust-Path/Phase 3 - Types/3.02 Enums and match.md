# 3.02 Enums and match

> [!abstract] Why this matters
> An **enum** is a type that's exactly one of several choices. Rust's enums are much more powerful than C's, because each choice can carry its own data. With `match`, the compiler makes sure you handle every choice.

## An example

```rust
enum Command {
    Jump { parsecs: u32 },      // a choice with named data
    Fire(u8),                   // a choice with one value
    Land,                       // a choice with no data
}

fn run(c: &Command) -> String {
    match c {
        Command::Jump { parsecs } if *parsecs > 20 => String::from("too far for one jump"),
        Command::Jump { parsecs } => format!("jumping {parsecs} parsecs"),
        Command::Fire(0) => String::from("out of torpedoes"),
        Command::Fire(n) => format!("firing {n} torpedoes"),
        Command::Land => String::from("landing"),
    }
}

fn main() {
    let orders = [Command::Jump { parsecs: 12 }, Command::Jump { parsecs: 40 }, Command::Fire(2), Command::Fire(0), Command::Land];
    for o in &orders {
        println!("{}", run(o));
    }
}
```

## match

- `match` compares a value with each **pattern**, from top to bottom. The first one that fits runs.
- Patterns can take values out: `Command::Fire(n)` puts the number in `n`.
- `if *parsecs > 20` is a **guard**: an extra condition for that arm.
- `_` matches anything. It's often used last, for "everything else".
- The compiler checks that every choice is handled. Forget one, and it won't compile.

## if let

When you only care about one choice, `if let` is shorter:

`if let Command::Fire(n) = order { println!("{n}"); }`

## Try it

1. Click **Try in sandbox**, and run it.
2. Add a new choice, `Hide`, to the enum. Build it. The error lists the arm you forgot in `match`.
3. Add the arm, and run it again.

> [!sith] The dark side
> Ending every `match` with `_ => {}`. Then, when you add a new choice later, the compiler can't remind you to handle it. Only use `_` when you really mean "everything else".

## Check yourself

> [!question]- How is a Rust enum more powerful than a C enum?
> Each choice can carry its own data, like Jump { parsecs: u32 } or Fire(u8).

> [!question]- What does the compiler check about a match?
> That every possible choice is handled. If one is missing, it won't compile.

> [!question]- When would you use if let instead of match?
> When you only care about one choice, and want to ignore the rest.
