# 2.01 Ownership and Moves

> [!abstract] Why this matters
> This is Rust's big idea. Every value has exactly one owner. When the owner goes away, the value is freed automatically. Because there's only ever one owner, memory can't be freed twice, and it can't be used after it's freed.

## The three rules

1. Each value has one **owner**, a variable that's responsible for it.
2. There's only one owner at a time.
3. When the owner goes out of **scope**, the value is **dropped**: its memory is freed.

A **scope** is the part of the code where a variable exists, usually up to the closing `}`.

## A move

```rust
fn main() {
    let a = String::from("Falcon");   // a owns the String
    let b = a;                        // the String MOVES to b
    // println!("{a}");               // a is empty now: this wouldn't compile
    println!("{b}");

    let x = 5;
    let y = x;                        // numbers are COPIED, not moved
    println!("{x} {y}");              // both still work
}                                     // b goes out of scope: the String is freed, once
```

When you write `let b = a;` with a `String`, the String **moves** to `b`. The name `a` can't be used any more. Only `b` owns it, so only `b` frees it.

Numbers are different. They're small and simple, so assigning one makes a **copy**. Both names keep working.

## Moving into a function

Passing a value to a function moves it too:

```rust
// This one doesn't compile, on purpose: it shows the E0382 error.
fn launch(ship: String) {
    println!("launching {ship}");
}                                     // ship is dropped here

fn main() {
    let falcon = String::from("Falcon");
    launch(falcon);                   // falcon moves into launch
    println!("{falcon}");             // E0382: borrow of moved value
}
```

The fix, in the next note, is to **borrow** the value instead of giving it away.

## Try it

1. Click **Try in sandbox** on the first example, and run it.
2. Remove the `//` from `println!("{a}");`. Build it, and read the error. It says where the value moved.
3. Try the second example. Click the **?** next to the error, then **rustc --explain E0382**.

> [!sith] The dark side
> Adding `.clone()` everywhere to stop "moved value" errors. It works, but each clone copies the whole value. Most of the time, the real fix is to borrow, which the next note shows.

## Check yourself

> [!question]- What are Rust's three ownership rules?
> Each value has one owner. There's only one owner at a time. When the owner goes out of scope, the value is dropped.

> [!question]- What happens to a after let b = a; when a is a String?
> The String moves to b. a can't be used any more, and the compiler stops you if you try.

> [!question]- Why are numbers copied instead of moved?
> They're small and simple, with nothing to free. Copying them is cheap and safe, so Rust copies them.
