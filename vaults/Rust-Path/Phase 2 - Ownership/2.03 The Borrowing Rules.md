# 2.03 The Borrowing Rules

> [!abstract] Why this matters
> Two simple rules stop a huge class of bugs, including ones that are hard to find in C++. Most "fighting the borrow checker" is really these two rules. Once you know them, the errors start to make sense.

## The two rules

1. At any moment you can have **either** many shared borrows (`&T`), **or** exactly one mutable borrow (`&mut T`). Never both.
2. A borrow must never outlive the value it borrows.

Think of a document. Many people can read it at once. Or one person can edit it. But nobody should edit it while others are halfway through reading it.

## Why rule 1 matters

```rust
// This one doesn't compile, on purpose: it shows the E0502 error.
fn main() {
    let mut crew = vec!["Han", "Leia"];
    let first = &crew[0];           // a shared borrow of crew...
    crew.push("Luke");              // ...but push needs a mutable borrow
    println!("{first}");            // and first is still being used here
}
```

`push` might need more room. Then it moves every element to a new, bigger block of memory. `first` would be left pointing at the old block, which has been freed.

In C++, this exact bug compiles and runs. It reads freed memory. AddressSanitizer calls it heap-use-after-free. In Rust, it doesn't compile.

## The fix

```rust
fn main() {
    let mut crew = vec!["Han", "Leia"];
    let first = crew[0];            // copy the value out (a &str is cheap to copy)
    crew.push("Luke");              // no borrow is active now
    println!("{first} leads a crew of {}", crew.len());
}
```

A borrow only lasts until its last use. So often the fix is to finish with the borrow first, or to copy the value out.

## Try it

1. Try the first example. Read the error. It names all three lines: the borrow, the change, and the later use.
2. Move `println!("{first}");` to just before `crew.push("Luke");`. Now it compiles. The borrow ends before the change.
3. Run the second example.

> [!sith] The dark side
> Reaching for `RefCell` or `unsafe` to get around this error. The error is usually pointing at a real bug. Reorder the code first.

## Check yourself

> [!question]- What are the two borrowing rules?
> You can have many shared borrows or one mutable borrow, but not both at once. And a borrow must never outlive the value it borrows.

> [!question]- Why can't you push to a Vec while holding a reference to one of its elements?
> push may move all the elements to a bigger block of memory. The reference would then point at freed memory.

> [!question]- How long does a borrow last?
> Until the last place it's used, not necessarily to the end of the block.
