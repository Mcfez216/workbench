# 2.02 Borrowing

> [!abstract] Why this matters
> Moving values everywhere would be awkward. Usually a function only needs to look at a value, or change it, and then give it back. That's **borrowing**. You'll do it constantly, so it's worth getting comfortable with it.

## Two kinds of borrow

| Write | What the function can do | Called |
|---|---|---|
| `&value` | Read it | a shared borrow, or a reference |
| `&mut value` | Read and change it | a mutable borrow |

Either way, the owner keeps the value. The borrow ends, and the owner can use it normally again.

## An example

```rust
fn length(s: &String) -> usize {      // borrows to read
    s.len()
}

fn refuel(tank: &mut u32, amount: u32) {   // borrows to change
    *tank += amount;                   // * goes to the borrowed value
}

fn main() {
    let ship = String::from("Falcon");
    let n = length(&ship);            // lend ship, get it back
    println!("{ship} has {n} letters");   // ship still works

    let mut fuel = 40;
    refuel(&mut fuel, 10);
    println!("fuel is now {fuel}");
}
```

- `&ship` lends `ship` to the function. When it returns, `main` still owns `ship`.
- `&mut fuel` lends `fuel` so the function can change it. The variable itself must be `mut` too.
- `*tank += amount` changes the value the borrow points to. The `*` means "the value it refers to". This is called **dereferencing**.

## A borrow is like a C pointer, with rules

Under the hood, a borrow is an address, like a pointer in C. The difference is that the compiler checks every borrow. It's never null, and it's never left pointing at something that's gone.

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `length(&ship)` to `length(ship)`. Read the error: "expected `&String`, found `String`".
3. Remove the `mut` from `let mut fuel`. Read the error, and its help line.

> [!sith] The dark side
> Taking ownership in a function that only reads, like `fn length(s: String)`. Every caller loses their value for no reason. Borrow with `&` unless the function really needs to keep the value.

## Check yourself

> [!question]- What's the difference between &value and &mut value?
> &value lends it to be read. &mut value lends it to be read and changed. Either way, the owner keeps it.

> [!question]- What does * do in *tank += amount?
> It goes to the value the borrow refers to, so the change happens to the real value. This is called dereferencing.

> [!question]- How is a Rust borrow different from a C pointer?
> The compiler checks every borrow. It can never be null, and it can never point at something that has been freed.
