# 2.06 Ownership Compared with C and C++

> [!abstract] Why this matters
> Ownership isn't a Rust invention. Good C and C++ code already has owners. In C, they're in comments. In C++, they're in `unique_ptr` and RAII. Rust's difference is that the compiler checks them. Seeing the three side by side makes all three languages easier.

## The same ideas, three ways

| Idea | C | C++ | Rust |
|---|---|---|---|
| Who frees it | You decide, and write a comment | A destructor (RAII) | The owner, automatically |
| One owner | A convention | `std::unique_ptr` | Every value, always |
| Shared owners | A convention | `std::shared_ptr` | `Rc`, or `Arc` across threads |
| Borrowing | A plain pointer | A reference or pointer | `&T` and `&mut T`, checked |
| "Maybe nothing" | `NULL` | `nullptr` or `std::optional` | `Option<T>` |
| Moving | Copy the pointer, then forget it | `std::move`, leaves a valid but empty object | The default for owned types; the old name can't be used |

## Bugs and where each language catches them

| Bug | C | C++ | Rust |
|---|---|---|---|
| Use after free | At run time, if ASan is on | At run time, if ASan is on | While compiling |
| Double free | At run time, with ASan | Rare with RAII; ASan otherwise | Can't happen |
| Reading past the end | ASan, if that path runs | ASan, or `.at()` | A panic at run time, always |
| Dangling reference into a vector | ASan | ASan | While compiling |
| Data race between threads | ThreadSanitizer, sometimes | ThreadSanitizer, sometimes | While compiling |
| Null pointer | A crash | A crash | No null: `Option` |

## The same program in Rust

The C vault's [[3.04 Ownership in C]] shows a `Pilot` with create and destroy functions, and a `goto` for cleanup. In Rust, all of that is automatic:

```rust
struct Pilot {
    name: String,
    scores: Vec<u32>,
}

impl Pilot {
    fn new(name: &str, n: usize) -> Pilot {
        Pilot { name: name.to_string(), scores: vec![0; n] }
    }
}

fn main() {
    let mut wedge = Pilot::new("Wedge Antilles", 3);
    wedge.scores[0] = 7;
    println!("{}: {}", wedge.name, wedge.scores[0]);
}   // wedge is dropped here: its String and Vec are freed. No destroy function.
```

There's no `destroy`, no `free`, and no cleanup label. If making the `String` failed halfway, Rust would still free whatever had been made.

## Try it

1. Read [[3.04 Ownership in C]] in the C vault, and compare it with the example.
2. Run the example. Then add a `println!` that uses `wedge` after it's moved into a function. Read the error.

> [!sith] The dark side
> Thinking Rust's checks mean you don't need to understand memory. You still choose between the stack and the heap, owning and borrowing, and copying and moving. Rust just tells you when you get it wrong.

## Check yourself

> [!question]- What is the C++ equivalent of a Rust value with one owner?
> std::unique_ptr, or any type with RAII. Rust applies the same idea to every value, and checks it while compiling.

> [!question]- Which bug can happen in C++ but not compile in Rust: a reference into a vector, then push_back?
> The dangling reference. In C++, push_back can move the elements and leave the reference pointing at freed memory. In Rust, the borrowing rules stop it compiling.

> [!question]- What replaces NULL in Rust?
> Option<T>. It's either Some(value) or None, and you must handle None before you can use the value.
