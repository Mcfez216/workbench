# 2.04 Slices

> [!abstract] Why this matters
> A **slice** borrows part of a list or a string, without copying it. Functions that take a slice work with arrays, Vecs and parts of them. It's the safe version of C's "pointer plus a length".

## Slices

| Type | Borrows |
|---|---|
| `&[T]` | Part, or all, of an array or a Vec |
| `&str` | Part, or all, of a string |

A slice knows its own length. So you never have to pass the length separately, like you do in C.

## An example

```rust
fn total(scores: &[i32]) -> i32 {            // any list of i32: array, Vec, or part of one
    let mut sum = 0;
    for s in scores {
        sum += s;
    }
    sum
}

fn first_word(text: &str) -> &str {
    match text.find(' ') {
        Some(i) => &text[..i],
        None => text,
    }
}

fn main() {
    let arr = [10, 20, 30, 40];
    let v = vec![1, 2, 3];
    println!("{} {} {}", total(&arr), total(&v), total(&arr[1..3]));   // 100 6 50

    let quote = String::from("Do or do not");
    println!("first word: {}", first_word(&quote));
    println!("last two: {:?}", &arr[arr.len() - 2..]);
}
```

- `&arr[1..3]` borrows elements 1 and 2.
- `&arr[..2]` is the start up to 2. `&arr[2..]` is from 2 to the end.
- `total` takes `&[i32]`, so it works with an array, a Vec, or part of either.

## Slices are checked

If you ask for `&arr[2..9]` on a 4-element array, the program stops with a panic. It never reads past the end.

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `&arr[1..3]` to `&arr[1..9]`. Run it. The panic names the line, and says the range is out of bounds.
3. Use `arr.get(1..9)` instead. It gives `None` rather than a panic.

> [!sith] The dark side
> Writing functions that take `&Vec<T>`. Take `&[T]` instead. It accepts more kinds of input, and costs nothing extra.

## Check yourself

> [!question]- What is a slice?
> A borrow of part, or all, of a list or a string. It knows its own length, and it doesn't copy anything.

> [!question]- What does &v[2..] give you?
> A slice of v from position 2 to the end.

> [!question]- Why take &[i32] instead of &Vec<i32>?
> &[i32] accepts arrays, Vecs and parts of them. &Vec<i32> only accepts a whole Vec.
