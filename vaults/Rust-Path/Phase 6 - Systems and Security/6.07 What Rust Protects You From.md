# 6.07 What Rust Protects You From

> [!abstract] Why this matters
> Rust stops a lot, but not everything. Knowing exactly where its protection ends is what makes a Rust programmer trustworthy, and stops "it's written in Rust" becoming an excuse.

## What Rust stops (in safe code)

| Bug | How |
|---|---|
| Use after free, double free | Ownership: one owner, freed once |
| Dangling references | Lifetimes: no borrow outlives its value |
| Reading past the end of an array | Every index is checked: a panic instead |
| Null pointers | There's no null: `Option` instead |
| Data races between threads | `Send` and `Sync`, and `Mutex` owning its data |
| Using a variable before it's set | The compiler won't allow it |

## What it doesn't stop

| Problem | Example |
|---|---|
| Logic bugs | Charging the wrong price, perfectly safely |
| Panics | `unwrap()` on `None`, or an index out of bounds: the program stops |
| Integer overflow in release builds | It wraps around silently, like C |
| Deadlocks | Two threads waiting for each other's locks |
| Memory leaks | An `Rc` cycle, or `Box::leak`: safe, but never freed |
| Bugs in `unsafe` code | Inside `unsafe`, it's your promise |
| Bad input handling | Trusting a file or a network message |

## Overflow, on purpose

```rust
fn main() {
    let fuel: u8 = 250;
    let extra: u8 = 10;
    println!("checked:    {:?}", fuel.checked_add(extra));       // None: too big
    println!("saturating: {}", fuel.saturating_add(extra));      // 255: stops at the limit
    println!("wrapping:   {}", fuel.wrapping_add(extra));        // 4: wraps, on purpose
    let (sum, overflowed) = fuel.overflowing_add(extra);
    println!("overflowing: {sum}, overflowed: {overflowed}");
}
```

A plain `fuel + extra` panics in a debug build, and silently gives 4 in a release build. When numbers come from outside the program, choose one of these methods on purpose.

## A leak is safe

`Box::leak` and `Rc` cycles never free their memory. Rust counts that as safe: nothing reads freed memory, the program just uses more memory. In a long-running server, that can still be a problem.

## Try it

1. Click **Try in sandbox**, and run it.
2. Add `let plain = fuel + extra;`. Rust refuses, because it can see the answer doesn't fit. Make `extra` come from `std::env::args().count()` instead, and run it: a panic.
3. Look back at the C vault's security notes. For each bug, decide which Rust protection would stop it.

> [!sith] The dark side
> "It's written in Rust, so it's secure." Rust removes the most common memory bugs. It doesn't check that your program does the right thing. Tests, fuzzing and code review are still needed.

## Check yourself

> [!question]- Name three bugs Rust prevents in safe code.
> Any of: use after free, double free, dangling references, reading past the end of an array, null pointers, and data races.

> [!question]- Name three problems Rust doesn't prevent.
> Any of: logic bugs, panics, integer overflow in release builds, deadlocks, memory leaks, and bugs inside unsafe code.

> [!question]- What does a plain + do on overflow in a debug build, and in a release build?
> In a debug build it panics. In a release build it wraps around silently.
