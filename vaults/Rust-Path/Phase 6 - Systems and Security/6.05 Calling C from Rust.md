# 6.05 Calling C from Rust

> [!abstract] Why this matters
> There's a huge amount of C code in the world, and Rust can call it directly. This is called **FFI**, the foreign function interface. It's how Rust is added to big C programs, like the Linux kernel, one piece at a time. It's also where unsafe code is most needed.

## Calling the C library

```rust
use std::ffi::{CStr, CString, c_char, c_int};

// declarations of C functions: Rust can't check them, so they're unsafe to call
unsafe extern "C" {
    fn abs(x: c_int) -> c_int;
    fn strlen(s: *const c_char) -> usize;
}

fn c_strlen(text: &str) -> usize {
    // CString adds the '\0' that C strings need, and refuses a '\0' in the middle
    let c = CString::new(text).expect("no '\\0' inside the text");
    // SAFETY: c is a valid C string, and it lives until after strlen returns
    unsafe { strlen(c.as_ptr()) }
}

fn main() {
    // SAFETY: abs is safe for any int except INT_MIN, and -42 isn't INT_MIN
    let a = unsafe { abs(-42) };
    println!("abs(-42) = {a}");
    println!("strlen(\"Falcon\") = {}", c_strlen("Falcon"));

    // turning a C string back into Rust
    let c = CString::new("Kessel").unwrap();
    let back: &CStr = c.as_c_str();
    println!("back in Rust: {}", back.to_str().unwrap());
}
```

## The pieces

| Rust | C |
|---|---|
| `unsafe extern "C" { fn f(...); }` | A function declaration from a header |
| `c_int`, `c_char`, `usize` | `int`, `char`, `size_t` |
| `CString` | A string you own, with the `'\0'` at the end |
| `&CStr` | A borrowed C string |
| `*const T`, `*mut T` | `const T *`, `T *` |
| `#[repr(C)] struct` | A struct with C's layout |

## The safe wrapper pattern

`c_strlen` is a **safe wrapper**. It does the unsafe call once, correctly, behind a normal Rust function. The rest of the program just calls `c_strlen`, and can't get the details wrong. Every good FFI library works like this.

## Calling your own C code

For your own C files, a Cargo project uses a `build.rs` file and the `cc` crate to compile them. The C vault's [[3.04 Ownership in C]] shows the create and destroy functions such a library would have. In Rust, you'd wrap them in a struct whose `Drop` calls the destroy function.

## Try it

1. Click **Try in sandbox**, and run it.
2. Try `CString::new("Fal\0con")`. It returns an error. A `'\0'` in the middle would cut the C string short.
3. Call `strlen` without `unsafe`. Read the error.

> [!sith] The dark side
> Passing a pointer to Rust data that's freed before the C code finishes with it. For example, `strlen(CString::new("x").unwrap().as_ptr())`. The `CString` is freed at the end of that line, so the pointer dangles. Keep the `CString` in a variable for as long as C uses it.

## Check yourself

> [!question]- Why is calling a C function unsafe in Rust?
> Rust can't check what the C code does with memory, so you have to promise it's used correctly.

> [!question]- What does CString do that a Rust String doesn't?
> It adds the '\0' that C expects at the end, and it refuses text with a '\0' in the middle.

> [!question]- What is a safe wrapper?
> A normal Rust function that makes the unsafe call correctly, so the rest of the program never has to use unsafe.
