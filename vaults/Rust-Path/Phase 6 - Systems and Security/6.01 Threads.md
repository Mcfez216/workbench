# 6.01 Threads

> [!abstract] Why this matters
> A **thread** is a part of your program that runs at the same time as the rest. Threads use all of a computer's cores, but in C and C++ they bring data races: two threads changing the same memory at once. Rust's compiler stops data races. This is often called "fearless concurrency".

## An example

```rust
use std::thread;

fn main() {
    let names = vec!["Red Leader", "Red Two", "Red Five"];

    // scoped threads: they may borrow, because they all end before the scope does
    let total: usize = thread::scope(|s| {
        let handles: Vec<_> = names
            .iter()
            .map(|name| s.spawn(move || {
                let work = name.len() * 1000;
                println!("{name} reporting in");
                work
            }))
            .collect();
        handles.into_iter().map(|h| h.join().unwrap()).sum()
    });
    println!("total work: {total}");

    // a thread that owns its data: move gives it the Vec
    let squadron = vec![1, 2, 3];
    let handle = thread::spawn(move || squadron.iter().sum::<i32>());
    println!("sum from the thread: {}", handle.join().unwrap());
}
```

- `thread::spawn` starts a thread. Its closure needs `move`, so the thread owns the data it uses.
- `join()` waits for a thread to finish, and gives back its result.
- `thread::scope` lets threads borrow local data, because they're all finished before the scope ends.

## How Rust stops data races

Two traits decide what can cross between threads:

| Trait | Means |
|---|---|
| `Send` | A value can be moved to another thread. |
| `Sync` | A value can be shared between threads, through `&`. |

The compiler adds them automatically to types that are safe. `Rc` isn't `Send`, because its counter isn't thread-safe. So sending an `Rc` to a thread doesn't compile. Use `Arc` instead.

## Try it

1. Click **Try in sandbox**, and run it. The order of "reporting in" can change between runs.
2. Remove `move` from the second `spawn`. Read the error: the thread might outlive `squadron`.
3. Make the second thread change `squadron`, while `main` also uses it. Read the error.

> [!sith] The dark side
> Ignoring the result of `join()`. If a thread panics, `join()` returns an `Err`, and that's your only way to know. `unwrap()` passes the panic on, which is fine in examples. In real code, handle it.

## Check yourself

> [!question]- What does join() do?
> It waits for a thread to finish, and gives back the thread's result, or an Err if it panicked.

> [!question]- Why does a thread's closure usually need move?
> The thread might run longer than the function that started it. move gives the thread ownership of the data, so it can't outlive it.

> [!question]- What do Send and Sync mean?
> Send: a value can be moved to another thread. Sync: it can be shared between threads through &. The compiler only lets safe types cross.
