# 6.02 Channels

> [!abstract] Why this matters
> Instead of threads sharing memory, they can send each other messages. A **channel** is a queue between threads: one end sends, the other receives. Since each message is owned by one thread at a time, there's nothing to fight over.

## An example

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();          // tx sends, rx receives

    let mut workers = Vec::new();
    for id in 1..=3 {
        let tx = tx.clone();                 // each worker gets its own sender
        workers.push(thread::spawn(move || {
            for scan in 0..2 {
                tx.send(format!("probe {id}, scan {scan}: all clear")).unwrap();
            }
        }));
    }
    drop(tx);                                // main's sender: done, so the loop below can end

    for message in rx {                      // waits for messages, until every sender is gone
        println!("{message}");
    }
    for w in workers {
        w.join().unwrap();
    }
}
```

- `mpsc` stands for "many producers, single consumer". Many threads can send, one receives.
- `send` moves the value into the channel. The sending thread can't use it afterwards.
- `for message in rx` waits for each message. It ends when every sender has been dropped.

## Why drop(tx)?

The loop over `rx` only ends when there are no senders left. `main` still had the original `tx`. Dropping it says "main won't send anything".

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove `drop(tx);`. Run it. It waits forever, because one sender is still alive. Stop it with Ctrl+C.
3. Try to use a String after sending it. Read the error.

> [!sith] The dark side
> Forgetting that a receiving loop waits until every sender is gone. A sender kept alive by accident makes the program hang, with no error. If it hangs, look for a sender that's still around.

## Check yourself

> [!question]- What is a channel?
> A queue between threads. One end sends values, the other receives them.

> [!question]- What happens to a value after send()?
> It moves into the channel. The sending thread can't use it any more.

> [!question]- When does a for loop over a receiver end?
> When every sender has been dropped.
