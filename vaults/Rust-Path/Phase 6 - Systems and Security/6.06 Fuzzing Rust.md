# 6.06 Fuzzing Rust

> [!abstract] Why this matters
> **Fuzzing** means feeding a program huge numbers of random, broken inputs, to find the ones that crash it. In C, a crash can be an exploitable memory bug. In Rust, it's usually a panic, but a panic in a server is still a way to knock it over. Fuzzing finds them before anyone else does.

## A tiny fuzzer

The real tool is `cargo fuzz`, which uses the same libFuzzer as MHDE's C fuzzing. It needs the nightly version of Rust. But the idea fits in a few lines:

```rust
// a parser for "NAME:AGE" records, with a bug in it
fn parse_record(input: &[u8]) -> Option<(String, u8)> {
    let text = std::str::from_utf8(input).ok()?;
    let colon = text.find(':')?;
    let name = text[..colon].to_string();
    let age = text[colon + 1..].parse().ok()?;
    let initial = name.as_bytes()[0];         // the bug: what if the name is empty?
    if initial.is_ascii_uppercase() { Some((name, age)) } else { None }
}

// a simple random number generator, so the example needs no libraries
fn next(seed: &mut u64) -> u64 {
    *seed ^= *seed << 13;
    *seed ^= *seed >> 7;
    *seed ^= *seed << 17;
    *seed
}

fn main() {
    let alphabet = b"Han:42 :x";
    let mut seed = 0x5eed;
    for round in 0..100_000 {
        let len = (next(&mut seed) % 6) as usize;
        let input: Vec<u8> = (0..len).map(|_| alphabet[(next(&mut seed) % alphabet.len() as u64) as usize]).collect();
        let result = std::panic::catch_unwind(|| parse_record(&input));
        if result.is_err() {
            println!("round {round}: {:?} makes it panic", String::from_utf8_lossy(&input));
            return;
        }
    }
    println!("no panics found");
}
```

It makes random inputs from a few useful characters, and tries each one. Within a few thousand rounds it finds `":5"`, or something like it: an empty name, so `name.as_bytes()[0]` panics.

## The fix

Ask instead of assuming: `let initial = *name.as_bytes().first()?;`. An empty name now gives `None`, which the caller already handles.

## cargo fuzz

```bash
rustup toolchain install nightly
cargo install cargo-fuzz
cargo fuzz init
cargo +nightly fuzz run fuzz_target_1
```

Its inputs are smarter than random ones. It watches which code each input reaches, and keeps the ones that go somewhere new.

## Try it

1. Click **Try in sandbox**, and run it. It prints the input that caused the panic.
2. Make the fix above. Run it again: "no panics found".
3. Add another bug, like `age / (name.len() as u8 - 3)`, and see how quickly it's found.

> [!sith] The dark side
> Thinking "it's Rust, so it can't crash". Panics, endless loops and using up all the memory are all still possible. For any code that reads input from outside, fuzz it.

## Check yourself

> [!question]- What is fuzzing?
> Feeding a program huge numbers of random or broken inputs, to find the ones that make it crash or misbehave.

> [!question]- In Rust, what does fuzzing usually find?
> Panics, like an index past the end or an unwrap on None. In a server, a panic can still be used to knock it over.

> [!question]- How is cargo fuzz smarter than random inputs?
> It watches which code each input reaches, and keeps building on the inputs that reach new code.
