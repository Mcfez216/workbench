# 4.03 Iterators

> [!abstract] Why this matters
> An **iterator** goes through values one at a time. Rust's iterator methods, like `filter`, `map` and `sum`, let you say what a loop is for, instead of writing it out. They compile into the same fast machine code as a hand-written loop.

## An example

```rust
fn main() {
    let scores = vec![42, 7, 99, 7, 13, 64];

    let total: i32 = scores.iter().sum();
    let big: Vec<i32> = scores.iter().copied().filter(|&s| s > 20).collect();
    let doubled: Vec<i32> = scores.iter().map(|s| s * 2).collect();
    let sevens = scores.iter().filter(|&&s| s == 7).count();
    let best = scores.iter().max();
    let first_big = scores.iter().position(|&s| s > 50);
    let all_positive = scores.iter().all(|&s| s > 0);

    println!("total {total}, big {big:?}");
    println!("doubled {doubled:?}");
    println!("{sevens} sevens, best {best:?}, first over 50 at {first_big:?}, all positive: {all_positive}");

    // chains read from top to bottom
    let crew = ["han", "leia", "luke", "chewie"];
    let names: Vec<String> = crew
        .iter()
        .filter(|n| n.starts_with('l'))
        .map(|n| n.to_uppercase())
        .collect();
    println!("{names:?}");

    // with positions, and pairs from two lists
    for (i, n) in crew.iter().enumerate().skip(2) {
        println!("{i}: {n}");
    }
    let ranks = [1, 2, 3, 4];
    let pairs: Vec<(&&str, &i32)> = crew.iter().zip(ranks.iter()).collect();
    println!("{:?}", pairs[0]);
}
```

## The ones to learn first

| Method | What it does |
|---|---|
| `iter()` | Goes through borrowed items |
| `filter(test)` | Keeps the items that pass |
| `map(f)` | Changes each item |
| `collect()` | Gathers the results into a `Vec`, `String`, `HashMap`... |
| `sum()`, `count()`, `max()`, `min()` | One answer from all the items |
| `any(test)`, `all(test)` | Is it true for some, or for every item? |
| `find(test)`, `position(test)` | The first one that passes, or its position |
| `enumerate()` | Adds each item's position |
| `zip(other)` | Pairs items from two lists |
| `take(n)`, `skip(n)` | Only the first n, or all but the first n |

## Iterators are lazy

Nothing happens until something asks for the values, like `collect`, `sum` or a `for` loop. A chain of `filter` and `map` makes no temporary lists along the way.

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove `.collect()` from the `big` line. Read the error. Without it, `big` is just the plan, not the values.
3. Write a chain that finds the sum of the squares of the odd scores.

> [!sith] The dark side
> Writing very long chains on one line. Put each step on its own line, like the `names` example. Then each step reads as one sentence.

## Check yourself

> [!question]- Are iterator chains slower than for loops?
> No. The compiler turns them into the same machine code as a hand-written loop.

> [!question]- What does collect() do?
> It runs the chain, and gathers the results into a collection, like a Vec.

> [!question]- What does "iterators are lazy" mean?
> Nothing is worked out until something asks for the values, like collect, sum or a for loop.
