# 4.02 HashMap and HashSet

> [!abstract] Why this matters
> "Look this up by name" and "have I seen this before?" are two of the most common jobs in programming. `HashMap` and `HashSet` do them quickly. The `entry` API makes counting and grouping a one-liner.

## An example

```rust
use std::collections::{BTreeMap, HashMap, HashSet};

fn main() {
    let mut bounty: HashMap<&str, u32> = HashMap::new();
    bounty.insert("Han", 25000);
    bounty.insert("Chewie", 10000);
    bounty.insert("Han", 30000);            // replaces the old value

    if let Some(b) = bounty.get("Han") {
        println!("Han: {b}");
    }
    println!("Boba: {:?}", bounty.get("Boba"));   // None: not there

    // counting with entry
    let mut sightings: HashMap<&str, u32> = HashMap::new();
    for planet in ["Tatooine", "Hoth", "Tatooine", "Endor", "Tatooine"] {
        *sightings.entry(planet).or_insert(0) += 1;
    }
    println!("Tatooine seen {} times", sightings["Tatooine"]);

    // have I seen this?
    let mut seen = HashSet::new();
    for code in [5, 1, 5, 3, 1] {
        if !seen.insert(code) {
            println!("{code} again");
        }
    }

    // BTreeMap keeps its keys sorted
    let sorted: BTreeMap<_, _> = sightings.into_iter().collect();
    println!("{sorted:?}");
}
```

## Which one?

| Type | Holds | Order |
|---|---|---|
| `HashMap<K, V>` | key → value | None: the order can change |
| `BTreeMap<K, V>` | key → value | Sorted by key |
| `HashSet<T>` | Each value once | None |
| `BTreeSet<T>` | Each value once | Sorted |

## The entry API

`map.entry(key)` finds the place for a key. Then:

- `.or_insert(0)` puts in 0 if the key is new, and gives you a mutable reference to the value.
- `*... += 1` adds one to it.

It looks the key up only once.

## Try it

1. Click **Try in sandbox**, and run it.
2. Print `bounty` with `{:?}` a few times, in separate runs. The order can change. That's normal for a `HashMap`.
3. Change `sightings["Tatooine"]` to `sightings["Naboo"]`. It panics, because indexing needs the key to exist. Use `.get()` instead.

> [!sith] The dark side
> Relying on a `HashMap`'s order, for example in test output. It's random on purpose, to make some attacks harder. Use `BTreeMap` when you need an order.

## Check yourself

> [!question]- What does map.entry(key).or_insert(0) give you?
> A mutable reference to the value for that key. If the key was new, it's set to 0 first.

> [!question]- What does HashSet::insert return?
> true if the value was new, and false if it was already in the set.

> [!question]- When would you use a BTreeMap instead of a HashMap?
> When you need the keys kept in sorted order.
