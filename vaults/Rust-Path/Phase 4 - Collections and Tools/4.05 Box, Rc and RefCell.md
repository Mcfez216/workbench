# 4.05 Box, Rc and RefCell

> [!abstract] Why this matters
> Most Rust values have one owner, and live on the stack or inside a collection. Sometimes you need more: a value on the heap, a value with several owners, or a value you need to change through a shared borrow. These three **smart pointers** handle those cases.

## The three

| Type | What it's for | C++ is like |
|---|---|---|
| `Box<T>` | One value on the heap, with one owner | `std::unique_ptr<T>` |
| `Rc<T>` | One value, shared by several owners. It's freed when the last owner goes. | `std::shared_ptr<T>` |
| `RefCell<T>` | Changing a value through a shared borrow, with the borrowing rules checked while the program runs | Nothing quite like it |

## An example

```rust
use std::cell::RefCell;
use std::rc::Rc;

// a recursive type needs a Box: otherwise it would contain itself forever
enum Route {
    Stop(&'static str),
    Hop(&'static str, Box<Route>),
}

// walk the route: each Hop leads to the rest of it
fn stops(r: &Route) -> Vec<&'static str> {
    match r {
        Route::Stop(p) => vec![p],
        Route::Hop(p, rest) => {
            let mut all = vec![*p];
            all.extend(stops(rest));
            all
        }
    }
}

fn main() {
    let route = Route::Hop("Tatooine", Box::new(Route::Hop("Alderaan", Box::new(Route::Stop("Yavin")))));
    println!("route: {}", stops(&route).join(" -> "));

    // Rc: two ships share one hangar log
    let log = Rc::new(RefCell::new(Vec::<String>::new()));
    let falcon_log = Rc::clone(&log);       // a second owner, not a copy of the Vec
    let xwing_log = Rc::clone(&log);
    println!("owners: {}", Rc::strong_count(&log));

    // RefCell: change the Vec through a shared Rc
    falcon_log.borrow_mut().push(String::from("Falcon landed"));
    xwing_log.borrow_mut().push(String::from("X-wing landed"));
    println!("{:?}", log.borrow());
}
```

## Rc and RefCell together

`Rc<T>` only gives shared borrows, because several owners might be reading. To change the value inside, wrap it in a `RefCell`. `borrow()` reads, and `borrow_mut()` changes. The borrowing rules are checked while the program runs: two `borrow_mut()` at once is a panic.

`Rc` is for one thread. Across threads, use `Arc` and `Mutex` instead, from [[6.03 Shared State - Mutex and Arc]].

## Try it

1. Click **Try in sandbox**, and run it.
2. Hold two mutable borrows at once: `let a = log.borrow_mut(); let b = log.borrow_mut();`. It panics with "already borrowed".
3. Remove the `Box` from the `Route` enum. Read the error: "recursive type has infinite size".

> [!sith] The dark side
> Using `Rc<RefCell<T>>` everywhere, to get C++-style shared objects. It works, but it moves the borrow checks from compile time to run time, where they become panics. Most designs don't need it. Try plain ownership first.

## Check yourself

> [!question]- What is Box<T> for?
> Putting one value on the heap, with one owner. It's needed for recursive types, and for trait objects like Box<dyn Trait>.

> [!question]- What does Rc::clone do?
> It adds another owner of the same value. It doesn't copy the value. The value is freed when the last owner goes.

> [!question]- What happens if you call borrow_mut() twice at once on a RefCell?
> The program panics, because the borrowing rules are checked while it runs.
