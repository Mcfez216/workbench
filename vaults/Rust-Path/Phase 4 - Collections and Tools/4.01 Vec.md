# 4.01 Vec

> [!abstract] Why this matters
> `Vec<T>` is a list that grows. It's the collection you'll use most, like `std::vector` in C++. It owns its elements, frees them when it's dropped, and checks every index.

## An example

```rust
fn main() {
    let mut crew: Vec<String> = Vec::new();
    crew.push(String::from("Rey"));
    crew.push(String::from("Finn"));
    let mut scores = vec![42, 7, 99];      // vec! makes one with values

    println!("{} crew, first {}", crew.len(), crew[0]);

    // safe access: get gives an Option instead of panicking
    match scores.get(10) {
        Some(s) => println!("score {s}"),
        None => println!("there's no score 10"),
    }

    // change each element through a mutable borrow
    for s in &mut scores {
        *s += 1;
    }
    scores.sort();
    scores.retain(|&s| s > 10);            // keep only some
    let last = scores.pop();               // remove the last one: Option
    println!("{scores:?}, popped {last:?}");

    // capacity: room before it needs to grow
    let mut big: Vec<u32> = Vec::with_capacity(100);
    big.extend(0..5);
    println!("{} items, room for {}", big.len(), big.capacity());
}
```

## Going through a Vec

| Write | You get | The Vec afterwards |
|---|---|---|
| `for x in &v` | `&T`, to read each item | Still yours |
| `for x in &mut v` | `&mut T`, to change each item | Still yours, changed |
| `for x in v` | `T`, each item itself | Used up: it moved into the loop |

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `scores.get(10)` to `scores[10]`. It panics, naming the line and the length.
3. Change `for s in &mut scores` to `for s in scores`. Read the error on the next line.

> [!sith] The dark side
> Holding a reference to an element while pushing to the Vec. In C++, that's a dangling reference. In Rust, it won't compile, as [[2.03 The Borrowing Rules]] showed. Take the value out first, or use positions.

## Check yourself

> [!question]- What's the difference between v[i] and v.get(i)?
> v[i] gives the element, or panics if i is past the end. v.get(i) gives an Option: Some(&element), or None.

> [!question]- What happens to a Vec after for x in v?
> It's used up: each element moves into the loop, and the Vec can't be used afterwards.

> [!question]- What does retain do?
> It keeps only the elements that pass a test, and removes the rest.
