# 4.07 Testing

> [!abstract] Why this matters
> Testing is built into Rust and Cargo. There's nothing to install. Write a function, mark it `#[test]`, and `cargo test` (F7) runs it. Tests are how you know your code works, and how you know it still works after you change it.

## An example

```rust
pub fn fuel_for(parsecs: u32) -> Option<u32> {
    parsecs.checked_mul(10)
}

pub fn parse_parsecs(text: &str) -> Result<u32, String> {
    text.trim().parse().map_err(|_| format!("not a distance: {text}"))
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn twelve_parsecs() {
        assert_eq!(fuel_for(12), Some(120));
    }

    #[test]
    fn too_far_is_none_not_a_wrap() {
        assert_eq!(fuel_for(u32::MAX), None);
    }

    #[test]
    fn bad_text_is_an_error() {
        assert!(parse_parsecs("far").is_err());
        assert_eq!(parse_parsecs(" 12 "), Ok(12));
    }

    #[test]
    #[should_panic(expected = "index out of bounds")]
    fn indexing_past_the_end_panics() {
        let v = vec![1, 2, 3];
        let i = v.len();
        let _ = v[i];
    }
}
```

## The tools

| Write | What it does |
|---|---|
| `#[test]` | Marks a test |
| `assert_eq!(a, b)` | Fails, showing both values, if they're different |
| `assert!(condition)` | Fails if the condition is false |
| `assert!(cond, "message {x}")` | The same, with your own message |
| `#[should_panic]` | The test passes only if the code panics |
| `#[cfg(test)]` | Only build this module when testing |

## Where tests go

- **Unit tests** sit at the bottom of the file they test, in `mod tests`. They can use private functions.
- **Integration tests** go in a `tests/` folder in the project. They use your library from outside, like a real user would.

## Try it

1. Choose File → New project, **Rust**, **Library + tests**.
2. Paste this example into `src/lib.rs`. Press F7. Four tests pass.
3. Break `fuel_for` on purpose: change `10` to `11`. Press F7. Problems shows `left` and `right` for the failing test.
4. Click a test in the Tests sidebar to jump to it.

> [!sith] The dark side
> Only testing the easy case. The bugs live in the edges: empty input, zero, the biggest value, and text that isn't what you expected. Write one test for each.

## Check yourself

> [!question]- How do you mark a function as a test?
> Put #[test] on the line above it.

> [!question]- What does #[cfg(test)] on the tests module do?
> It only builds that module when running the tests, so the tests aren't part of the finished program.

> [!question]- What's the difference between unit tests and integration tests in Rust?
> Unit tests sit in the same file as the code, and can use private functions. Integration tests go in the tests/ folder, and use the library from outside.
