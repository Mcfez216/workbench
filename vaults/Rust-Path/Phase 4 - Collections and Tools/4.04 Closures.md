# 4.04 Closures

> [!abstract] Why this matters
> A **closure** is a small function without a name, written right where you need it. Like `|s| s > 20` in the last note. Closures can use variables from around them, and Rust's borrow rules decide how.

## An example

```rust
fn apply_twice(f: impl Fn(i32) -> i32, x: i32) -> i32 {
    f(f(x))
}

fn make_adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n                  // move: the closure takes its own copy of n
}

fn main() {
    let limit = 20;
    let is_big = |s: i32| s > limit;            // borrows limit
    println!("{} {}", is_big(42), is_big(7));

    let mut count = 0;
    let mut bump = || count += 1;               // borrows count mutably
    bump();
    bump();
    println!("count {count}");

    let add5 = make_adder(5);
    println!("{}", apply_twice(&add5, 1));       // 11
    println!("{}", apply_twice(|x| x * 3, 2));   // 18

    let mut crew = vec!["Rey", "Finn", "Poe"];
    crew.sort_by_key(|name| name.len());
    println!("{crew:?}");
}
```

## How a closure uses outside variables

| The closure... | It's a... | Example |
|---|---|---|
| Only reads them | `Fn` | `\|s\| s > limit` |
| Changes them | `FnMut` | `\|\| count += 1` |
| Takes ownership of them | `FnOnce` | `move \|\| drop(name)` |

`move` before a closure makes it take ownership of what it uses. You need it when the closure outlives the variables, like when you return it, or send it to a thread.

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove `move` from `make_adder`. Read the error: `n` would be gone when the closure runs.
3. Add `println!("{count}");` between the two `bump()` calls. Read the error: `count` is still mutably borrowed by `bump`.

> [!sith] The dark side
> Reaching for `move` and `.clone()` until it compiles, without asking why. The error is telling you how long each value needs to live. Read it once properly. It'll save you the next ten times.

## Check yourself

> [!question]- What is a closure?
> A small function without a name, written where it's used. It can use variables from around it.

> [!question]- What does move do on a closure?
> The closure takes ownership of the variables it uses, instead of borrowing them.

> [!question]- What's the difference between Fn and FnMut?
> An Fn closure only reads the variables it uses. An FnMut closure changes them.
