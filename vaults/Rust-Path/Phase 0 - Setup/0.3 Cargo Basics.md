# 0.3 Cargo Basics

> [!abstract] Why this matters
> Almost every Rust program is a Cargo project. Cargo builds it, runs it, tests it, and downloads any libraries it uses. One tool does what CMake, a package manager and a test runner do for C++.

## A Cargo project

A Cargo project is a folder like this:

```
fleet/
  Cargo.toml      the project's name, version, edition and libraries
  src/main.rs     the program
  target/         what cargo builds (don't edit it, and don't commit it)
```

`Cargo.toml` looks like this:

```toml
[package]
name = "fleet"
version = "0.1.0"
edition = "2024"

[dependencies]
```

The **edition** is the version of the Rust language the project uses. This vault uses 2024.

## A library with tests

A project can also be a **library**: code for other programs to use. Its code is in `src/lib.rs`. The tests usually sit at the bottom of the same file:

```rust
pub fn add(a: i64, b: i64) -> i64 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn adds_two_numbers() {
        assert_eq!(add(2, 3), 5);
    }
}
```

- `#[test]` marks a function as a test.
- `assert_eq!(a, b)` checks that a equals b. If not, the test fails and shows both values.
- `#[cfg(test)]` means "only build this when running the tests".

## Try it

1. Choose File → New project. Pick **Rust** and **Library + tests**. Call it `fleet`.
2. Press F9 to build it.
3. Press F7 to run the tests. The Tests sidebar ticks off both.
4. In `lib.rs`, change `a + b` to `a - b`. Press F7 again.
5. One test fails. Problems shows `left: -1`, `right: 5`, at the line of the check.

> [!sith] The dark side
> Committing the `target/` folder to git. It's huge, and it's rebuilt anyway. New projects come with a `.gitignore` that leaves it out.

## Check yourself

> [!question]- What goes in Cargo.toml?
> The project's name, version and Rust edition, and the libraries it depends on.

> [!question]- Where do a library's tests usually go?
> At the bottom of the same file, in a module marked #[cfg(test)], with each test marked #[test].

> [!question]- What does assert_eq!(a, b) do when a and b are different?
> It makes the test fail, and shows both values, as left and right.
