# 5.03 Graphs

> [!abstract] Why this matters
> A **graph** is a set of places, called nodes, joined by connections, called edges. Maps, social networks and computer networks are all graphs. Two searches answer most questions about them.

## Storing a graph

The usual way is an **adjacency list**: for each node, a list of its neighbours. In Rust, that's a `Vec<Vec<usize>>`. Using positions instead of references keeps the borrow checker happy.

## Breadth-first search

**Breadth-first search** visits the nearest nodes first, then the ones two steps away, and so on. It finds the fewest number of hops between two nodes.

```rust
use std::collections::VecDeque;

fn fewest_hops(edges: &[Vec<usize>], from: usize, to: usize) -> Option<usize> {
    let mut dist = vec![None; edges.len()];
    let mut queue = VecDeque::new();
    dist[from] = Some(0);
    queue.push_back(from);
    while let Some(node) = queue.pop_front() {
        if node == to {
            return dist[node];
        }
        for &next in &edges[node] {
            if dist[next].is_none() {
                dist[next] = Some(dist[node].unwrap() + 1);
                queue.push_back(next);
            }
        }
    }
    None
}

fn main() {
    let names = ["Tatooine", "Alderaan", "Yavin", "Hoth", "Dagobah"];
    // each line: the neighbours of that planet
    let edges = vec![
        vec![1, 2],     // Tatooine - Alderaan, Yavin
        vec![0, 3],     // Alderaan - Tatooine, Hoth
        vec![0, 3],     // Yavin - Tatooine, Hoth
        vec![1, 2],     // Hoth - Alderaan, Yavin
        vec![],         // Dagobah: no routes
    ];
    match fewest_hops(&edges, 0, 3) {
        Some(n) => println!("{} to {}: {n} hops", names[0], names[3]),
        None => println!("no route"),
    }
    println!("to Dagobah: {:?}", fewest_hops(&edges, 0, 4));
}
```

- `VecDeque` is a queue: add at the back, take from the front.
- `dist` remembers how far each node is. `None` means "not reached yet".
- `while let Some(node) = queue.pop_front()` loops until the queue is empty.

## Depth-first, and shortest distances

- **Depth-first search** goes as deep as it can along one path before trying another. It's good for "can I get there at all?", and is easy to write with recursion.
- When edges have different lengths, **Dijkstra's algorithm** finds the shortest total distance. It uses `std::collections::BinaryHeap`. Project R04 builds it.

> [!sith] The dark side
> Storing a graph as nodes that hold references to each other. The borrow checker will fight you every step, because the nodes point at each other. Store them in a `Vec`, and use positions for the edges.

## Check yourself

> [!question]- What is an adjacency list?
> For each node, a list of its neighbours. In Rust, usually a Vec<Vec<usize>>.

> [!question]- What does breadth-first search find?
> The fewest number of hops from one node to another.

> [!question]- Why use positions instead of references for a graph's edges in Rust?
> Nodes that refer to each other break the borrowing rules. Positions into a Vec have no such problem.
