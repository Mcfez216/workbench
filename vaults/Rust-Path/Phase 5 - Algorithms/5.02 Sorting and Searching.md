# 5.02 Sorting and Searching

> [!abstract] Why this matters
> Sorting and searching are in almost every program. Rust's standard library does both well. Knowing how to sort by your own rules, and how to search sorted data quickly, covers most of what you'll need.

## An example

```rust
#[derive(Debug, Clone)]
struct Pilot {
    name: &'static str,
    kills: u32,
}

fn main() {
    let mut scores = vec![42, 7, 99, 13, 64];
    scores.sort();                                   // smallest first
    println!("{scores:?}");
    scores.sort_by(|a, b| b.cmp(a));                 // biggest first
    println!("{scores:?}");

    let mut squad = vec![
        Pilot { name: "Wedge", kills: 7 },
        Pilot { name: "Biggs", kills: 2 },
        Pilot { name: "Luke", kills: 9 },
    ];
    squad.sort_by_key(|p| p.kills);                  // by one field
    let names: Vec<&str> = squad.iter().map(|p| p.name).collect();
    println!("{names:?}");

    // binary search: only on sorted data
    let sorted = [3, 8, 15, 23, 42];
    match sorted.binary_search(&23) {
        Ok(i) => println!("23 is at {i}"),
        Err(i) => println!("not there; it would go at {i}"),
    }
    println!("{:?}", sorted.binary_search(&10));     // Err(2)

    // the smallest or biggest by a key
    let ace = squad.iter().max_by_key(|p| p.kills).unwrap();
    println!("ace: {}", ace.name);
}
```

## The tools

| Method | What it does |
|---|---|
| `sort()` | Sorts in order. It's stable: equal items keep their order. |
| `sort_unstable()` | Usually a bit faster, but equal items may swap. |
| `sort_by(\|a, b\| ...)` | Sorts by your own comparison |
| `sort_by_key(\|x\| ...)` | Sorts by one value from each item |
| `binary_search(&x)` | Finds x in sorted data, in O(log n). `Ok(position)`, or `Err(where it would go)`. |
| `max_by_key`, `min_by_key` | The biggest or smallest by one value |

## Sorting decimals

`f64` can't use plain `sort()`, because of NaN, the special "not a number" value. Use `v.sort_by(|a, b| a.total_cmp(b))`.

## Try it

1. Click **Try in sandbox**, and run it.
2. Sort the squad by name instead, with `sort_by_key(|p| p.name)`.
3. Try `vec![2.5, 1.0].sort()`. Read the error, then fix it with `total_cmp`.

> [!sith] The dark side
> Using `binary_search` on data that isn't sorted. It doesn't fail. It just gives wrong answers. Sort first, or use `iter().position()` instead.

## Check yourself

> [!question]- What does binary_search return when the value isn't there?
> Err with the position where it would go, to keep the list sorted.

> [!question]- How do you sort a Vec of structs by one field?
> v.sort_by_key(|x| x.field)

> [!question]- Why can't you call sort() on a Vec<f64>?
> Decimals include NaN, which can't be ordered. Use sort_by with total_cmp instead.
