# 5.01 Recursion and Speed

> [!abstract] Why this matters
> Some problems are easiest to solve with a function that calls itself. That's **recursion**. And knowing how the work grows as the input grows tells you whether a program will finish in a second or in a year.

## Recursion

A recursive function needs two parts:

1. a **base case**, small enough to answer directly,
2. a step that makes the problem smaller, and calls itself.

```rust
use std::collections::HashMap;

fn factorial(n: u64) -> u64 {
    if n <= 1 { 1 } else { n * factorial(n - 1) }
}

// slow: works out the same answers again and again
fn fib_slow(n: u64) -> u64 {
    if n < 2 { n } else { fib_slow(n - 1) + fib_slow(n - 2) }
}

// fast: remembers answers it has already worked out
fn fib_memo(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {
    if n < 2 {
        return n;
    }
    if let Some(&v) = memo.get(&n) {
        return v;
    }
    let v = fib_memo(n - 1, memo) + fib_memo(n - 2, memo);
    memo.insert(n, v);
    v
}

fn main() {
    println!("10! = {}", factorial(10));
    println!("fib(30), the slow way: {}", fib_slow(30));
    let mut memo = HashMap::new();
    println!("fib(90), remembering: {}", fib_memo(90, &mut memo));
}
```

`fib_slow(30)` does over a million calls. `fib_memo(90)` does about 180. Remembering answers like this is called **memoisation**.

## How work grows

| Name | Doubling the input... | Example |
|---|---|---|
| O(1) | ...takes the same time | `v[i]`, a `HashMap` lookup |
| O(log n) | ...adds one step | `binary_search` |
| O(n) | ...doubles the time | one loop over the list |
| O(n log n) | ...a bit more than doubles it | `sort` |
| O(n²) | ...four times the time | a loop inside a loop |
| O(2ⁿ) | ...squares the time | `fib_slow` |

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `fib_slow(30)` to `fib_slow(45)`. Notice how long it takes. Stop it with Ctrl+C.
3. `fib_memo(90)` is instant. Try 93. What happens at 94? (Hint: it's too big for a `u64`.)

> [!sith] The dark side
> Very deep recursion, like a function calling itself a million times. Each call uses some stack, and the stack is small. Rust stops the program with "stack overflow" rather than corrupting memory, but it still stops. For deep problems, use a loop.

## Check yourself

> [!question]- What two parts does a recursive function need?
> A base case, small enough to answer directly, and a step that makes the problem smaller and calls the function again.

> [!question]- What is memoisation?
> Remembering answers you've already worked out, so you don't work them out again.

> [!question]- If an algorithm is O(n²), what happens when the input doubles?
> It takes about four times as long.
