# 1.02 Variables and Mutability

> [!abstract] Why this matters
> In Rust, a variable can't change unless you say so. This surprises people coming from C. But it means you can see what changes just by reading the declarations, and the compiler stops changes you didn't mean.

## let and let mut

```rust
fn main() {
    let name = "Rey";            // can't change
    let mut fuel = 40;           // mut: can change
    fuel += 10;
    println!("{name} has {fuel} fuel");

    // shadowing: a new variable with the same name
    let fuel = fuel * 2;
    println!("doubled: {fuel}");

    // a constant: known while compiling, and always written in capitals
    const MAX_CREW: u32 = 6;
    println!("room for {MAX_CREW}");
}
```

- `let` makes a variable you can't change. This is called **immutable**.
- `let mut` makes one you can change. **Mutable** means "can change".
- Writing `let` again with the same name makes a new variable that hides the old one. This is called **shadowing**. It's useful when you change a value's type, or work it out in steps.
- `const` is a value fixed while compiling. It needs a type.

## Why not mutable by default?

Most values never change after you make them. Marking the few that do makes them stand out. Then, when you read code, you know exactly where to look.

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove the `mut` from `let mut fuel`. Build it.
3. Read the error: "cannot assign twice to immutable variable". Rust even suggests adding `mut` back.

> [!sith] The dark side
> Adding `mut` to everything to stop the errors. Only add it where the value really changes. clippy and the compiler warn about a `mut` you never use.

## Check yourself

> [!question]- What does mut do?
> It lets a variable change after it's made. Without it, the variable can't change.

> [!question]- What is shadowing?
> Writing let again with the same name. It makes a new variable that hides the old one, and it can even have a different type.

> [!question]- What's the difference between let and const?
> A const is fixed while compiling, must have a type written out, and is usually in capitals. A let variable is made while the program runs.
