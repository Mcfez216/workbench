# 1.04 Functions and Expressions

> [!abstract] Why this matters
> In Rust, almost everything gives back a value. An `if` gives a value, a block gives a value, and a function gives back its last line. Once you see this, Rust code reads much more simply.

## A function

```rust
fn fuel_needed(parsecs: u32) -> u32 {
    parsecs * 10              // no semicolon: this is the result
}

fn describe(parsecs: u32) -> &'static str {
    if parsecs < 13 { "fast" } else { "normal" }
}

fn main() {
    let trip = 12;
    let fuel = fuel_needed(trip);
    let speed = describe(trip);

    // a block is an expression too: its last line is its value
    let bonus = {
        let base = fuel / 2;
        base + 5
    };
    println!("{trip} parsecs: {fuel} fuel, {speed}, bonus {bonus}");
}
```

- Each input has a type: `parsecs: u32`.
- `-> u32` says what the function gives back.
- The last line, **without** a semicolon, is the value it gives back.
- `return x;` also works, but it's usually only used to leave early.

## Statements and expressions

An **expression** gives a value, like `parsecs * 10`. A **statement** does something but gives no value, like `let x = 5;`.

A semicolon turns an expression into a statement. That's why the last line of a function has no semicolon.

## Try it

1. Click **Try in sandbox**, and run it.
2. Add a semicolon to the end of `parsecs * 10`. Build it.
3. Read the error: "mismatched types, expected u32, found ()". `()` means "nothing". The help line suggests removing the semicolon.

> [!sith] The dark side
> Writing `return` on every last line, out of habit from C. It works, but it hides the expression style the rest of Rust uses. Save `return` for leaving a function early.

## Check yourself

> [!question]- What does a Rust function give back if its last line has no semicolon?
> The value of that last line.

> [!question]- What is () in Rust?
> The "unit" type, which means "no value". A function with no -> gives back ().

> [!question]- Can an if give a value in Rust?
> Yes. let s = if ok { "yes" } else { "no" }; Both branches must give the same type.
