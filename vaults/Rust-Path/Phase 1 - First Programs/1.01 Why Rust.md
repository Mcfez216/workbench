# 1.01 Why Rust

> [!abstract] Why this matters
> Rust is as fast as C and C++, but it stops memory bugs before the program ever runs. Big companies now use it for operating systems, browsers and security tools for exactly this reason. Knowing why it exists makes its rules easier to accept.

## The problem Rust solves

Most serious security bugs in C and C++ programs are memory bugs. For example:

- reading or writing past the end of an array,
- using memory after it's been freed,
- two threads changing the same data at the same time.

In C and C++, the compiler doesn't stop these. The sanitizers catch some of them, but only when the bad path actually runs.

Rust's compiler checks for them while it compiles. If your program might use freed memory, it doesn't compile.

## What it costs

- **Learning time.** Ownership and borrowing take a while to click. Phase 2 goes slowly for this reason.
- **Compile time.** The compiler does more checking, so it's slower than a C compiler.

It doesn't cost speed when the program runs. There's no garbage collector, the background process some languages use to free memory.

## Your first program

```rust
fn main() {
    let ship = "Millennium Falcon";
    let parsecs = 12;
    println!("The {ship} made the Kessel Run in {parsecs} parsecs.");
}
```

- `fn main()` is where every Rust program starts.
- `let` makes a variable.
- `println!` prints a line. The `!` means it's a **macro**, a piece of code that writes code for you.
- `{ship}` inside the text puts the variable's value there.

## Try it

1. Click **Try in sandbox**, then press Ctrl+F9.
2. Change `12` to `"twelve"`, with the quotes. It still works, because `{parsecs}` can print text too.
3. Now add a line `let total = parsecs + 1;`. It doesn't compile any more, because you can't add a number to text.

> [!sith] The dark side
> Thinking Rust is "C++ with extra rules". Its ideas are different, especially about who owns what. Learn them as new ideas, not as C++ with the compiler shouting at you.

## Check yourself

> [!question]- What kind of bug does Rust stop at compile time that C and C++ don't?
> Memory bugs, like using freed memory, reading past the end of an array, and two threads changing the same data at once.

> [!question]- Does Rust's safety make programs slower?
> No. The checks happen while compiling. There's no garbage collector running in the background.

> [!question]- Why does println! have an exclamation mark?
> It's a macro, not a normal function. Macros write code for you while compiling.
