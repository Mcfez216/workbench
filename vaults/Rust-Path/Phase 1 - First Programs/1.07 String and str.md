# 1.07 String and str

> [!abstract] Why this matters
> Rust has two string types, and that confuses everyone at first. `String` owns its text. `&str` only looks at text owned by someone else. Knowing which to use is a small first taste of ownership, the big idea of Phase 2.

## The two types

| Type | What it is | When to use it |
|---|---|---|
| `String` | Owns its text, on the heap. It can grow. | When you build or keep text. |
| `&str` | Borrows some text. It can't grow. | Function inputs that only read text. |

Text in double quotes in your code, like `"Falcon"`, is a `&str`. It's built into the program.

## An example

```rust
fn shout(s: &str) -> String {          // borrows the text, gives back new text
    let mut out = s.to_uppercase();
    out.push('!');
    out
}

fn main() {
    let mut name = String::from("Han");    // a String: owned, can grow
    name.push_str(" Solo");
    let first: &str = &name[..3];          // a &str: a view into name
    println!("{name} ({} letters), first name {first}", name.len());

    println!("{}", shout(&name));          // a String can be borrowed as &str
    println!("{}", shout("help me"));      // so can text in quotes

    for word in "may the force".split(' ') {
        print!("[{word}]");
    }
    println!();
    println!("{}", name.contains("Solo"));
}
```

- `String::from("Han")` makes a `String` from text in quotes.
- `push_str` adds text. `push` adds one character.
- `&name[..3]` borrows the first three bytes of `name` as a `&str`.
- A function that takes `&str` accepts both a `String` (borrowed with `&`) and text in quotes.

## Strings are UTF-8

Rust strings can hold any language and emoji, using UTF-8. Some characters take more than one byte. So `s.len()` counts bytes, not characters. To count characters, use `s.chars().count()`.

## Try it

1. Click **Try in sandbox**, and run it.
2. Change `&name[..3]` to `&name[..2]`. It shows "Ha".
3. Try `let s = String::from("é"); println!("{}", s.len());`. It prints 2, because é takes two bytes.

> [!sith] The dark side
> Writing functions that take `&String` or `String` when they only read the text. Take `&str` instead. It accepts more kinds of input, and it never forces the caller to give up their string.

## Check yourself

> [!question]- What's the difference between String and &str?
> A String owns its text and can grow. A &str only borrows some text that belongs to someone else.

> [!question]- What type should a function take if it only reads some text?
> &str. It works with Strings, with text in quotes, and with parts of strings.

> [!question]- Does s.len() count characters?
> No, it counts bytes. Some characters take several bytes in UTF-8. Use s.chars().count() for characters.
