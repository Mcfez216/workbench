# 1.03 Types

> [!abstract] Why this matters
> Every value in Rust has a type, and Rust never changes one type into another without being asked. That stops a whole family of C bugs, like a negative number quietly becoming a huge one.

## The basic types

| Type | What it holds |
|---|---|
| `i8`, `i16`, `i32`, `i64` | Whole numbers that can be negative. The number is the size in bits. |
| `u8`, `u16`, `u32`, `u64` | Whole numbers from 0 up. The `u` means unsigned. |
| `usize` | Sizes and positions in a list. |
| `f64` | Numbers with decimals. |
| `bool` | `true` or `false`. |
| `char` | One character, like `'a'` or `'🚀'`. |

If you don't say, a whole number is `i32` and a decimal is `f64`.

## An example

```rust
fn main() {
    let crew: u8 = 4;
    let fuel: i64 = -20;
    let speed = 1.5;                     // f64
    let ready = crew > 2;                // bool
    let initial = 'H';                   // char

    // no silent conversions: you say which type you want
    let total = crew as i64 + fuel;
    println!("{crew} {fuel} {speed} {ready} {initial} total={total}");

    // tuples and arrays
    let pilot: (&str, u32) = ("Wedge", 7);
    let scores = [10, 20, 30];
    println!("{} has {} kills; first score {}", pilot.0, pilot.1, scores[0]);

    println!("u8 holds {} to {}", u8::MIN, u8::MAX);
}
```

- `crew as i64` converts on purpose. Without it, adding a `u8` to an `i64` is a compile error.
- A **tuple** like `("Wedge", 7)` holds a few values of different types. You read them with `.0`, `.1`.
- An **array** like `[10, 20, 30]` holds a fixed number of values of the same type.

## Overflow is checked

In a debug build, if a number goes past its biggest value, the program stops with a panic. In C, it would quietly wrap around.

## Try it

1. Click **Try in sandbox**, and run it.
2. Remove `as i64` from the `total` line. Read the error: "mismatched types".
3. Put it back. Add `let big: u8 = 255; let more = big + 1;`. Rust refuses, because it can see the answer doesn't fit.

> [!sith] The dark side
> Using `as` everywhere to make type errors go away. `as` can cut a number down without warning: `300 as u8` is 44. For conversions that can fail, use `try_into()`, which tells you when the value doesn't fit.

## Check yourself

> [!question]- What type is a whole number if you don't say?
> i32.

> [!question]- What happens in a debug build when a u8 goes past 255?
> The program stops with a panic that says "attempt to add with overflow". It doesn't wrap around quietly.

> [!question]- Why is 300 as u8 dangerous?
> as cuts the value to fit, without any warning. 300 becomes 44. try_into() tells you instead when a value doesn't fit.
