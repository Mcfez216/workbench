# 5.05 DHCP Snooping and Dynamic ARP Inspection

> [!abstract] Why this matters
> DHCP and ARP trust anyone who answers. An attacker can run a fake DHCP server, or send fake ARP replies, and make every PC send its traffic through the attacker's laptop. DHCP snooping and Dynamic ARP Inspection stop these attacks on the switch.

## The attacks

- **Rogue DHCP server.** An attacker's laptop answers DHCP Discovers faster than the real server. It hands out its own address as the gateway. Now it sees all the traffic. That's a **man-in-the-middle** attack, also called on-path.
- **DHCP starvation.** An attacker asks for every address in the pool with fake MAC addresses. Real PCs get nothing.
- **ARP poisoning**, or ARP spoofing. An attacker sends ARP replies saying "the gateway's IP address is at my MAC". PCs believe it, and send it their traffic.

## DHCP snooping

The switch sorts its ports into two kinds.

- **Trusted** ports face real DHCP servers, and uplinks to other switches. Server messages are allowed here.
- **Untrusted** ports are every other port, by default. If a DHCP **Offer** or **Acknowledge** arrives on one, it's dropped. Only a server sends those, so it must be a fake server.

The switch also builds a **binding table**: which MAC address got which IP address, on which port and VLAN.

```text
ip dhcp snooping
ip dhcp snooping vlan 10,20
no ip dhcp snooping information option
interface g0/1
 ip dhcp snooping trust
interface range fa0/1 - 24
 ip dhcp snooping limit rate 10
```

- `limit rate 10` allows 10 DHCP messages a second on each user port. Above that, the port goes err-disabled. This stops starvation.
- `no ip dhcp snooping information option` turns off option 82. The switch normally adds it to DHCP requests. Some DHCP servers, including a Cisco router acting as one, drop requests that have it.

```text
show ip dhcp snooping
show ip dhcp snooping binding
```

## Dynamic ARP Inspection

**DAI** checks every ARP message on untrusted ports against the DHCP snooping binding table. If an ARP reply says "IP X is at MAC Y", but the table doesn't agree, it's dropped.

So DAI **needs** DHCP snooping to be on first.

```text
ip arp inspection vlan 10,20
interface g0/1
 ip arp inspection trust
```

Devices with fixed addresses aren't in the binding table. Their ARP messages would be dropped, so you add them with an **ARP ACL**.

```text
show ip arp inspection
```

## Lab

Packet Tracer supports DHCP snooping on the 2960. It may not support every DAI command. If a command is refused, read the idea and carry on.

1. Build a 2960 switch. Connect a router acting as DHCP server on G0/1, with a pool for `192.168.10.0/24`.
2. Add two PCs set to DHCP. Check they get addresses from the router.
3. Add a **Server-PT** on Fa0/24 as a fake DHCP server. Give it a pool in `10.66.66.0/24`, with its own address as the gateway.
4. Release and renew on the PCs: `ipconfig /release` then `ipconfig /renew`. Some PCs may now get a `10.66.66` address. That's the attack working.
5. Type the DHCP snooping commands above. Trust only G0/1.
6. Renew again. Every PC now gets a `192.168.10` address. The fake server's Offers are dropped on Fa0/24.
7. Run `show ip dhcp snooping binding`. Each PC is listed with its MAC, IP, VLAN and port.

> [!sith] The dark side
> Turning on DHCP snooping and forgetting to trust the uplink. Every port is untrusted by default, including the one that leads to the real DHCP server. Now **all** Offers are dropped, and every PC gets a 169.254 address. Trust the ports that lead to the real server.

## Check yourself

> [!question]- What attack does DHCP snooping stop?
> DHCP snooping stops rogue DHCP servers by dropping DHCP server messages, Offer and Acknowledge, that arrive on untrusted ports. With rate limiting, it also stops DHCP starvation.

> [!question]- Which ports should be trusted for DHCP snooping?
> Ports that lead towards the real DHCP server, such as uplinks to other switches or the router. Ports facing users stay untrusted.

> [!question]- What is the DHCP snooping binding table?
> It is a list the switch builds of which MAC address got which IP address, on which port and VLAN.

> [!question]- What does Dynamic ARP Inspection check?
> DAI checks ARP messages on untrusted ports against the DHCP snooping binding table, and drops any that don't match.

> [!question]- Why does DAI need DHCP snooping?
> DAI uses the DHCP snooping binding table to know which IP address really belongs to which MAC address.

> [!question]- What is ARP poisoning?
> ARP poisoning is when an attacker sends fake ARP replies so that other devices link the gateway's IP address to the attacker's MAC address, and send their traffic to the attacker.
