# 5.04 Port Security

> [!abstract] Why this matters
> Anyone can walk up to a network socket and plug in a laptop. Port security limits which devices can use each switch port. It stops strangers, and it stops attacks that flood the switch with fake MAC addresses.

## The idea

Port security counts and remembers the MAC addresses on a port. If a different, or an extra, MAC address appears, the switch takes action.

## The commands

```text
interface fa0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
```

- The port **must** be an access port, set by hand. Port security won't turn on for a port in dynamic mode.
- `maximum 2` allows two MAC addresses. The default is 1. Two is common for a phone with a PC behind it.
- `mac-address sticky` learns the first addresses it sees, and writes them into the running-config. Save the configuration to keep them.
- You can also type an address by hand: `switchport port-security mac-address 0001.4321.ABCD`.

## The violation modes

| Mode | Drops bad frames? | Sends a log message and counts? | Shuts the port? |
|---|---|---|---|
| `protect` | Yes | No | No |
| `restrict` | Yes | Yes | No |
| `shutdown` | Yes | Yes | Yes, err-disabled |

**Shutdown** is the default.

To bring back an err-disabled port, fix the cause, then type `shutdown` and `no shutdown`. Or set it to recover by itself:

```text
errdisable recovery cause psecure-violation
errdisable recovery interval 300
```

## The show commands

```text
show port-security
show port-security interface fa0/1
show port-security address
```

## Lab

1. Build a 2960 switch with PC0 on Fa0/1 and PC1 on Fa0/2, in one network.
2. Turn on port security on Fa0/1 with `maximum 1`, `sticky`, and the default violation mode.
3. Ping PC1 from PC0. Run `show port-security address`. PC0's MAC address is learned.
4. Run `show running-config interface fa0/1`. The sticky address is now in the configuration.
5. Unplug PC0. Plug a new PC, PC2, into Fa0/1. Ping from PC2.
6. The port goes red. Run `show port-security interface fa0/1`. It says **Secure-shutdown**, and the violation count is 1. `show interfaces status` shows the port as **err-disabled**.
7. Put PC0 back. Recover the port with `shutdown` then `no shutdown`.
8. Change the violation mode to `restrict` and repeat step 5. The port stays up, PC2's frames are dropped, and the counter goes up.

> [!sith] The dark side
> Turning on port security on an uplink to another switch. That port sees the MAC addresses of every device behind the other switch, so it breaks the limit straight away and shuts down. Everything behind it is cut off. Use port security only on access ports that face users.

## Check yourself

> [!question]- What does port security do?
> Port security limits which MAC addresses, and how many, can use a switch port, and takes action when another one appears.

> [!question]- What must a port be before port security can be turned on?
> It must be set as an access port by hand, with switchport mode access.

> [!question]- What are the three port security violation modes, and which is the default?
> Protect, restrict and shutdown. Shutdown is the default.

> [!question]- What is the difference between protect and restrict?
> Both drop frames from unknown MAC addresses. Restrict also sends a log message and counts the violation. Protect does neither.

> [!question]- What does sticky do in port security?
> Sticky learns the MAC addresses on the port and adds them to the running configuration, so they are kept if you save it.

> [!question]- How do you recover a port that port security has put in err-disabled?
> Fix the cause, then type shutdown and no shutdown on the port. Or set errdisable recovery so it comes back after a set time.

> [!question]- What is the default maximum number of MAC addresses with port security?
> One.
