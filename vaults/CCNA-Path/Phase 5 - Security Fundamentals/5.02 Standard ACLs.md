# 5.02 Standard ACLs

> [!abstract] Why this matters
> An ACL is a list of rules that allow or block traffic. It's the most basic way to control who can reach what. The exam has many ACL questions: reading them, writing them and placing them.

## An example first

```text
access-list 10 deny 192.168.10.50 0.0.0.0
access-list 10 permit 192.168.10.0 0.0.0.255
interface g0/1
 ip access-group 10 out
```

A packet from `192.168.10.50` leaving G0/1 is **denied**. A packet from `192.168.10.20` is **permitted**. A packet from `172.16.1.1` is **denied** too, because of a rule you can't see. That rule is described next.

ACL means access control list.

## How an ACL is read

1. The router checks the rules **from the top down**.
2. The **first** rule that matches is used. The rest are skipped.
3. If no rule matches, the packet is **denied**. Every ACL ends with an invisible **implicit deny any**.

So every ACL needs at least one `permit`. An ACL with only `deny` lines blocks everything.

## Standard ACLs

A **standard ACL** only checks the **source** IP address.

- Numbered standard ACLs use **1 to 99**, and **1300 to 1999**.
- Place them **close to the destination**. They can't tell destinations apart, so if you put one near the source, it would block that source from everywhere.

## Wildcard masks

A wildcard mask says which bits must match. **0 means must match. 1 means anything.**

| Match | Wildcard | Shortcut |
|---|---|---|
| One host, 10.1.1.5 | 0.0.0.0 | `host 10.1.1.5` |
| A /24 | 0.0.0.255 | |
| A /26 | 0.0.0.63 | |
| Everything | 255.255.255.255 | `any` |

To find the wildcard for a subnet: **255.255.255.255 minus the subnet mask**. For a /26, 255.255.255.255 − 255.255.255.192 = 0.0.0.63.

## Named ACLs

Named ACLs are easier to read, and you can edit single lines.

```text
ip access-list standard BLOCK-GUEST
 10 deny 192.168.50.0 0.0.0.255
 20 permit any
```

Each line has a **sequence number**. To insert a line between 10 and 20, type `15 deny host 192.168.60.5`. To remove a line, type `no 10`.

## Applying an ACL

- `ip access-group 10 in` checks packets as they **arrive** on the interface.
- `ip access-group 10 out` checks packets as they **leave**.
- One ACL per interface, per direction, per protocol. So at most one IPv4 ACL in and one out.

## Protecting the VTY lines

A standard ACL can limit who may SSH to a device:

```text
access-list 5 permit 192.168.99.0 0.0.0.255
line vty 0 4
 access-class 5 in
```

On lines, the command is `access-class`, not `access-group`.

## The show commands

```text
show access-lists
show ip interface g0/1
```

`show access-lists` shows how many packets matched each line. That's the quickest way to see if a rule is working.

## Lab

1. Build R1 with three networks: Sales `192.168.10.0/24` on G0/0, Guest `192.168.50.0/24` on G0/1, and Servers `10.0.0.0/24` on G0/2. Put a PC in each user network and a server in Servers.
2. Check every PC can ping the server.
3. Goal: Guest must not reach Servers. Everyone else can.
4. Write the named ACL `BLOCK-GUEST` above.
5. Where does it go? Close to the destination: G0/2, **out**. Type `ip access-group BLOCK-GUEST out` on G0/2.
6. Ping from the Guest PC to the server. It fails, and the router replies `U`: unreachable. Ping from Sales. It works.
7. Run `show access-lists`. The match counters should go up.
8. Add an access-class so only Sales can SSH to R1. Set up SSH from [[4.04 Remote Access with SSH]] first if needed.

> [!sith] The dark side
> Forgetting the implicit deny. You write `access-list 10 deny 192.168.50.0 0.0.0.255`, apply it, and now nothing at all gets through. The invisible last line denies everything you didn't permit. End with `permit any` when you only mean to block a few.

## Check yourself

> [!question]- What does a standard ACL check?
> A standard ACL only checks the source IP address of a packet.

> [!question]- What number ranges are used for standard ACLs?
> 1 to 99, and 1300 to 1999.

> [!question]- Where should a standard ACL be placed, and why?
> Close to the destination, because it only checks the source address. Near the source it would block that source from reaching everything.

> [!question]- What happens to a packet that matches no line in an ACL?
> It is denied by the implicit deny any at the end of every ACL.

> [!question]- What is the wildcard mask for a /26 network?
> 0.0.0.63, which is 255.255.255.255 minus 255.255.255.192.

> [!question]- In which order does a router check the lines of an ACL?
> From the top down. The first line that matches is used, and the rest are ignored.

> [!question]- Which command applies an ACL to the VTY lines?
> access-class, for example access-class 5 in, typed under line vty 0 4.

> [!question]- How many IPv4 ACLs can you apply to one interface?
> One in each direction: one inbound and one outbound.
