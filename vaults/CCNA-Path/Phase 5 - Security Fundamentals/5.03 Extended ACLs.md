# 5.03 Extended ACLs

> [!abstract] Why this matters
> A standard ACL can only say "block this sender". An extended ACL can say "this sender may reach that server, but only for web pages". That's how real networks are filtered. Writing extended ACLs is one of the most tested skills on the exam.

## An example first

```text
ip access-list extended SALES-IN
 10 permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.100 eq 443
 20 permit udp 192.168.10.0 0.0.0.255 host 10.0.0.53 eq 53
 30 deny ip 192.168.10.0 0.0.0.255 10.0.0.0 0.0.0.255
 40 permit ip any any
interface g0/0
 ip access-group SALES-IN in
```

Sales may reach the web server on HTTPS and the DNS server for lookups. Nothing else from Sales may reach the server network. Everything else is allowed.

## The shape of a line

`permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.100 eq 443`

| Part | Means |
|---|---|
| `permit` or `deny` | What to do |
| `tcp` | The protocol: `ip`, `tcp`, `udp`, `icmp`, `ospf` and more. `ip` means any IP traffic. |
| `192.168.10.0 0.0.0.255` | The source and its wildcard |
| `host 10.0.0.100` | The destination |
| `eq 443` | The destination port. `eq` means equal to. |

Other port words: `gt` greater than, `lt` less than, `neq` not equal, `range 20 21`. You can use names for well-known ports, like `eq www` for 80.

A port placed straight after the **source** matches the source port. A port after the **destination** matches the destination port. Usually you want the destination port.

## Numbers and placement

- Numbered extended ACLs use **100 to 199**, and **2000 to 2699**.
- Place them **close to the source**. They can name the destination exactly, so they can stop unwanted traffic early, before it uses bandwidth.

## Useful lines

```text
permit icmp any any echo-reply
permit tcp any any established
permit ospf any any
deny tcp any host 10.0.0.1 eq 23
```

- `echo-reply` allows ping replies back in.
- `established` matches TCP traffic that's part of a connection already started from inside. It lets replies in, but not new connections.
- If an ACL is on a link that runs OSPF, permit OSPF, or the neighbours will drop.

## Writing one, step by step

1. Write the goal in one sentence: who, to where, for what.
2. List the permits first, from the most specific to the least.
3. Add any denies.
4. End with `permit ip any any` if other traffic should pass.
5. Choose the interface nearest the source, and the direction. Traffic **entering** the router from the source network means `in`.

## Lab

1. Use your lab from [[5.02 Standard ACLs]]. Remove the standard ACL from G0/2 with `no ip access-group BLOCK-GUEST out`.
2. On the server, turn on **HTTP**, **HTTPS** and **FTP** in Services.
3. Goal: Sales may only use HTTP and HTTPS to the server. Guest may only use HTTP. Pings from both are allowed.
4. Write an extended ACL for Sales, and apply it **in** on G0/0. Write one for Guest, and apply it **in** on G0/1.
5. From the Sales PC: open `http://10.0.0.100` and `https://10.0.0.100` in the web browser. Both should work. Try `ftp 10.0.0.100` from the command prompt. It should fail.
6. From the Guest PC: HTTP works, HTTPS fails.
7. Run `show access-lists`. Check the counters on each line match what you tested.
8. Save as `5.03 ACLs.pkt`.

> [!sith] The dark side
> Putting the general line above the specific one. If line 10 is `permit ip any any`, nothing below it ever runs, because everything already matched line 10. Specific lines go first. General lines go last.

## Check yourself

> [!question]- What can an extended ACL check that a standard ACL can't?
> An extended ACL can check the destination address, the protocol, and the source and destination port numbers, as well as the source address.

> [!question]- What number ranges are used for extended ACLs?
> 100 to 199, and 2000 to 2699.

> [!question]- Where should an extended ACL be placed, and why?
> Close to the source, because it can match the destination exactly, so it stops unwanted traffic before it crosses the network.

> [!question]- Write an ACL line that permits HTTPS from 192.168.10.0/24 to the host 10.0.0.100.
> permit tcp 192.168.10.0 0.0.0.255 host 10.0.0.100 eq 443

> [!question]- What does the keyword established do in an extended ACL?
> It matches TCP packets that belong to a connection that was already started, so replies can come in but new connections from outside can't.

> [!question]- What happens if permit ip any any is the first line of an ACL?
> Every packet matches the first line, so all traffic is permitted and none of the later lines are ever used.

> [!question]- Why must an ACL on an OSPF link permit OSPF?
> Otherwise the implicit deny drops the OSPF Hello messages, and the OSPF neighbours go down.
