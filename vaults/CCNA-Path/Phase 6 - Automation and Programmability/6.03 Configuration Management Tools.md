# 6.03 Configuration Management Tools

> [!abstract] Why this matters
> Configuration management tools set up many devices the same way, from files you can check and keep. A change to 200 switches takes minutes, and is the same on every one. The exam asks you to compare Ansible, Terraform, Puppet and Chef.

## The idea

You write down **what the configuration should be**, in files. The tool makes the devices match. The files can be kept in **git**, a version control system. So every change is recorded, can be reviewed, and can be undone. This idea is called **infrastructure as code**.

- **Configuration drift** is when devices slowly stop matching their standard, because of small hand-made changes. These tools find drift and fix it.

## Push and pull

- In a **push** model, a central server connects to the devices and sends the changes.
- In a **pull** model, an **agent** on each device asks the server for its configuration, regularly.
- **Agentless** means nothing extra is installed on the device. The tool uses SSH or an API that's already there.

## The four tools

| | Ansible | Terraform | Puppet | Chef |
|---|---|---|---|---|
| Model | Push | Push | Pull | Pull |
| Agent on device? | No, agentless | No, agentless | Yes, usually | Yes |
| Connects with | SSH, or APIs | Provider APIs | Agent, port 8140 | Agent, port 10002 |
| Files written in | YAML | HCL | Puppet's own language | Ruby |
| Files called | Playbooks | Configurations, .tf | Manifests | Recipes and cookbooks |
| Best known for | Network devices | Cloud resources | Servers | Servers |

**Ansible** is the one most used for network devices, because it's agentless and works over SSH.

## An Ansible playbook

```yaml
---
- name: Set NTP and a banner on every router
  hosts: routers
  gather_facts: no
  tasks:
    - name: NTP server
      cisco.ios.ios_config:
        lines:
          - ntp server 10.0.0.1
    - name: Banner
      cisco.ios.ios_banner:
        banner: motd
        text: Authorised access only
        state: present
```

- The **inventory** file lists the devices. Here they're in a group called `routers`.
- A **playbook** has **plays**. A play has **tasks**. Each task uses a **module** that knows how to do one job.
- YAML uses indentation to show what belongs to what. A `-` starts a list item.

## Lab

Packet Tracer can't run Ansible. Instead:

1. Read the playbook above. Say in your own words what it will do, to which devices.
2. Open any saved lab with several routers. Write down the commands you'd want the same on every router: NTP, a banner, `no ip domain-lookup`, SSH.
3. Write those as an Ansible playbook in a note, using the example as a pattern.
4. Extra, if you have Linux: install Ansible with `pip install ansible`. The free Cisco DevNet sandboxes give you real devices to run your playbook against.

> [!sith] The dark side
> Mixing up which tools use agents. Ansible and Terraform are agentless and push. Puppet and Chef use agents and pull. Exam questions often turn on this one difference.

## Check yourself

> [!question]- What is infrastructure as code?
> Infrastructure as code means writing the configuration of devices in files, kept in version control, and letting a tool make the devices match those files.

> [!question]- What is the difference between the push and pull models?
> In the push model a central server connects to the devices and sends changes. In the pull model an agent on each device regularly asks the server for its configuration.

> [!question]- Which configuration tools are agentless, and which use agents?
> Ansible and Terraform are agentless. Puppet and Chef use agents.

> [!question]- What language are Ansible playbooks written in, and how does Ansible connect to network devices?
> Ansible playbooks are written in YAML, and Ansible connects to network devices over SSH or through their APIs.

> [!question]- What is configuration drift?
> Configuration drift is when devices slowly stop matching their standard configuration, because of small changes made by hand.

> [!question]- What is Terraform mostly used for?
> Terraform is mostly used to create and manage cloud resources, using files written in HCL.
