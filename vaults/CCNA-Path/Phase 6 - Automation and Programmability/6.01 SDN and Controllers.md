# 6.01 SDN and Controllers

> [!abstract] Why this matters
> Setting up hundreds of devices one at a time is slow, and people make mistakes. Controllers let you manage the whole network from one place. The exam asks how this differs from the traditional way, and what the parts are called.

## The three planes

Every network device does three kinds of work. Each is called a **plane**.

| Plane | What it does | Examples |
|---|---|---|
| Data plane | Moves packets and frames through the device | Forwarding, NAT, applying ACLs |
| Control plane | Decides where traffic should go | OSPF, STP, ARP, building the routing table |
| Management plane | Lets people and systems manage the device | SSH, SNMP, syslog |

The data plane is also called the **forwarding plane**.

## SDN

In a traditional network, every device runs its own control plane, and you configure each device by itself.

**SDN**, software-defined networking, moves much of the control plane to a central **controller**. The controller has a view of the whole network, and tells the devices what to do.

### The two kinds of API

An **API**, application programming interface, is a defined way for one program to talk to another.

- The **northbound API** is between the controller and the programs above it: your scripts, apps and dashboards. It's usually a **REST** API. You'll meet REST in [[6.02 REST APIs and JSON]].
- The **southbound API** is between the controller and the network devices below it. Examples: **NETCONF**, **RESTCONF**, **OpenFlow**, and SSH or SNMP.

## Overlay, underlay and fabric

- The **underlay** is the physical network: the cables, switches and routing between them.
- The **overlay** is virtual tunnels built on top of the underlay. They connect devices as if they were next to each other. VXLAN is a common overlay tunnel.
- The **fabric** is the underlay and overlay together.

## Cisco's controllers

- **Catalyst Center**, which used to be called DNA Center, manages campus and branch networks. It's an **intent-based** controller. You say what you want, for example "Guests can only reach the internet", and it works out the configuration.
- **Cisco SD-Access** is Catalyst Center's campus fabric.
- **Cisco SD-WAN** manages links between sites over any mix of internet and private lines.
- **Meraki** is managed from the cloud, through a website.

## Traditional and controller-based, side by side

| | Traditional | Controller-based |
|---|---|---|
| Set up | Device by device, by CLI | Once, centrally |
| Control plane | On every device | Mostly on the controller |
| Consistency | Depends on people typing the same thing | The same template everywhere |
| Changes | Slow, and mistakes are common | Fast, checked and repeatable |
| Troubleshooting | Log in to each device | One view of the whole network, with health scores |

## Lab

Packet Tracer has a **Network Controller**, under Network Devices.

1. Open `3.03 OSPF.pkt`. Add a **Network Controller** and connect it to a switch on R1's LAN. Give it an address, such as `10.1.1.200/24`, with R1 as its gateway.
2. Set up SSH on every router, with the same username, from [[4.04 Remote Access with SSH]].
3. From a PC, open the **Web Browser** and go to the controller's address. Create an admin account.
4. In the controller, add a **credential** with the SSH username and password. Then add each router's address under **Discovery**.
5. Open **Topology**. The controller draws the network from what it found.
6. Look at the **Network Device** list and the health of each device.

> [!sith] The dark side
> Thinking a controller replaces knowing the network. When the controller pushes a bad change, it pushes it to every device at once. You still need to read routing tables and fix problems by hand, and you need to check a change before you send it.

## Check yourself

> [!question]- What do the data, control and management planes do?
> The data plane forwards packets and frames. The control plane decides where traffic should go, with protocols like OSPF and STP. The management plane lets people and systems manage the device, with SSH, SNMP and syslog.

> [!question]- What is SDN?
> SDN, software-defined networking, moves much of the control plane onto a central controller that sees the whole network and tells the devices what to do.

> [!question]- What is the difference between a northbound and a southbound API?
> A northbound API connects the controller to the programs and scripts above it, usually using REST. A southbound API connects the controller to the network devices below it, using protocols like NETCONF, RESTCONF or OpenFlow.

> [!question]- What is the difference between an underlay and an overlay?
> The underlay is the physical network and its routing. The overlay is virtual tunnels built on top of the underlay to connect devices.

> [!question]- What is Cisco Catalyst Center?
> Catalyst Center, previously called DNA Center, is Cisco's intent-based controller for campus and branch networks.

> [!question]- Name two benefits of controller-based networking over traditional networking.
> Changes are made once, centrally, and pushed the same way everywhere, so configuration stays consistent. It is also faster, and gives one view of the whole network for troubleshooting.
