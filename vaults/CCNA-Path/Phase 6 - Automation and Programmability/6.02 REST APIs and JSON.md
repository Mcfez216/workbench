# 6.02 REST APIs and JSON

> [!abstract] Why this matters
> Controllers and modern devices are managed through REST APIs, which send data as JSON. The exam shows you JSON and asks what's in it. It also asks what the HTTP verbs and response codes mean.

## REST

A **REST API** is a way for programs to talk using HTTP, the same protocol as web pages. REST means representational state transfer.

- Each thing you can manage has a **URI**, an address. For example, `https://controller/api/v1/network-device`.
- You send an HTTP **request** with a **verb** that says what to do.
- You get back a **response code** and, usually, data in **JSON**.
- REST is **stateless**. Each request carries everything needed. The server remembers nothing between requests.

### Verbs and CRUD

**CRUD** means create, read, update, delete. Each maps to an HTTP verb.

| CRUD | HTTP verb |
|---|---|
| Create | POST |
| Read | GET |
| Update | PUT, to replace, or PATCH, to change part |
| Delete | DELETE |

### Response codes

| Code | Means |
|---|---|
| 200 OK | It worked |
| 201 Created | A new thing was made |
| 204 No Content | It worked, and there's nothing to send back |
| 400 Bad Request | Your request was wrong |
| 401 Unauthorized | You're not logged in, or your token is wrong |
| 403 Forbidden | You're logged in, but not allowed |
| 404 Not Found | That URI doesn't exist |
| 500 Internal Server Error | The server failed |

2xx means success. 4xx means you made a mistake. 5xx means the server did.

### Authentication

You usually log in first, and get a **token**. A token is a long string that proves who you are. You send it with every request, in a header, like `X-Auth-Token`. Other ways are basic authentication with a username and password, or an API key.

## JSON

JSON means JavaScript Object Notation. It's text that's easy for people to read and programs to process.

```json
{
  "hostname": "R1",
  "managementIp": "10.1.1.1",
  "reachable": true,
  "uptimeDays": 42,
  "interfaces": [
    { "name": "GigabitEthernet0/0", "ip": "10.1.1.1", "up": true },
    { "name": "GigabitEthernet0/1", "ip": "10.0.12.1", "up": true }
  ],
  "location": null
}
```

- `{ }` holds an **object**: a set of **key: value** pairs.
- `[ ]` holds an **array**: a list.
- Keys are always in double quotes.
- Values can be a **string** in double quotes, a **number**, `true` or `false`, `null`, an object, or an array.
- Pairs are separated by commas. There's no comma after the last one.

In this example, `interfaces` is an array of two objects. `interfaces[1].ip` is `10.0.12.1`.

## Other data formats

- **XML** uses tags, like HTML: `<hostname>R1</hostname>`. NETCONF uses XML.
- **YAML** uses indentation, with no brackets. Ansible uses YAML. You'll meet it in [[6.03 Configuration Management Tools]].

> [!sith] The dark side
> A trailing comma or single quotes in JSON. `{'name': 'R1',}` looks fine, but it's not valid JSON. Keys and strings need double quotes, and the last item has no comma after it. On the exam, check every bracket, quote and comma before you decide a JSON example is valid.

## Check yourself

> [!question]- Which HTTP verbs match create, read, update and delete?
> POST creates, GET reads, PUT or PATCH updates, and DELETE deletes.

> [!question]- What do HTTP codes 200, 201, 401, 403 and 404 mean?
> 200 means OK. 201 means something was created. 401 means you are not authenticated. 403 means you are authenticated but not allowed. 404 means the resource was not found.

> [!question]- What does it mean that REST is stateless?
> Each request carries everything the server needs, and the server doesn't remember anything between requests.

> [!question]- In JSON, what is the difference between curly brackets and square brackets?
> Curly brackets hold an object, which is a set of key and value pairs. Square brackets hold an array, which is a list of values.

> [!question]- What kinds of values can JSON hold?
> A string in double quotes, a number, true or false, null, an object, or an array.

> [!question]- What is a token in a REST API?
> A token is a long string the server gives you when you log in. You send it with each request to prove who you are.

> [!question]- Which data formats use tags, and which uses indentation?
> XML uses tags. YAML uses indentation.
