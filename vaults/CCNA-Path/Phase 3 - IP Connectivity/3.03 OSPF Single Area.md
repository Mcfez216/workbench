# 3.03 OSPF Single Area

> [!abstract] Why this matters
> Static routes don't scale. With 20 routers, you'd type hundreds of them, and none would change when a link fails. OSPF lets routers find every network and the best path by themselves. OSPF is the one routing protocol the CCNA tests in depth.

## The idea

OSPF means Open Shortest Path First. It's a **link-state** protocol.

1. Each router finds its neighbours by sending **Hello** messages.
2. Each router tells every other router about its own links, in messages called **LSAs**, link-state advertisements.
3. Every router builds the same map of the whole network. This is the **LSDB**, the link-state database.
4. Each router works out the shortest path to every network on that map, using the **SPF** algorithm, also called Dijkstra's algorithm.

All routers in one **area** share the same map. The CCNA covers **single-area** OSPF, which uses **area 0**, also called the **backbone area**.

## The cost

OSPF's metric is **cost**. Cost = reference bandwidth ÷ interface bandwidth. The default reference bandwidth is 100 Mbps.

| Link | Default cost |
|---|---|
| 10 Mbps | 10 |
| 100 Mbps | 1 |
| 1 Gbps | 1 |
| 10 Gbps | 1 |

Because 100 Mbps and faster all cost 1, change the reference bandwidth on **every** router: `auto-cost reference-bandwidth 10000`. Then 1 Gbps costs 10 and 10 Gbps costs 1.

You can also set the cost of one interface with `ip ospf cost 50`.

## The router ID

Every OSPF router has a 32-bit **router ID**, written like an IPv4 address. It's chosen in this order:

1. The `router-id` command, if you typed one.
2. Otherwise, the highest IP address on a **loopback** interface. A loopback is a virtual interface that never goes down.
3. Otherwise, the highest IP address on any interface that's up.

Changing the router ID only takes effect after `clear ip ospf process`.

## Neighbours

Two routers become neighbours only if these things match:

- The same **area**.
- The same **subnet** and mask on the link.
- The same **hello and dead timers**. The defaults are 10 and 40 seconds on Ethernet.
- The same **authentication**, if any.
- Each router has a **different** router ID.
- Neither interface is **passive**.
- For a full neighbour, the same **MTU**, the largest packet size.

### Neighbour states

**Down → Init → 2-Way → ExStart → Exchange → Loading → Full**

- **2-Way** means each has seen the other's Hello.
- **Full** means their maps are the same. This is the goal.

## DR and BDR

On an Ethernet link with many routers, every router talking to every other would be slow. So they elect a **DR**, designated router, and a **BDR**, backup designated router. Everyone sends updates to the DR, and the DR passes them on.

- The highest **OSPF priority** wins. The default is 1. Priority 0 means "never become DR".
- If priorities tie, the highest router ID wins.
- There's no taking over. A new router with a higher priority waits until the DR fails.
- The other routers are **DROTHERs**. They stay at 2-Way with each other, which is normal.
- On a **point-to-point** link, with only two routers, there's no DR. Use `ip ospf network point-to-point` on router-to-router Ethernet links to skip the election.

OSPF sends to the multicast address **224.0.0.5** for all OSPF routers, and **224.0.0.6** for the DR and BDR.

## The commands

```text
router ospf 1
 router-id 1.1.1.1
 network 10.1.1.0 0.0.0.255 area 0
 network 10.0.12.0 0.0.0.3 area 0
 passive-interface g0/0
 auto-cost reference-bandwidth 10000
 default-information originate
```

- `1` is the **process ID**. It only matters inside this router. Neighbours don't need the same one.
- `network 10.1.1.0 0.0.0.255 area 0` turns OSPF on for every interface whose address matches. `0.0.0.255` is a **wildcard mask**: 0 bits must match, 1 bits can be anything. A wildcard mask is the opposite of a subnet mask.
- `passive-interface g0/0` still advertises the network, but sends no Hellos out of that port. Use it on ports to PCs.
- `default-information originate` shares this router's default route with every other OSPF router.

You can also turn OSPF on inside the interface:

```text
interface g0/1
 ip ospf 1 area 0
```

## The show commands

```text
show ip ospf neighbor
show ip ospf interface brief

```

## Lab: three routers

```text
        PC1                       PC3
         |                         |
       G0/0                       G0/0
        [R1] G0/1 ------- G0/1 [R3]
       G0/2                       G0/2
          \                       /
           G0/1               G0/2
              \     [R2]     /
                    G0/0
                     |
                    PC2
```

1. Build three 2911 routers in a triangle, with a PC on each router's G0/0.
2. Address plan: R1 LAN `10.1.1.0/24`, R2 LAN `10.2.2.0/24`, R3 LAN `10.3.3.0/24`. Router links: R1–R3 `10.0.13.0/30`, R1–R2 `10.0.12.0/30`, R2–R3 `10.0.23.0/30`. The lower router number gets `.1`.
3. On each router, set the router ID to `1.1.1.1`, `2.2.2.2` and `3.3.3.3`.
4. Add a `network` command for every connected network, in area 0. Make G0/0 passive.
5. Run `show ip ospf neighbor` on each router. Each should have two neighbours in the **FULL** state.
6. Run `show ip route ospf` on R1. You should see R2's and R3's LANs, and the R2–R3 link.
7. Ping from PC1 to PC2 and PC3.
8. Shut down R1's G0/2. Within 40 seconds, R1 finds a new path to R2 through R3. Check `show ip route` again.
9. Break a neighbour on purpose: on R3's G0/1, type `ip ospf hello-interval 5`. Watch the neighbour go down. Fix it with `no ip ospf hello-interval 5`.
10. Add a default route on R1 to a fourth router acting as the internet, and use `default-information originate`. Check R2 and R3 now have an `O*E2` default route.
11. Save as `3.03 OSPF.pkt`. You'll break it on purpose in [[3.05 Troubleshooting Method]].

> [!sith] The dark side
> Writing the wildcard mask as a subnet mask. `network 10.1.1.0 255.255.255.0 area 0` is accepted, but it means "the first octet can be anything", which is wrong. OSPF then runs on interfaces you didn't mean. A /24 needs the wildcard `0.0.0.255`. A /30 needs `0.0.0.3`.

## Check yourself

> [!question]- What kind of routing protocol is OSPF?
> OSPF is a link-state routing protocol. Each router builds the same map of the network and works out the shortest path itself.

> [!question]- How is the OSPF cost of an interface worked out?
> The cost is the reference bandwidth divided by the interface bandwidth. The default reference bandwidth is 100 Mbps.

> [!question]- How is the OSPF router ID chosen?
> First from the router-id command. If there is none, the highest loopback IP address. If there is no loopback, the highest IP address on an active interface.

> [!question]- What must match for two routers to become OSPF neighbours?
> The area, the subnet and mask, the hello and dead timers, and the authentication must match. The router IDs must be different, and neither interface can be passive. The MTU must match for the neighbours to reach full.

> [!question]- What are the OSPF neighbour states, in order?
> Down, Init, 2-Way, ExStart, Exchange, Loading, Full.

> [!question]- How is the OSPF DR elected?
> The router with the highest OSPF priority becomes the DR. If priorities are equal, the highest router ID wins. A priority of 0 means the router can never become DR.

> [!question]- What are the default OSPF hello and dead timers on Ethernet?
> The hello timer is 10 seconds and the dead timer is 40 seconds.

> [!question]- What does passive-interface do in OSPF?
> It stops OSPF sending Hellos out of that interface, so no neighbours form there, but the interface's network is still advertised.

> [!question]- What wildcard mask matches a /30 network?
> 0.0.0.3.

> [!question]- What does default-information originate do?
> It makes an OSPF router share its own default route with all the other OSPF routers.

> [!question]- Which multicast addresses does OSPF use?
> 224.0.0.5 reaches all OSPF routers, and 224.0.0.6 reaches the DR and BDR.

> [!question]- Do two OSPF neighbours need the same process ID?
> No. The process ID only matters inside one router.
