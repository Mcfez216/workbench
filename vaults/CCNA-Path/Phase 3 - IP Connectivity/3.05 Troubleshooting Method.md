# 3.05 Troubleshooting Method

> [!abstract] Why this matters
> Building a network is half the job. Fixing one is the other half. A clear order of checks stops you guessing. The exam's labs often hand you a broken network and ask you to fix it.

## Start at the bottom

Work up the OSI layers. Each check depends on the one before it.

### Layer 1: is it plugged in?

- Are the lights green?
- `show ip interface brief`. Look at **Status** and **Protocol**.

| Status | Protocol | Means |
|---|---|---|
| up | up | Working |
| administratively down | down | Someone typed `shutdown`. Type `no shutdown`. |
| down | down | No cable, a bad cable, or the other end is off |
| up | down | A Layer 2 problem, like a mismatch at each end |

On a switch, **err-disabled** means the port was shut down by a feature like port security or BPDU Guard. Fix the cause, then `shutdown` and `no shutdown`.

### Layer 2: is the switching right?

- `show vlan brief`. Is the port in the right VLAN?
- `show interfaces trunk`. Is the trunk up? Is the VLAN allowed? Do the native VLANs match?
- `show mac address-table`. Has the switch learned the device?
- `show spanning-tree`. Is the port blocked?

### Layer 3: are the addresses and routes right?

- On the PC, `ipconfig`. Check the address, mask and gateway.
- Ping the gateway first. Then ping across the router. Then ping the far device.
- `show ip route`. Is there a route there? And a route back?
- `show ip ospf neighbor`. Are the neighbours FULL?

### Layer 4 and up: is something filtering?

- `show access-lists`. Are the hit counters going up on a deny line?
- `show ip nat translations`.
- Can you ping the server, but not open the web page? Then the problem is above Layer 3. Check the service and any ACLs.

## The tools

- **ping** tests whether a device answers. `!` is a reply. `.` is a timeout. `U` means unreachable: a router said it has no route.
- **traceroute**, or `tracert` on a PC, lists every router on the path. Where it stops is where to look.
- **show ip interface brief** is the most useful command of all. Run it first.
- **show running-config** shows what was actually typed.
- **debug** shows events as they happen, like `debug ip ospf adj`. Turn it off with `undebug all`. On a busy real router, debug can overload the CPU.

## Common faults, and what they look like

| What you see | Look for |
|---|---|
| PC can't ping its gateway | The PC's address or mask is wrong, the port is in the wrong VLAN, or the router port is shut down. |
| PC can ping the gateway, not beyond | The PC has the wrong gateway, a route is missing, or there's no route back. |
| Only one VLAN can't cross the trunk | That VLAN is missing from the allowed list, or doesn't exist on one switch. |
| OSPF neighbour stuck or missing | Area, subnet, timers or passive-interface. Two routers with the same router ID. |
| Pings work, web page doesn't | An ACL blocks port 80, or the web service is off. |
| Some PCs get 169.254 addresses | DHCP is broken, or there's no `ip helper-address` on the gateway. |

## Lab: break and fix

Ask a study partner to break one of your saved labs, or break it yourself and wait a day so you forget.

1. Open `3.03 OSPF.pkt` and save a copy as `3.05 Broken.pkt`.
2. Make three faults: a wrong mask on one PC, a passive interface on a router link, and a shut-down interface.
3. Close it. The next day, open it and fix it using only the order above.
4. For each fault, write down the command that showed it. Use [[Templates/Lab Template]].

> [!sith] The dark side
> Changing many things at once. If you change five settings and the network works, you don't know which one fixed it, and you may have broken something else. Change one thing, test, then decide.

## Check yourself

> [!question]- What does administratively down mean in show ip interface brief?
> It means someone shut the interface down with the shutdown command. Typing no shutdown turns it back on.

> [!question]- What does a status of up and a protocol of down usually mean?
> It means the physical link is working but there is a Layer 2 problem, such as a mismatch in settings at the two ends.

> [!question]- In a ping, what do !, . and U mean?
> An exclamation mark is a reply, a full stop is a timeout, and U means a router reported the destination as unreachable.

> [!question]- A PC can ping its gateway but not a server on another network. What should you check?
> Check the PC's default gateway setting, check there is a route to the server's network, and check there is a route back.

> [!question]- What does err-disabled mean on a switch port, and how do you recover it?
> Err-disabled means a feature like port security or BPDU Guard shut the port down. Fix the cause, then type shutdown and no shutdown on the port.

> [!question]- Why should you work up from Layer 1 when troubleshooting?
> Each layer depends on the one below it, so a fault low down causes problems at every layer above. Checking from the bottom finds the real cause first.
