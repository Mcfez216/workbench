# 1.06 TCP and UDP

> [!abstract] Why this matters
> TCP and UDP are the two Layer 4 protocols. Every application uses one of them. ACLs, firewalls and NAT all filter by their port numbers, so you need to know which application uses which port.

## Port numbers

A **port number** says which program on a device the data is for. An IP address gets the data to the right device. The port gets it to the right program.

- Ports 0 to 1023 are **well-known ports**, used by servers. For example, a web server listens on port 80.
- The client picks a random high port for its side, called an **ephemeral port**.

## TCP

TCP means Transmission Control Protocol. It's **connection-oriented**. That means it sets up a connection before sending data.

- It starts with a **three-way handshake**: SYN, then SYN-ACK, then ACK.
- It numbers every segment, so the other end can put them back in order.
- It resends anything that was lost.
- It uses **windowing** to control how much data is sent before an acknowledgement. This is called flow control.
- It ends a connection with FIN messages.

## UDP

UDP means User Datagram Protocol. It's **connectionless**.

- No handshake, no numbering, no resending.
- It's faster and has a smaller header.
- It's used where speed matters more than every piece arriving: voice, video, DNS lookups and DHCP.

## Side by side

| | TCP | UDP |
|---|---|---|
| Connection | Set up with a handshake | None |
| Reliable | Yes. Lost data is resent. | No |
| Order | Put back in order | Not guaranteed |
| Header size | 20 bytes or more | 8 bytes |
| Used for | Web, email, file transfer, SSH | Voice, video, DNS, DHCP, TFTP, SNMP |

## The ports to learn

| Port | Protocol | TCP or UDP |
|---|---|---|
| 20, 21 | FTP | TCP |
| 22 | SSH | TCP |
| 23 | Telnet | TCP |

| 53 | DNS | UDP, and TCP for big replies |

## Lab: watch a handshake

1. Build a PC and a **Server-PT** on one switch. Give the PC `10.0.0.10/24` and the server `10.0.0.100/24`.
2. On the server, open **Services → HTTP**. Check it's turned on.
3. Switch to **Simulation**. Click **Edit Filters**, and show only **TCP** and **HTTP**.
4. On the PC, open **Desktop → Web Browser**, type `http://10.0.0.100`, and press Go.
5. Step through the events. You should see three TCP envelopes before the first HTTP one. That's the handshake. Click each envelope and find the SYN and ACK flags in the TCP header.
6. Look at the source and destination port in the TCP header. One is 80. What is the other one?

> [!sith] The dark side
> Saying "DNS uses TCP" or "DNS uses UDP" as if it's only one. DNS normally uses UDP port 53. It uses TCP port 53 for large replies and for copying zones between DNS servers. On the exam, read the question carefully.

## Check yourself

> [!question]- What are the three steps of the TCP three-way handshake?
> The client sends SYN, the server replies with SYN-ACK, and the client answers with ACK.

> [!question]- Why does voice traffic use UDP instead of TCP?
> Voice needs to arrive quickly. Resending a lost piece of speech is useless because it would arrive too late, so the speed of UDP is better than the reliability of TCP.

> [!question]- What does TCP windowing do?
> Windowing controls how much data the sender may send before it must wait for an acknowledgement. This is called flow control.

> [!question]- Which port numbers do SSH, Telnet, HTTP and HTTPS use?
> SSH uses TCP 22, Telnet uses TCP 23, HTTP uses TCP 80, and HTTPS uses TCP 443.

> [!question]- Which ports does DHCP use, and is it TCP or UDP?
> DHCP uses UDP. The server listens on port 67 and the client uses port 68.

> [!question]- What is the job of a port number?
> A port number tells the receiving device which program the data is for, such as a web server on port 80.
