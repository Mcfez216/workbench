# 1.07 How Switches Learn - MAC Addresses and ARP

> [!abstract] Why this matters
> Switches learn where every device is by watching traffic. ARP finds the MAC address that goes with an IP address. Together they explain how a frame really gets from one PC to another. The exam often asks you to follow a frame step by step.

## The MAC address

A MAC address is 48 bits, written in hex. For example, `0001.42A3.1B2C`. The first half names the company that made the card. It's called the **OUI**, or organizationally unique identifier. The second half is unique to the card.

The broadcast MAC address is `FFFF.FFFF.FFFF`.

## How a switch learns

A switch keeps a **MAC address table**. It lists which MAC address is on which port.

1. A frame arrives. The switch reads the **source** MAC address. It writes that address and the port into its table. This is **learning**.
2. The switch reads the **destination** MAC address and looks it up.
3. If it's in the table, the switch sends the frame out of that one port. This is **forwarding**.
4. If it isn't in the table, the switch sends it out of every port except the one it came in on. This is **flooding**. A frame to an unknown address is called an **unknown unicast**.
5. Broadcast frames are always flooded.
6. Entries are removed after 5 minutes with no traffic. This is called **aging**.

A **broadcast domain** is all the devices that get each other's broadcasts. All the ports of a switch are one broadcast domain. A router stops broadcasts, so each router interface is its own broadcast domain.

## How ARP works

ARP means Address Resolution Protocol. A PC knows the IP address it wants. It needs the MAC address to build the frame.

1. PC A wants to send to `10.0.0.11` on its own network.
2. It checks its **ARP cache**, which is a list of IP and MAC pairs it already knows.
3. If the address isn't there, it sends an **ARP request** as a broadcast: "Who has 10.0.0.11?"
4. Every device receives it. Only `10.0.0.11` answers, with an **ARP reply** sent unicast: "I do, and my MAC is ..."
5. PC A saves the answer and sends the frame.

If the address is on **another** network, the PC asks ARP for the MAC address of its **default gateway**, not of the far device. The frame goes to the router. The router builds a new frame for the next link.

So as a packet crosses routers, the **IP addresses stay the same** and the **MAC addresses change** at every hop.

## The commands

```text
show mac address-table
show mac address-table dynamic
clear mac address-table dynamic
show ip arp
```

On a PC: `arp -a` shows the ARP cache.

## Lab

1. Build a 2960 switch with three PCs: `10.0.0.10`, `.11` and `.12`, all /24.
2. On the switch, type `show mac address-table`. It's empty, or nearly.
3. In **Simulation** mode, edit the filters to show only **ARP** and **ICMP**. ICMP is the protocol ping uses.
4. Ping from PC0 to PC1. Watch the ARP request go to **every** PC. Watch the reply come back to PC0 only.
5. Back in Realtime, run `show mac address-table` again. PC0's and PC1's MAC addresses are now in it. PC2's isn't, because it hasn't sent anything.
6. On PC0, type `arp -a`. You should see PC1's IP address and MAC address.
7. Add a router as the gateway, with a second network behind it. Ping a PC on the far network. Look at the MAC addresses in the frame on each side of the router.

> [!sith] The dark side
> Thinking a switch learns from the destination address. It only learns from the **source** address. That's why a device that never sends anything is never in the table, and frames to it are flooded.

## Check yourself

> [!question]- Which MAC address does a switch learn from: the source or the destination?
> A switch learns from the source MAC address of each frame that arrives, and writes it into the MAC address table with the port it came in on.

> [!question]- What does a switch do with a frame for a MAC address that isn't in its table?
> It floods the frame out of every port except the one it arrived on. This is called an unknown unicast flood.

> [!question]- What does ARP do?
> ARP finds the MAC address that belongs to a known IP address on the local network, by broadcasting a request and getting a unicast reply.

> [!question]- When a PC sends to a device on another network, whose MAC address does it look up with ARP?
> It looks up the MAC address of its default gateway, because the frame must go to the router first.

> [!question]- What changes and what stays the same as a packet crosses a router?
> The source and destination IP addresses stay the same. The source and destination MAC addresses change at every hop.

> [!question]- What is a broadcast domain?
> A broadcast domain is the group of devices that all receive each other's broadcasts. Switches pass broadcasts on, and routers stop them.
