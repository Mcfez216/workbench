# 1.08 Virtualisation and Cloud

> [!abstract] Why this matters
> Many servers today are not separate machines. They are virtual machines or containers on shared hardware, often in the cloud. The exam asks you to explain these ideas. There's no Packet Tracer lab for most of them, so this note is short.

## Virtual machines

A **virtual machine**, or VM, is a computer made in software. One physical server can run many VMs at once.

- The **hypervisor** is the software that runs the VMs and shares out the hardware.
- A **Type 1** hypervisor runs straight on the hardware. VMware ESXi is an example. It's used in data centres.
- A **Type 2** hypervisor runs as a program on a normal operating system. VirtualBox is an example.
- VMs connect to the network through a **virtual switch** inside the hypervisor.

## Containers

A **container** packages one program and everything it needs. Containers share the host's operating system, so they're smaller and start faster than VMs. Docker is the best-known example.

## VRFs

A **VRF**, or virtual routing and forwarding, splits one router into several separate routers. Each VRF has its own routing table. Two customers can even use the same IP addresses on one router without mixing.

## Cloud services

| Service | What you rent | Example |
|---|---|---|
| IaaS, infrastructure as a service | Virtual servers, storage and networks. You manage the operating system. | A VM in AWS or Azure |
| PaaS, platform as a service | A ready platform. You only bring your code. | A managed database |
| SaaS, software as a service | A finished program, used in a browser | Email, Microsoft 365 |

Ways to deploy a cloud:

- **Public cloud** is shared by many customers, run by a provider.
- **Private cloud** is used by one organisation only.
- **Hybrid cloud** joins a private and a public cloud.

You can reach a cloud over the normal internet, over a VPN, or over a private line straight to the provider.

> [!sith] The dark side
> Mixing up IaaS and PaaS. Ask who manages the operating system. In IaaS you do. In PaaS the provider does, and you only manage your program and its data.

## Check yourself

> [!question]- What is the difference between a Type 1 and a Type 2 hypervisor?
> A Type 1 hypervisor runs straight on the hardware, as in data centres. A Type 2 hypervisor runs as a program on top of a normal operating system.

> [!question]- How is a container different from a virtual machine?
> A container shares the host's operating system and only packages one program and what it needs, so it is smaller and starts faster. A virtual machine has its own complete operating system.

> [!question]- What is a VRF?
> A VRF, or virtual routing and forwarding instance, splits one router into several separate routing tables, so different networks can share one router without mixing.

> [!question]- What is the difference between IaaS, PaaS and SaaS?
> In IaaS you rent virtual servers and manage the operating system yourself. In PaaS you rent a ready platform and only bring your code. In SaaS you use a finished program, usually in a browser.
