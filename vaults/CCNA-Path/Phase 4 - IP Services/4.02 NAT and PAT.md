# 4.02 NAT and PAT

> [!abstract] Why this matters
> Private addresses can't be used on the internet. NAT changes them to a public address on the way out. Almost every home and office network uses it. The exam asks you to set it up, and to name the four kinds of address it uses.

## An example first

A PC at `192.168.1.10` opens a web page. The router's internet port is `203.0.113.5`.

1. The packet leaves the PC with source `192.168.1.10`.
2. The router changes the source to `203.0.113.5`, and writes the change in its **NAT table**.
3. The web server replies to `203.0.113.5`.
4. The router looks in its NAT table, and changes the destination back to `192.168.1.10`.

NAT means Network Address Translation.

## The four address names

| Name | Means | In the example |
|---|---|---|
| Inside local | The inside device's real address | 192.168.1.10 |
| Inside global | What the inside device looks like from outside | 203.0.113.5 |
| Outside global | The outside device's real address | The web server's address |
| Outside local | What the outside device looks like from inside | Usually the same as outside global |

**Inside** or **outside** says which side the device is on. **Local** or **global** says which side you're looking from.

## The three kinds of NAT

- **Static NAT** maps one inside address to one public address, permanently. Use it for a server that must be reachable from the internet.
- **Dynamic NAT** takes a public address from a **pool** for each inside device, one at a time. If the pool runs out, the next device can't get out.
- **PAT**, port address translation, also called **NAT overload**, lets many inside devices share **one** public address. It tells them apart by their **port numbers**. This is what homes and offices use.

## The commands

First, mark the sides. This step is the same for every kind of NAT.

```text
interface g0/0
 ip nat inside
interface g0/1
 ip nat outside
```

### Static NAT

```text
ip nat inside source static 192.168.1.100 203.0.113.10
```

### Dynamic NAT

```text
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat pool PUBLIC 203.0.113.20 203.0.113.30 netmask 255.255.255.0
ip nat inside source list 1 pool PUBLIC
```

### PAT using the outside interface's address

```text
access-list 1 permit 192.168.1.0 0.0.0.255
ip nat inside source list 1 interface g0/1 overload
```

The ACL picks which inside addresses are allowed to be translated.

### Checking

```text
show ip nat translations
show ip nat statistics
clear ip nat translation *
```

## Lab

1. Build an inside network: a 2911 router, R1, with a switch and two PCs on G0/0, `192.168.1.0/24`. Add a server at `192.168.1.100`.
2. Build the "internet": a second router, ISP, connected to R1's G0/1 with the network `203.0.113.0/24`. R1 is `.5`, ISP is `.1`. Put a web server on ISP's G0/0 at `198.51.100.10/24`.
3. On R1, add a default route to `203.0.113.1`. **Don't** give ISP any route to `192.168.1.0`. The internet doesn't know private addresses.
4. Ping the web server from a PC. It fails. The reply has nowhere to go.
5. Set up PAT on R1 with the commands above.
6. Ping again from both PCs. It works. Run `show ip nat translations`. You'll see both PCs sharing `203.0.113.5`, with different port numbers. For ping, the "port" is the ICMP ID.
7. Add static NAT for the inside server to `203.0.113.10`. From the web server, browse to `http://203.0.113.10`. It reaches your inside server.
8. Save as `4.02 NAT.pkt`.

> [!sith] The dark side
> Putting `ip nat inside` and `ip nat outside` on the wrong interfaces, or forgetting one. Nothing is translated, and the only clue is an empty `show ip nat translations`. Inside faces your private network. Outside faces the internet. Check both.

## Check yourself

> [!question]- What does NAT do?
> NAT changes IP addresses as packets pass through a router. Usually it changes private inside addresses into a public address, so devices can use the internet.

> [!question]- What is an inside local address and an inside global address?
> The inside local address is the real private address of a device on the inside. The inside global address is the public address it appears as on the outside.

> [!question]- What is the difference between static NAT, dynamic NAT and PAT?
> Static NAT maps one inside address to one public address permanently. Dynamic NAT gives inside devices public addresses from a pool, one each. PAT lets many inside devices share one public address by using different port numbers.

> [!question]- Write the command for PAT that uses ACL 1 and the address of interface g0/1.
> ip nat inside source list 1 interface g0/1 overload

> [!question]- Which command shows the current NAT translations?
> show ip nat translations.

> [!question]- When should you use static NAT?
> Use static NAT for an inside server that must always be reachable from the internet at the same public address.

> [!question]- What happens with dynamic NAT when the pool of public addresses runs out?
> The next inside device can't be translated, so it can't reach the outside until an address is free.
