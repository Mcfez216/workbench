# 4.04 Remote Access with SSH

> [!abstract] Why this matters
> You can't walk to every router with a console cable. SSH lets you log in over the network, safely. Telnet does the same thing but sends your password in plain text. The exam expects you to set SSH up from memory.

## Telnet and SSH

| | Telnet | SSH |
|---|---|---|
| Port | TCP 23 | TCP 22 |
| Encrypted? | No. Passwords can be read by anyone. | Yes |
| Use it? | No | Yes, always |

SSH means Secure Shell.

## The steps

SSH needs four things: a hostname, a domain name, RSA keys and a user account.

```text
hostname R1
ip domain-name lab.local
crypto key generate rsa
 ! answer 2048 when it asks for the size
ip ssh version 2
username admin secret Cisco-Lab-1
line vty 0 4
 login local
 transport input ssh
 exec-timeout 10 0
```

1. `hostname` and `ip domain-name` together name the keys. The router won't make keys while its name is still "Router".
2. `crypto key generate rsa` makes the encryption keys. SSH version 2 needs at least **768** bits. Use **2048**.
3. `username ... secret` makes a local account. `secret` stores the password as a hash. A hash is a scrambled form that can't be turned back into the password.
4. `line vty 0 4` sets up the 5 virtual lines used for remote logins. VTY means virtual terminal.
5. `login local` checks logins against the local accounts.
6. `transport input ssh` allows SSH only, and blocks Telnet.
7. `exec-timeout 10 0` logs out an idle session after 10 minutes.

A switch needs the same steps, plus a management SVI and `ip default-gateway`, from [[2.01 VLANs]].

## Checking

```text
show ip ssh
show ssh
```

From a PC or another router: `ssh -l admin 10.0.0.1`

## Lab

1. Build a 2911 router, a 2960 switch and a PC. Give the router `192.168.1.1/24` on G0/0.
2. On the router, type the commands above.
3. On the PC, open **Desktop → Command Prompt** and type `ssh -l admin 192.168.1.1`. Type the password. You should see the `R1>` prompt.
4. Try `telnet 192.168.1.1` from the PC. It's refused, because only SSH is allowed.
5. Now set up SSH on the switch: VLAN 1 SVI at `192.168.1.2`, `ip default-gateway 192.168.1.1`, and the same SSH steps. SSH to the switch from the PC.
6. In **Simulation** mode, compare a Telnet session with an SSH one. Change `transport input ssh` to `transport input telnet ssh` for this test. Click a Telnet packet: you can read the password. Click an SSH packet: you can't.

> [!sith] The dark side
> Using `login` instead of `login local` on the VTY lines. `login` uses a line password, typed with `password`. If no line password is set, nobody can log in at all. You'll see "Password required, but none set". Use `login local` with a username, or set a line password.

## Check yourself

> [!question]- Why should you use SSH instead of Telnet?
> Telnet sends everything, including passwords, as plain text that anyone on the network can read. SSH encrypts the whole session.

> [!question]- Which ports do SSH and Telnet use?
> SSH uses TCP port 22 and Telnet uses TCP port 23.

> [!question]- What must you set before crypto key generate rsa will work?
> A hostname other than the default, and a domain name with ip domain-name.

> [!question]- What does transport input ssh do on the VTY lines?
> It only allows SSH logins on those lines, and blocks Telnet.

> [!question]- What does login local do?
> It makes the line check logins against the usernames and passwords stored on the device itself.

> [!question]- What is the smallest RSA key size for SSH version 2?
> 768 bits, but 2048 bits is the size you should use.
