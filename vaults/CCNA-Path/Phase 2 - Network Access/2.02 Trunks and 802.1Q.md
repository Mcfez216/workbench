# 2.02 Trunks and 802.1Q

> [!abstract] Why this matters
> When VLANs stretch over two switches, the link between them must carry every VLAN. That link is a trunk. Trunk mistakes are one of the most common reasons a lab doesn't work.

## The idea

A **trunk** is a link that carries many VLANs. Each frame gets a small **tag** that says which VLAN it belongs to. The receiving switch reads the tag and puts the frame back in the right VLAN.

The tagging standard is **IEEE 802.1Q**, usually called "dot1q". It adds a 4-byte tag inside the Ethernet frame. The tag has a 12-bit VLAN ID, which is why VLANs only go up to 4094.

## The native VLAN

Frames in the **native VLAN** cross the trunk with **no tag**. The default native VLAN is VLAN 1.

- Both ends must have the same native VLAN. If they don't, traffic leaks from one VLAN into another, and CDP shows a "native VLAN mismatch" message.
- For security, set the native VLAN to an unused VLAN, like 999.

## DTP

DTP, the Dynamic Trunking Protocol, lets two Cisco switches agree to make a trunk by themselves.

| Mode | What it does |
|---|---|
| `switchport mode trunk` | Always a trunk |
| `switchport mode access` | Never a trunk |
| `switchport mode dynamic desirable` | Asks the other end to trunk |
| `switchport mode dynamic auto` | Trunks only if the other end asks |

Two ports on **auto** both wait for the other, so they never make a trunk. For security, set trunks by hand and turn DTP off with `switchport nonegotiate`.

## The commands

```text
interface g0/1
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,99
 switchport nonegotiate
 end
show interfaces trunk
```

On a **3560** multilayer switch, you must choose the tagging type first, with `switchport trunk encapsulation dot1q`. A 2960 only supports dot1q, so it doesn't have this command.

To add a VLAN to the allowed list later, use `switchport trunk allowed vlan add 30`. Without the word `add`, the new list **replaces** the old one.

## VTP

VTP, the VLAN Trunking Protocol, copies the VLAN list from one switch to others. One wrong switch can delete VLANs everywhere, so many networks use **transparent** mode, which means "don't take part". The exam only asks you to know what it is.

## Lab

1. Build two 2960 switches, SW1 and SW2. Connect their G0/1 ports with a **Copper Cross-Over** cable.
2. On each switch, create VLAN 10 named SALES, VLAN 20 named IT, VLAN 99 named MANAGEMENT and VLAN 999 named NATIVE.
3. Put two PCs on each switch: one in VLAN 10, one in VLAN 20. Sales PCs get `192.168.10.x/24`. IT PCs get `192.168.20.x/24`.
4. Ping from the Sales PC on SW1 to the Sales PC on SW2. It fails. The link is an access port in VLAN 1.
5. Type the trunk commands above on G0/1 of both switches.
6. Run `show interfaces trunk`. You should see G0/1, mode "on", native VLAN 999, and VLANs 10, 20 and 99 allowed.
7. Ping again. Sales can reach Sales, and IT can reach IT. Sales still can't reach IT.
8. Break it on purpose. On SW2 only, change the native VLAN to 1. Wait a minute and look for the CDP message on the console. Then fix it.

> [!sith] The dark side
> `switchport trunk allowed vlan 30` on a trunk that carried 10 and 20. Now it only carries 30, and VLANs 10 and 20 stop working everywhere past this link. Use `switchport trunk allowed vlan add 30`.

## Check yourself

> [!question]- What is a trunk?
> A trunk is a link between switches that carries many VLANs, by adding a tag to each frame that says which VLAN it belongs to.

> [!question]- What is the name of the trunking standard, and how big is its tag?
> The standard is IEEE 802.1Q. It adds a 4-byte tag to each frame, with a 12-bit VLAN ID.

> [!question]- What is special about the native VLAN on a trunk?
> Frames in the native VLAN cross the trunk without a tag. Both ends must use the same native VLAN.

> [!question]- Will two switch ports both set to dynamic auto form a trunk?
> No. Both ports wait for the other to ask, so they stay access ports.

> [!question]- What does switchport trunk allowed vlan add 30 do, and why is the word add important?
> It adds VLAN 30 to the list of VLANs allowed on the trunk. Without add, the command replaces the whole list with only VLAN 30.

> [!question]- Which command shows the trunks on a switch, their native VLAN and their allowed VLANs?
> show interfaces trunk.

> [!question]- Which extra command does a 3560 switch need before switchport mode trunk?
> switchport trunk encapsulation dot1q, because a 3560 must be told which tagging type to use.
