# 0.4 The DOS Retro Track in C

> [!abstract] Why this matters
> Optional and fun: C was the language of DOS. Compile a C program with Open Watcom (the compiler behind Doom's DOS version) and run it in an emulated PC. You'll see how much your modern tools do for you.

## Set up

- Open Watcom 2: installs to `~/opt/open-watcom-2` (the C++ vault's code has `scripts/install-open-watcom.sh`; it works for C too).
- DOSBox-X: `sudo apt install dosbox-x`.

## A DOS program

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("Hello from DOS!\n");
    printf("INT_MAX here is %d\n", INT_MAX);
    return 0;
}
```

Save it as `hello.c` (8 letters or fewer: DOS names are 8.3), then Tools → DOS retro track → compile and run in DOSBox-X.

## What you'll notice

- `INT_MAX` is **32767**: a 16-bit int. On Linux it's 2147483647.
- No memory protection: a bad pointer can overwrite DOS itself, and the machine just hangs. No sanitizers, no Valgrind, no SEGV report.
- Far and near pointers, memory models, 640K: the problems C programmers solved in 1991.

> [!sith] The dark side
> Writing code that assumes int is 32 bits. When the size matters, use `<stdint.h>`: `int32_t`, `uint8_t`.

## Check yourself

> [!question]- Why is INT_MAX 32767 in a 16-bit DOS program?
> The C standard only requires int to be at least 16 bits; a 16-bit DOS compiler makes it exactly that, so the largest int is 2^15 - 1.
