# 0.4 The DOS Retro Track in C

> [!abstract] Why this matters
> This one is optional, and just for fun. C was the main language of DOS, the system PCs ran before Windows. You'll build a C program with Open Watcom, the compiler used for Doom on DOS. Then you'll run it on a pretend old PC. You'll see how much your modern tools do for you.

## Set up

- **Open Watcom 2** installs into `~/opt/open-watcom-2`. The C++ vault's code has a script for it, `scripts/install-open-watcom.sh`. It works for C too.
- **DOSBox-X** pretends to be an old PC. Install it with `sudo apt install dosbox-x`.

## A DOS program

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("Hello from DOS!\n");
    printf("INT_MAX here is %d\n", INT_MAX);
    return 0;
}
```

1. Save it as `hello.c`. DOS file names can only have 8 letters before the dot.
2. Choose Tools → DOS retro track.
3. Build it, then run it in DOSBox-X.

## What you'll notice

- `INT_MAX`, the biggest `int`, is **32767**. That's because an `int` on DOS is 16 bits. On Linux it's 32 bits, so the biggest `int` is 2147483647.
- Nothing protects memory. A bad pointer can overwrite DOS itself, and the whole machine just freezes. There are no checkers and no crash reports.
- You'll meet old problems like memory models and the 640 KB memory limit. C programmers in 1991 had to deal with these every day.

> [!sith] The dark side
> Writing code that assumes an `int` is always 32 bits. When the size matters, use the types from `<stdint.h>`, like `int32_t` or `uint8_t`. Their size is in their name.

## Check yourself

> [!question]- Why is INT_MAX 32767 in a 16-bit DOS program?
> The C standard only says an int must be at least 16 bits. A 16-bit DOS compiler makes it exactly 16 bits. The biggest number that fits is 2 to the power 15, minus 1, which is 32767.
