# 0.3 Reading man Pages

> [!abstract] Why this matters
> The C library's manual is already on your machine, it's precise, and it answers the questions that matter most in C: what does this return when it fails, and who frees what.

## Sections

`man` has numbered sections. The two you'll use:

| Section | Has |
|---|---|
| 2 | system calls: `open`, `read`, `write`, `fork` |
| 3 | the C library: `printf`, `malloc`, `strlen`, `fopen` |

`man 3 printf` (not `man printf`, which is the shell command). In the workbench: Help → man page..., or the button in the reference (Ctrl+Shift+H).

## Read these parts first

1. **SYNOPSIS**: the `#include` you need and the exact parameter types.
2. **RETURN VALUE**: what it gives back, and what it gives back when it **fails**.
3. **ERRORS**: the errno values it can set.
4. **NOTES / BUGS**: the traps.

## Try it

Open `man 3 fgets` and answer: what does it return at the end of the file? Does the newline end up in the buffer? Then `man 3 strtol`: how do you tell "0" from "not a number"?

> [!sith] The dark side
> Skipping RETURN VALUE. Almost every C crash you'll write starts with a function that failed, returned NULL or -1, and code that used the result anyway.

## Check yourself

> [!question]- Which man section is the C library in, and which has system calls?
> Section 3 is the C library; section 2 is system calls.

> [!question]- What does fgets return at end of file?
> NULL (and it leaves the buffer as it was if nothing was read).
