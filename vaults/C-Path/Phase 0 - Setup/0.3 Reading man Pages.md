# 0.3 Reading man Pages

> [!abstract] Why this matters
> The C library's manual is already on your computer. It's exact, and it answers the two most important questions in C. What does this function give back when it fails? And who has to free the memory?

## Sections

The manual, called `man`, is split into numbered sections. You'll mostly use two:

| Section | What's in it |
|---|---|
| 2 | System calls, like `open`, `read`, `write` and `fork`. These ask the operating system to do something. |
| 3 | The C library, like `printf`, `malloc`, `strlen` and `fopen`. |

Type `man 3 printf` to get the C function. Plain `man printf` gives you a shell command with the same name.

In the workbench, use Help → man page..., or the button in the reference (Ctrl+Shift+H).

## Read these parts first

1. **SYNOPSIS** shows the `#include` line you need, and the exact types of the inputs.
2. **RETURN VALUE** says what the function gives back. It also says what it gives back when it **fails**.
3. **ERRORS** lists the error codes it can set.
4. **NOTES** and **BUGS** list the traps.

## Try it

1. Open `man 3 fgets`.
2. Find out what it returns at the end of a file.
3. Find out whether the newline character ends up in your buffer.
4. Now open `man 3 strtol`.
5. Find out how to tell the input "0" apart from input that isn't a number.

> [!sith] The dark side
> Skipping the RETURN VALUE part. Many crashes in C start the same way. A function fails and returns NULL or -1. Then the code uses that result anyway.

## Check yourself

> [!question]- Which man section has the C library, and which has system calls?
> Section 3 has the C library. Section 2 has system calls.

> [!question]- What does fgets return at the end of a file?
> It returns NULL. If it read nothing, it leaves your buffer as it was.
