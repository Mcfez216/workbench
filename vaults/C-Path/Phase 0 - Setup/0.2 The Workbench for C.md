# 0.2 The Workbench for C

> [!abstract] Why this matters
> A few keys do almost everything. Learn them once, and the tools fade into the background.

## Switch to C

The toolbar's **C | C++** switch (or Ctrl+Shift+J). With **C** lit: new files are `.c`, the sandbox is C, the judge expects C, and gcc with C17 is used. A `.c` file is always C whatever the switch says.

## The keys

| Key | Does |
|---|---|
| **Ctrl+F9** | build and run this file (gcc, sanitizers on) |
| **F9** | build |
| **F7** | check the exercise you're in, or run the tests |
| **Ctrl+Shift+D** | gdb, stopped at your cursor's line |
| **F4** | the C sandbox |
| **Ctrl+Shift+H** | look up a function (printf, malloc...) without leaving the app |
| **Ctrl+Shift+P** | any command by name |

## Where to practise

- **Learn** (toolbar): exercises. The C basics track goes with Phases 1 to 4; the Security lab with Phase 6.
- **Sandbox** (F4): quick experiments. The examples list has the C classics and the "break it" programs.
- **Memory view** (Learn → Visualise memory): watch variables and pointers as boxes and arrows.

## Try it

1. Switch to C.
2. File → New file → Program. Name it `hello`, in a folder like `~/c-path`.
3. Ctrl+F9.
4. Learn → **First functions**: F7 checks it.

> [!sith] The dark side
> Writing a whole program before compiling once. Compile every few lines: the errors stay small and close to what you just typed.

## Check yourself

> [!question]- What changes when you flip the toolbar switch to C?
> New files, new projects, the sandbox and the judge use C (gcc, C17), and .h headers are treated as C.

> [!question]- How do you look up what a C library function does without leaving the workbench?
> Ctrl+Shift+H on the function's name opens the built-in reference (with a man page button).
