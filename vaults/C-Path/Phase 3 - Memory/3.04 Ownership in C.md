# 3.04 Ownership in C

> [!abstract] Why this matters
> C doesn't tell you who should free each block of memory. You decide, you write it down, and you stick to it. Giving every block one clear owner is what stops C programs leaking.

## The habits

- **One owner for each block.** The owner frees it. Everyone else only borrows it.
- **Make and destroy in pairs.** Every `thing_create` function has a `thing_destroy` function. Code that uses a thing never frees its insides by hand.
- **Write it in a comment.** For example: "Returns a new string. The caller must free it." Or: "The list owns this pointer. Don't free it."
- **Clean up in one place.** At the end of a function, a `fail:` label with `goto` is the usual C way to free everything when something goes wrong.

## An example

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *name; int *scores; size_t n; } Pilot;

/* Returns a new Pilot; the caller owns it and must call pilot_destroy. NULL on failure. */
static Pilot *pilot_create(const char *name, size_t n) {
    Pilot *p = calloc(1, sizeof *p);
    if (!p) goto fail;
    p->name = malloc(strlen(name) + 1);
    if (!p->name) goto fail;
    strcpy(p->name, name);
    p->scores = calloc(n, sizeof *p->scores);
    if (!p->scores) goto fail;
    p->n = n;
    return p;
fail:                       /* one exit for every failure: frees whatever got made */
    if (p) { free(p->name); free(p); }
    return NULL;
}

static void pilot_destroy(Pilot *p) {   /* safe with NULL, like free */
    if (!p) return;
    free(p->scores);
    free(p->name);
    free(p);
}

int main(void) {
    Pilot *wedge = pilot_create("Wedge Antilles", 3);
    if (!wedge) return 1;
    wedge->scores[0] = 7;
    printf("%s: %d\n", wedge->name, wedge->scores[0]);
    pilot_destroy(wedge);
    return 0;
}
```

`pilot_create` makes three blocks: the Pilot itself, its name, and its scores. If any `malloc` fails, it jumps to `fail:`, which frees whatever was already made.

`pilot_destroy` frees all three. It's safe to call with `NULL`, just like `free`.

## Try it

1. Click **Try in sandbox** and run it with the sanitizers on. No leaks are reported.
2. Delete one of the `free` lines in `pilot_destroy`.
3. Run it again. LeakSanitizer tells you exactly which block was never freed.

> [!sith] The dark side
> Two parts of the program both think they own the same block. Then either both free it, which is a double free, or one frees it while the other is still using it. If you can't say who owns a block, that's already a bug.

## Check yourself

> [!question]- What is the create and destroy pattern?
> Every type that uses memory gets two functions. Create builds it, and destroy frees everything it owns. Code that uses the type only calls those two.

> [!question]- Why is goto acceptable for cleanup in C?
> It sends every failure to one place that frees whatever was made so far. Otherwise you'd repeat the cleanup in every branch, and it's easy to get one wrong.
