# 3.04 Ownership in C

> [!abstract] Why this matters
> C won't tell you who should free a block. So you decide, write it down, and stick to it. A clear owner for every allocation is what separates C code that leaks from C code that doesn't.

## The conventions

- **One owner per block.** The owner frees it. Everyone else just borrows.
- **Pairs.** Every `thing_create` has a `thing_destroy`. Callers never free the insides themselves.
- **Say it in the comment.** "Returns a new string; the caller must free it." / "The returned pointer belongs to the list; don't free it."
- **Clean up in one place.** A `goto cleanup` at the end of a function is the standard C way to free everything on every path.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *name; int *scores; size_t n; } Pilot;

/* Returns a new Pilot; the caller owns it and must call pilot_destroy. NULL on failure. */
static Pilot *pilot_create(const char *name, size_t n) {
    Pilot *p = calloc(1, sizeof *p);
    if (!p) goto fail;
    p->name = malloc(strlen(name) + 1);
    if (!p->name) goto fail;
    strcpy(p->name, name);
    p->scores = calloc(n, sizeof *p->scores);
    if (!p->scores) goto fail;
    p->n = n;
    return p;
fail:                       /* one exit for every failure: frees whatever got made */
    if (p) { free(p->name); free(p); }
    return NULL;
}

static void pilot_destroy(Pilot *p) {   /* safe with NULL, like free */
    if (!p) return;
    free(p->scores);
    free(p->name);
    free(p);
}

int main(void) {
    Pilot *wedge = pilot_create("Wedge Antilles", 3);
    if (!wedge) return 1;
    wedge->scores[0] = 7;
    printf("%s: %d\n", wedge->name, wedge->scores[0]);
    pilot_destroy(wedge);
    return 0;
}
```

## Try it

- **Try in sandbox** with the sanitizers on: no leaks. Remove one `free` from `pilot_destroy` and see exactly which allocation LeakSanitizer reports.

> [!sith] The dark side
> Two parts of the program both thinking they own a block: both free it (double free) or one frees it while the other is still using it. If you can't say who owns something, that's the bug.

## Check yourself

> [!question]- What is the "create/destroy" pattern?
> Every type that allocates gets a create function that builds it and a destroy function that frees everything it owns; callers only use those two.

> [!question]- Why is goto acceptable for cleanup in C?
> It gives every failure path one exit that frees whatever was allocated, instead of repeating the cleanup (and getting it wrong) in each branch.
