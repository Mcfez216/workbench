# 3.02 malloc and free

> [!abstract] Why this matters
> malloc and free are how C gets memory whose size you only know at run time. The rules are short, and breaking any of them is a classic bug: a leak, a double free, a use-after-free.

## The pattern

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    size_t n = 5;
    int *scores = malloc(n * sizeof *scores);   /* sizeof *ptr: stays right if the type changes */
    if (scores == NULL) {                       /* malloc can fail: check */
        fprintf(stderr, "out of memory\n");
        return 1;
    }
    for (size_t i = 0; i < n; i++) scores[i] = (int)(i * 10);

    int *zeros = calloc(n, sizeof *zeros);      /* zeroed, and checks n * size for overflow */
    if (!zeros) { free(scores); return 1; }

    char *copy = malloc(strlen("Kessel") + 1);  /* +1 for the '\0' */
    if (!copy) { free(zeros); free(scores); return 1; }
    strcpy(copy, "Kessel");                     /* safe: we sized it exactly */

    printf("%d %d %s\n", scores[4], zeros[4], copy);

    free(copy);
    free(zeros);
    free(scores);
    scores = NULL;                              /* a freed pointer set to NULL can't be used by accident */
    free(scores);                               /* free(NULL) is allowed and does nothing */
    return 0;
}
```

## The rules

1. Check every `malloc` / `calloc` / `realloc` for NULL.
2. Size with `n * sizeof *ptr`; prefer `calloc(n, size)` for arrays.
3. `free` every block exactly once, with the pointer malloc gave you.
4. Never use a block after freeing it. Set the pointer to NULL.
5. malloc'd memory starts with garbage in it; calloc's starts zeroed.

## Try it

- **Try in sandbox** with the sanitizers on. Then delete `free(copy);`: LeakSanitizer reports "6 bytes leaked" and where they were allocated. Then free `scores` twice (without the NULL): "attempting double-free".
- Cheat sheet: [[Cheat Sheet - Memory and Sanitizers]].

> [!sith] The dark side
> Use-after-free: freeing a block, then using a pointer that still holds its address. The memory may already belong to something else. In browsers and kernels this is one of the most exploited bug classes there is.

## Check yourself

> [!question]- Why write malloc(n * sizeof *p) rather than malloc(n * sizeof(int))?
> It stays correct if p's type changes, because the size comes from what p points to.

> [!question]- Name three ways to misuse free.
> Not calling it (a leak), calling it twice on the same block (a double free), and using the block after it (use-after-free). Freeing a pointer malloc didn't return is a fourth.

> [!question]- What's the difference between malloc and calloc?
> calloc zeroes the memory and takes a count and a size (checking their product for overflow); malloc leaves it uninitialised.
