# 3.02 malloc and free

> [!abstract] Why this matters
> `malloc` and `free` let you get memory when you only know the size while the program runs. The rules are short. Breaking any of them causes a classic bug: a leak, a double free, or a use-after-free.

## An example

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    size_t n = 5;
    int *scores = malloc(n * sizeof *scores);   /* sizeof *ptr: stays right if the type changes */
    if (scores == NULL) {                       /* malloc can fail: check */
        fprintf(stderr, "out of memory\n");
        return 1;
    }
    for (size_t i = 0; i < n; i++) scores[i] = (int)(i * 10);

    int *zeros = calloc(n, sizeof *zeros);      /* zeroed, and checks n * size for overflow */
    if (!zeros) { free(scores); return 1; }

    char *copy = malloc(strlen("Kessel") + 1);  /* +1 for the '\0' */
    if (!copy) { free(zeros); free(scores); return 1; }
    strcpy(copy, "Kessel");                     /* safe: we sized it exactly */

    printf("%d %d %s\n", scores[4], zeros[4], copy);

    free(copy);
    free(zeros);
    free(scores);
    scores = NULL;                              /* a freed pointer set to NULL can't be used by accident */
    free(scores);                               /* free(NULL) is allowed and does nothing */
    return 0;
}
```

## The rules

1. Check every `malloc`, `calloc` and `realloc` result. If it's `NULL`, there was no memory to give you.
2. Work out sizes as `n * sizeof *ptr`. This stays right even if you change the pointer's type later. For arrays, `calloc(n, size)` is safer, because it checks the multiplication for you.
3. `free` every block exactly once, using the pointer `malloc` gave you.
4. Never use a block after freeing it. Set the pointer to `NULL` straight after.
5. Memory from `malloc` starts full of leftover values. Memory from `calloc` starts as all zeros.

## Try it

1. Click **Try in sandbox** and run it with the sanitizers on. No reports.
2. Delete the line `free(copy);` and run it again.
3. LeakSanitizer reports that 6 bytes leaked, and shows where they were allocated. A **leak** means memory that's never given back.
4. Put it back. Now delete `scores = NULL;`, and add a second `free(scores);` straight after the first.
5. Run it. You'll see "attempting double-free".
6. The cheat sheet [[Cheat Sheet - Memory and Sanitizers]] lists these reports.

> [!sith] The dark side
> Use-after-free: freeing a block, then using a pointer that still holds its old address. That memory may already belong to something else. In web browsers and operating systems, attackers use this bug more than almost any other.

## Check yourself

> [!question]- Why write malloc(n * sizeof *p) instead of malloc(n * sizeof(int))?
> It stays right if p's type changes later, because the size comes from what p points to.

> [!question]- Name three ways to misuse free.
> Never calling it, which is a leak. Calling it twice on the same block, which is a double free. Using the block after freeing it, which is a use-after-free.

> [!question]- What's the difference between malloc and calloc?
> calloc sets all the memory to zero, and checks that count × size doesn't overflow. malloc leaves the memory full of leftover values.
