# 3.03 realloc and Growing Arrays

> [!abstract] Why this matters
> Often you don't know how many things you'll need to store. For example, "read lines until there are no more". The answer is an array that doubles in size when it fills up. C++'s vector and Python's list work this way inside. You'll build one yourself in [[Projects/Start Here|C03 Dynamic Array Library]].

## An example

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    size_t len, cap;
} IntList;

static int push(IntList *l, int value) {
    if (l->len == l->cap) {
        size_t newcap = l->cap ? l->cap * 2 : 4;
        int *bigger = realloc(l->data, newcap * sizeof *bigger);   /* into a NEW pointer */
        if (!bigger) return -1;     /* the old block is still valid and still ours */
        l->data = bigger;
        l->cap = newcap;
    }
    l->data[l->len++] = value;
    return 0;
}

int main(void) {
    IntList l = {0};                 /* data NULL: realloc(NULL, n) acts like malloc */
    for (int i = 1; i <= 20; i++) {
        size_t before = l.cap;
        if (push(&l, i * i) != 0) { free(l.data); return 1; }
        if (l.cap != before) printf("grew to %zu\n", l.cap);
    }
    printf("%zu items, last %d\n", l.len, l.data[l.len - 1]);
    free(l.data);
    return 0;
}
```

The list keeps three things:

- `data` points to the numbers.
- `len` is how many numbers are in use.
- `cap` is how many fit before it has to grow.

When `len` reaches `cap`, `push` asks `realloc` for a block twice as big. `realloc` may move the numbers to a new place, and it gives you the new address.

## Why double the size?

Growing by one each time means copying every number on every push. That gets very slow. Doubling means each number is only copied a few times in total. So adding a number stays fast on average.

## Try it

1. Click **Try in sandbox** and run the example. It shows each time the list grows.
2. Change the growth to `l->cap + 1`.
3. Push 100,000 numbers instead of 20, and feel how much slower it is.

> [!sith] The dark side
> Writing `p = realloc(p, n);`. If `realloc` fails, it returns `NULL`, and the old block is still there. But you've just overwritten your only pointer to it. So the old block leaks, and `p` is now NULL. Always put the result in a second variable first, like `push` does with `bigger`.

## Check yourself

> [!question]- Why should you put realloc's result in a second pointer first?
> If realloc fails, it returns NULL but keeps the old block. Writing NULL straight back would lose your only pointer to that block.

> [!question]- What does realloc(NULL, n) do?
> The same as malloc(n).

> [!question]- Why grow an array by doubling it, instead of adding one space?
> Each push stays fast on average. With doubling, the total copying grows in step with the number of items. Adding one space at a time makes the copying grow much faster than that.
