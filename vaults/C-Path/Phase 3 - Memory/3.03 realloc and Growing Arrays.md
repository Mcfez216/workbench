# 3.03 realloc and Growing Arrays

> [!abstract] Why this matters
> "Read lines until there are no more" means storing an unknown number of things. The answer is an array that doubles when it fills up. It's how C++'s vector and Python's list work underneath, and you'll build it yourself in [[Projects/Start Here|C03 Dynamic Array Library]].

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    size_t len, cap;
} IntList;

static int push(IntList *l, int value) {
    if (l->len == l->cap) {
        size_t newcap = l->cap ? l->cap * 2 : 4;
        int *bigger = realloc(l->data, newcap * sizeof *bigger);   /* into a NEW pointer */
        if (!bigger) return -1;     /* the old block is still valid and still ours */
        l->data = bigger;
        l->cap = newcap;
    }
    l->data[l->len++] = value;
    return 0;
}

int main(void) {
    IntList l = {0};                 /* data NULL: realloc(NULL, n) acts like malloc */
    for (int i = 1; i <= 20; i++) {
        size_t before = l.cap;
        if (push(&l, i * i) != 0) { free(l.data); return 1; }
        if (l.cap != before) printf("grew to %zu\n", l.cap);
    }
    printf("%zu items, last %d\n", l.len, l.data[l.len - 1]);
    free(l.data);
    return 0;
}
```

## Why double?

Growing by one each time copies everything every time: n pushes cost about n² copies. Doubling means each element is copied only a couple of times on average, so pushes are cheap ("amortised O(1)").

## Try it

- **Try in sandbox**. Change the growth to `l->cap + 1` and push 100 000 items: feel the difference.

> [!sith] The dark side
> `p = realloc(p, n);` If realloc fails it returns NULL, and you've just overwritten your only pointer to the old block: a leak, and then a NULL dereference. Always realloc into a temporary first.

## Check yourself

> [!question]- Why assign realloc's result to a temporary pointer?
> If it fails it returns NULL but leaves the old block allocated; assigning straight back would lose the only pointer to it.

> [!question]- What does realloc(NULL, n) do?
> The same as malloc(n).

> [!question]- Why grow by doubling rather than by one?
> Each push is cheap on average: the total copying is proportional to n, not n squared.
