# 3.01 Stack and Heap

> [!abstract] Why this matters
> Every variable lives somewhere, for some length of time. Knowing where (the stack or the heap) answers the big C questions: why returning a pointer to a local is a bug, why big arrays crash, and who has to call free.

## Two places

| | Stack | Heap |
|---|---|---|
| What goes there | local variables, function arguments | whatever you `malloc` |
| Lifetime | until the function returns | until you `free` it |
| Size | small (often 8 MB) | as much as the machine has |
| Speed | very fast | slower to allocate |
| Who cleans up | automatic | you |

```c
#include <stdio.h>
#include <stdlib.h>

static int *make_counter(void) {
    int *c = malloc(sizeof *c);   /* on the heap: survives the return */
    if (c) *c = 0;
    return c;
}

/* static int *broken(void) { int local = 5; return &local; }   local dies at the return */

int main(void) {
    int on_stack = 42;
    int *on_heap = make_counter();
    if (!on_heap) return 1;
    *on_heap += 3;
    printf("stack var at %p, heap block at %p, value %d\n",
           (void *)&on_stack, (void *)on_heap, *on_heap);
    free(on_heap);                /* your job, exactly once */
    on_heap = NULL;
    return 0;
}
```

## Try it

- Learn → **Visualise memory** on this example: the stack frames on one side, the heap block on the other, and the arrow between them.
- **Try in sandbox**: uncomment `broken`, call it and print the value. The compiler warns, and ASan (with `detect_stack_use_after_return`) catches it.

> [!sith] The dark side
> Returning the address of a local variable. The frame is gone the moment the function returns; the next call reuses it, and your "value" changes under you.

## Check yourself

> [!question]- How long does a local variable live?
> Until the function (or block) it's declared in ends.

> [!question]- Why can't a function return a pointer to its own local variable?
> The local's memory is released when the function returns; the pointer is left dangling.

> [!question]- Why might int big[10000000]; inside main crash?
> It's 40 MB on the stack, which is usually limited to a few MB: a stack overflow. Use malloc for big buffers.
