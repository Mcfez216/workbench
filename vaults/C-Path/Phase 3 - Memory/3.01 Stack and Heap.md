# 3.01 Stack and Heap

> [!abstract] Why this matters
> Every variable lives somewhere, for some amount of time. In C there are two main places: the **stack** and the **heap**. Knowing which one answers the big questions in C. Why can't you return the address of a local variable? Why do big arrays crash? Who has to call free?

## Two places

| | The stack | The heap |
|---|---|---|
| What goes there | Local variables and function inputs | Whatever you ask `malloc` for |
| How long it lasts | Until the function ends | Until you call `free` |
| Size | Small, often 8 MB | As much as the computer has |
| Speed | Very fast | A bit slower to get |
| Who cleans it up | C does it for you | You do |

## An example

```c
#include <stdio.h>
#include <stdlib.h>

static int *make_counter(void) {
    int *c = malloc(sizeof *c);   /* on the heap: survives the return */
    if (c) *c = 0;
    return c;
}

/* static int *broken(void) { int local = 5; return &local; }   local dies at the return */

int main(void) {
    int on_stack = 42;
    int *on_heap = make_counter();
    if (!on_heap) return 1;
    *on_heap += 3;
    printf("stack var at %p, heap block at %p, value %d\n",
           (void *)&on_stack, (void *)on_heap, *on_heap);
    free(on_heap);                /* your job, exactly once */
    on_heap = NULL;
    return 0;
}
```

`make_counter` asks `malloc` for space on the heap. That space lasts after the function ends, so it's safe to return its address. The caller then has to `free` it.

The `broken` function, which is commented out, returns the address of a local variable. That variable is on the stack, and it's gone as soon as the function ends.

## Try it

1. Open the example in Learn → **Visualise memory**.
2. Step through it. The stack is on one side, the heap is on the other, and an arrow joins them.
3. Click **Try in sandbox**. Remove the `/*` and `*/` around `broken`.
4. Call it from `main`, and print the value it points to. The compiler warns you. AddressSanitizer catches it when it runs.

> [!sith] The dark side
> Returning the address of a local variable. Its space is given back the moment the function returns. The next function call reuses that space, and your "value" changes without warning.

## Check yourself

> [!question]- How long does a local variable last?
> Until the function, or the block in curly brackets, that it's in ends.

> [!question]- Why can't a function return a pointer to its own local variable?
> The local variable's memory is given back when the function ends. The pointer is left pointing at memory that something else will use.

> [!question]- Why might int big[10000000]; inside main crash?
> That's 40 MB on the stack, and the stack is usually only a few MB. This is called a stack overflow. Use malloc for big arrays.
