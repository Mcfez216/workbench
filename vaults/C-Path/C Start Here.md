# C Start Here

> [!abstract] Why this matters
> C is the language underneath operating systems, drivers and small devices. Many famous security bugs are C bugs. Learning C teaches you how a computer really uses memory. Developers and security people both need that.

> [!holocron] How this vault works
> Every note has the same parts, in the same order, so you always know where to look.
> 1. **Why this matters** is at the top.
> 2. Then the idea, in short sections.
> 3. Then some code. In the workbench, set the switch to **C** and click **Try in sandbox** to run it.
> 4. **Try it** gives you something to do, in numbered steps.
> 5. **The dark side** shows one common mistake.
> 6. **Check yourself** has questions. Click one to see the answer. They also become flashcards in Revise (Ctrl+Shift+V).
> 7. A link to the next note.
>
> A note takes 5 to 15 minutes. You don't have to finish a phase in one go.

## Your first hour

1. Read [[0.1 The C Toolchain]].
2. Read [[0.2 The Workbench for C]], and set the toolbar switch to **C**.
3. Read [[1.01 Why C and How It Compiles]].
4. Open Learn → **First functions**. It's your first C exercise.

## A daily habit

15 to 45 minutes a day is plenty.

1. **Start** with Learn → Where was I?
2. **Focus** with Ctrl+Shift+G. Pick one thing and start the timer.
3. **Do** one note, or one step of an exercise.
4. **Finish** by writing one line in [[C Done Log]].

> [!tip] Stuck?
> Click the **?** next to an error. It explains the error in plain words. The note's "dark side" box often names the mistake too. If you're still stuck, take a short break.
