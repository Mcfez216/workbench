# 2.01 Arrays

> [!abstract] Why this matters
> An array is a row of same-sized boxes, side by side in memory. C doesn't check that you stay inside the row. Writing past the end is the root of the most famous security bug there is, so the habits start here.

```c
#include <stdio.h>

#define CREW 4                          /* one name for the size, used everywhere */

static double average(const int *values, size_t n) {   /* an array arrives as a pointer: pass its length too */
    long sum = 0;
    for (size_t i = 0; i < n; i++) sum += values[i];
    return n ? (double)sum / (double)n : 0.0;
}

int main(void) {
    int ages[CREW] = {19, 23, 32, 41};
    int scores[10] = {0};               /* all zeros */
    size_t count = sizeof ages / sizeof ages[0];   /* works here, where ages is a real array */

    for (size_t i = 0; i < count; i++)            /* 0 to count-1: never <= count */
        printf("ages[%zu] = %d at %p\n", i, ages[i], (void *)&ages[i]);
    printf("average %.1f, scores[9] = %d\n", average(ages, count), scores[9]);
    return 0;
}
```

The printed addresses go up by `sizeof(int)` (usually 4): the boxes really are side by side.

## Arrays decay

Pass an array to a function and it arrives as a pointer to its first element: the size is lost. That's why `average` takes `n`, and why `sizeof` inside it would give the pointer's size, not the array's.

## Try it

- **Try in sandbox**. Change the loop to `i <= count` and build with the sanitizers on: AddressSanitizer reports a stack-buffer-overflow and names the line.
- Learn → **Visualise memory**: the four boxes in a row.

> [!sith] The dark side
> The off-by-one: `i <= n`, or `char name[8]` holding an 8-letter name with no room for the terminator. C writes past the end without a word, onto whatever sits next to it.

## Check yourself

> [!question]- What does sizeof arr / sizeof arr[0] give you, and where does it stop working?
> The number of elements; it stops working once the array has decayed to a pointer, for example inside a function it was passed to.

> [!question]- What are the valid indexes of int a[5]?
> 0 to 4.

> [!question]- Why does a function taking an array also need its length?
> The array arrives as a pointer to its first element, which carries no size.
