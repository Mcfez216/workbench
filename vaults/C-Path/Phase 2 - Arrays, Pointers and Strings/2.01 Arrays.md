# 2.01 Arrays

> [!abstract] Why this matters
> An array is a row of boxes, all the same size, side by side in memory. C doesn't check that you stay inside the row. Writing past the end is the cause of the most famous security bug there is. So the safe habits start here.

## An example

```c
#include <stdio.h>

#define CREW 4                          /* one name for the size, used everywhere */

static double average(const int *values, size_t n) {   /* an array arrives as a pointer: pass its length too */
    long sum = 0;
    for (size_t i = 0; i < n; i++) sum += values[i];
    return n ? (double)sum / (double)n : 0.0;
}

int main(void) {
    int ages[CREW] = {19, 23, 32, 41};
    int scores[10] = {0};               /* all zeros */
    size_t count = sizeof ages / sizeof ages[0];   /* works here, where ages is a real array */

    for (size_t i = 0; i < count; i++)            /* 0 to count-1: never <= count */
        printf("ages[%zu] = %d at %p\n", i, ages[i], (void *)&ages[i]);
    printf("average %.1f, scores[9] = %d\n", average(ages, count), scores[9]);
    return 0;
}
```

When you run it, look at the addresses it prints. Each one is `sizeof(int)` bigger than the last, usually 4. That shows the boxes really are side by side.

## The size, and how to find it

- `int ages[CREW]` makes an array of `CREW` ints.
- The first element is `ages[0]`. The last one is `ages[CREW - 1]`.
- `sizeof ages / sizeof ages[0]` works out how many elements there are. It divides the size of the whole array by the size of one element.

## Arrays lose their size in functions

When you pass an array to a function, the function only gets the address of the first element. It doesn't get the size. People say the array **decays** to a pointer.

That's why `average` needs `n` as a second input. Inside the function, `sizeof` would give the size of a pointer, not the size of the array.

## Try it

1. Click **Try in sandbox** and run the example.
2. Change the loop to `i <= count`, so it runs one time too many.
3. Run it with the sanitizers on. AddressSanitizer reports a **stack-buffer-overflow**, and names the line.
4. To see the boxes, open it in Learn → **Visualise memory**.

> [!sith] The dark side
> Going one past the end. It happens with `i <= n` in a loop. It also happens with `char name[8]` holding an 8-letter name, because there's no room left for the `'\0'` at the end. C writes past the end without a word, over whatever is stored next.

## Check yourself

> [!question]- What does sizeof arr / sizeof arr[0] give you, and when does it stop working?
> It gives the number of elements in the array. It stops working inside a function the array was passed to, because there the array is only a pointer.

> [!question]- What are the valid indexes of int a[5]?
> 0, 1, 2, 3 and 4.

> [!question]- Why does a function that takes an array also need its length?
> The function only gets a pointer to the first element. A pointer doesn't know how many elements come after it.
