# 2.02 Pointers

> [!abstract] Why this matters
> A pointer is a variable that holds an address: where something lives. Everything powerful in C (arrays, strings, the heap, data structures, talking to hardware) is built on them. One picture makes them click: a box holding the address of another box.

## Two operators

- `&x` gives the address of x.
- `*p` goes to the address in p (dereference).

```c
#include <stdio.h>

static void refuel(int *tank, int amount) {   /* a pointer lets a function change the caller's variable */
    if (tank == NULL) return;                  /* check pointers you didn't make yourself */
    *tank += amount;
}

int main(void) {
    int fuel = 40;
    int *p = &fuel;              /* p holds fuel's address */

    printf("fuel=%d, &fuel=%p, p=%p, *p=%d\n", fuel, (void *)&fuel, (void *)p, *p);
    *p = 55;                     /* changes fuel itself */
    refuel(&fuel, 10);
    printf("fuel is now %d\n", fuel);

    int *nothing = NULL;         /* "points nowhere", on purpose */
    refuel(nothing, 5);          /* safe: refuel checks */
    printf("sizeof(int*) = %zu\n", sizeof p);
    return 0;
}
```

## Pointers and functions

C passes everything **by value**: a function gets copies. To change the caller's variable, pass its address. That's why `scanf("%d", &x)` needs the `&`.

## Try it

- Learn → **Visualise memory** on this example: step through and watch the arrow from p to fuel, then watch fuel change through it.
- **Try in sandbox**: remove the NULL check and call `refuel(NULL, 5)`. The sanitizer reports a SEGV on an address of 0.

> [!sith] The dark side
> An uninitialised pointer (`int *p; *p = 5;`) holds whatever was in that memory: it points somewhere random, and writing there corrupts memory or crashes. Initialise every pointer, to a real address or NULL.

## Check yourself

> [!question]- If p == &x, what is *p?
> x itself: reading *p reads x, and assigning to *p changes x.

> [!question]- Why does a function need a pointer parameter to change the caller's variable?
> C passes arguments by value; only with the variable's address can the function reach the original.

> [!question]- What should a pointer hold if it doesn't point at anything yet?
> NULL.
