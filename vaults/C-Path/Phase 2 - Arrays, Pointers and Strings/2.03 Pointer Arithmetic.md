# 2.03 Pointer Arithmetic

> [!abstract] Why this matters
> Adding 1 to a pointer moves it to the next element, not the next byte. That one rule explains why `a[i]` works, why pointers have types, and how C walks through memory.

```c
#include <stdio.h>

int main(void) {
    int parsecs[] = {12, 14, 9, 30};
    size_t n = sizeof parsecs / sizeof parsecs[0];
    int *p = parsecs;                   /* the array decays to &parsecs[0] */

    printf("p   = %p\np+1 = %p (moved %zu bytes)\n",
           (void *)p, (void *)(p + 1), sizeof *p);
    printf("parsecs[2] = %d, *(p + 2) = %d\n", parsecs[2], *(p + 2));   /* the same thing */

    for (int *it = parsecs; it != parsecs + n; it++)   /* walk with a pointer; stop at one-past-the-end */
        printf("%d ", *it);
    printf("\n");

    int *last = &parsecs[n - 1];
    printf("elements between: %td\n", last - p);       /* subtracting pointers counts elements */
    return 0;
}
```

## The rules

- `p + i` moves `i * sizeof *p` bytes.
- `a[i]` is defined as `*(a + i)`.
- Subtracting two pointers into the same array gives the number of elements between them (`ptrdiff_t`, printed with `%td`).
- You may point one past the end, but never read or write there.

## Try it

- **Try in sandbox**. Change `int` to `double`: the step becomes 8 bytes.
- Learn → **Visualise memory**, stepping through the loop.

> [!sith] The dark side
> Arithmetic that leaves the array (`p - 1`, `p + n + 1`) is undefined behaviour even if you never dereference it. And casting to `char *` and back to reinterpret bytes is where alignment and aliasing bugs live.

## Check yourself

> [!question]- If int *p is at address 1000 and sizeof(int) is 4, where is p + 3?
> 1012: it moves 3 elements of 4 bytes.

> [!question]- What is a[i] defined as?
> *(a + i).

> [!question]- Can you point one past the end of an array? Can you read there?
> You can point there (for comparisons, as an end marker), but reading or writing there is undefined behaviour.
