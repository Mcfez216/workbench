# 2.05 const and Pointers

> [!abstract] Why this matters
> Writing `const` on a function's input is a promise: "I only look at this, I don't change it". It tells other people what the function does. The compiler also makes sure you keep the promise.

## Read it from right to left

| Declaration | What it means |
|---|---|
| `const char *s` | A pointer to const chars. You can't change the chars through `s`. |
| `char *const s` | A const pointer. `s` can't be moved to point somewhere else. The chars can change. |
| `const char *const s` | Neither can change. |

## An example

```c
#include <ctype.h>
#include <stdio.h>

static size_t count_upper(const char *s) {   /* the const promises: only reading */
    size_t n = 0;
    for (; *s; s++)                            /* moving s itself is allowed */
        if (isupper((unsigned char)*s)) n++;
    /* *s = 'x';  would be an error: the chars are const here */
    return n;
}

static void shout(char *s) {                   /* no const: this one changes the text */
    for (; *s; s++) *s = (char)toupper((unsigned char)*s);
}

int main(void) {
    char line[] = "Never tell me the Odds";
    printf("%zu capitals\n", count_upper(line));
    shout(line);
    printf("%s\n", line);
    return 0;
}
```

`count_upper` only reads the text, so its input is `const char *`. `shout` changes the text, so its input isn't const.

The `(unsigned char)` casts are needed. Functions like `isupper` and `toupper` need a value that fits in an unsigned char. A plain `char` can be negative on some computers.

## Try it

1. Click **Try in sandbox** and run the example.
2. In `count_upper`, remove the `/*` and `*/` around `*s = 'x';`.
3. Build it. You get a compile error, because the function promised not to change the text. That's the point.

> [!sith] The dark side
> Casting `const` away to make an error go away. If the text really is read-only, like text in double quotes, writing to it is undefined behaviour.

## Check yourself

> [!question]- What's the difference between const char *p and char *const p?
> With const char *p, you can't change the chars through p, but p can move. With char *const p, p can't move, but the chars can change.

> [!question]- Why cast to unsigned char before calling isupper or toupper?
> These functions need a value that fits in an unsigned char. A plain char can be negative, and passing a negative value is undefined behaviour.
