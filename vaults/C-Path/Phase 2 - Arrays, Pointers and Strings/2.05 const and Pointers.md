# 2.05 const and Pointers

> [!abstract] Why this matters
> `const` in a function's parameters is a promise you can read: "I only look at this". It documents intent, and the compiler holds you to it.

## Read it right to left

| Declaration | Means |
|---|---|
| `const char *s` | pointer to const char: you can't change the chars through s |
| `char *const s` | const pointer: s can't be re-pointed, the chars can change |
| `const char *const s` | neither |

```c
#include <ctype.h>
#include <stdio.h>

static size_t count_upper(const char *s) {   /* the const promises: only reading */
    size_t n = 0;
    for (; *s; s++)                            /* moving s itself is allowed */
        if (isupper((unsigned char)*s)) n++;
    /* *s = 'x';  would be an error: the chars are const here */
    return n;
}

static void shout(char *s) {                   /* no const: this one changes the text */
    for (; *s; s++) *s = (char)toupper((unsigned char)*s);
}

int main(void) {
    char line[] = "Never tell me the Odds";
    printf("%zu capitals\n", count_upper(line));
    shout(line);
    printf("%s\n", line);
    return 0;
}
```

The `(unsigned char)` casts matter: the `ctype.h` functions need a value that fits in an unsigned char, and plain char may be negative.

## Try it

- **Try in sandbox**. Uncomment `*s = 'x';`: a compile error, which is the point.

> [!sith] The dark side
> Casting the const away to "fix" an error. If the data really was const (a string literal), writing to it is undefined behaviour.

## Check yourself

> [!question]- What's the difference between const char *p and char *const p?
> const char *p: the chars can't be changed through p, but p can move. char *const p: p can't move, but the chars can change.

> [!question]- Why cast to unsigned char before calling isupper or toupper?
> They need a value representable as unsigned char (or EOF); a negative plain char is undefined behaviour.
