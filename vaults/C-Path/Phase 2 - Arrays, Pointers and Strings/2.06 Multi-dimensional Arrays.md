# 2.06 Multi-dimensional Arrays

> [!abstract] Why this matters
> Grids are everywhere: maps, game boards, images, matrices. In C a 2D array is really one long row laid out a line at a time, and seeing that makes indexing and performance obvious.

```c
#include <stdio.h>

#define ROWS 3
#define COLS 5

/* the column count must be known to index a 2D array */
static void draw(const char grid[][COLS], int rows) {
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < COLS; c++) putchar(grid[r][c]);
        putchar('\n');
    }
}

int main(void) {
    char map[ROWS][COLS];
    for (int r = 0; r < ROWS; r++)
        for (int c = 0; c < COLS; c++)
            map[r][c] = '.';
    map[1][2] = 'X';                     /* the base */
    map[0][4] = '*';
    draw(map, ROWS);

    /* row-major: map[r][c] sits at offset r * COLS + c */
    const char *flat = &map[0][0];
    printf("flat[1*COLS+2] = %c\n", flat[1 * COLS + 2]);
    printf("sizeof map = %zu\n", sizeof map);
    return 0;
}
```

## Row-major order

Row 0 comes first, all of it, then row 1. Looping rows on the outside and columns on the inside walks memory in order, which is fast. Swap the loops on a big grid and it gets noticeably slower.

## Try it

- **Try in sandbox**. Draw a border of `#` around the map.
- Project idea: a tiny Game of Life on a 20x40 grid.

> [!sith] The dark side
> Mixing up rows and columns (`map[c][r]`) on a grid that isn't square: you read or write outside it without any warning.

## Check yourself

> [!question]- In char g[3][5], at what offset from the start is g[2][1]?
> 2 * 5 + 1 = 11.

> [!question]- Which loop order walks a 2D array in memory order?
> Rows on the outside, columns on the inside.
