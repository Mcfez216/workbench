# 2.04 Strings

> [!abstract] Why this matters
> C has no string type: a string is an array of chars ending in a zero byte, `'\0'`. Every string function trusts that the zero is there and that the buffer is big enough. When either is false, you have a buffer overflow.

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char ship[] = "Falcon";          /* 7 bytes: F a l c o n \0 */
    printf("strlen %zu, sizeof %zu\n", strlen(ship), sizeof ship);

    char name[16];
    /* snprintf: never writes more than the size, always terminates */
    int needed = snprintf(name, sizeof name, "%s-%d", "X-wing", 42);
    if (needed >= (int)sizeof name) printf("(cut short)\n");
    printf("name: %s\n", name);

    char small[5];
    needed = snprintf(small, sizeof small, "%s", "Millennium");
    printf("small: '%s' (needed %d)\n", small, needed);   /* Mill, safely cut */

    if (strcmp(ship, "Falcon") == 0)  /* compare contents with strcmp, never == */
        printf("same contents\n");

    const char *greeting = "Hello there";   /* a literal: read-only */
    printf("%c%c\n", greeting[0], greeting[6]);
    return 0;
}
```

GCC warns about the `small` line when you build it (`-Wformat-truncation`): it can see the text won't fit. That warning is on purpose here; in real code, treat it as a bug report.

## The rules that keep you safe

- Every buffer needs room for the `'\0'`.
- Write into buffers with `snprintf(buf, sizeof buf, ...)`.
- Read lines with `fgets(buf, sizeof buf, stdin)`. Never `gets` (it was removed from C for being impossible to use safely).
- Compare with `strcmp`; `==` compares addresses.
- String literals are read-only: `char *s = "x"; s[0] = 'y';` is undefined behaviour.

## Try it

- **Try in sandbox**. Replace the first snprintf with `strcpy(name, "a much longer name than sixteen")` and run with the sanitizers: stack-buffer-overflow.
- Cheat sheet: [[Cheat Sheet - C Standard Library]].

> [!sith] The dark side
> `strcpy`, `strcat`, `sprintf` and `gets` with input you don't control. They write until the source ends, however small the destination. That's the classic stack smash: see [[6.03 Buffer Overflows and How They're Exploited]].

## Check yourself

> [!question]- How many bytes does "Han" need?
> Four: three letters and the terminating '\0'.

> [!question]- Why is strcmp(a, b) == 0 correct but a == b wrong?
> == compares the two addresses; strcmp compares the characters.

> [!question]- What does snprintf return, and how do you spot truncation?
> The number of characters it would have written; if that's >= the buffer size, the output was cut short.
