# 2.04 Strings

> [!abstract] Why this matters
> C has no string type. A string is an array of `char` with a zero byte at the end, written `'\0'`. Every string function trusts two things: that the zero is there, and that your array is big enough. If either one is false, you get a buffer overflow.

## An example

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char ship[] = "Falcon";          /* 7 bytes: F a l c o n \0 */
    printf("strlen %zu, sizeof %zu\n", strlen(ship), sizeof ship);

    char name[16];
    /* snprintf: never writes more than the size, always terminates */
    int needed = snprintf(name, sizeof name, "%s-%d", "X-wing", 42);
    if (needed >= (int)sizeof name) printf("(cut short)\n");
    printf("name: %s\n", name);

    char small[5];
    needed = snprintf(small, sizeof small, "%s", "Millennium");
    printf("small: '%s' (needed %d)\n", small, needed);   /* Mill, safely cut */

    if (strcmp(ship, "Falcon") == 0)  /* compare contents with strcmp, never == */
        printf("same contents\n");

    const char *greeting = "Hello there";   /* a literal: read-only */
    printf("%c%c\n", greeting[0], greeting[6]);
    return 0;
}
```

When you build this, GCC warns about the `small` line. It can see the text won't fit. That warning is on purpose here, to show what happens. In real code, treat it as a bug.

## The rules that keep you safe

1. Every string array needs one extra byte for the `'\0'`. "Han" needs 4 bytes.
2. To put text into an array, use `snprintf(buf, sizeof buf, ...)`. It never writes more than the array can hold. It always ends the string with `'\0'`.
3. To read a line, use `fgets(buf, sizeof buf, stdin)`. Never use `gets`. It was removed from C because it can't be used safely.
4. To compare two strings, use `strcmp`. Using `==` only compares their addresses.
5. Text in double quotes in your code, like `"Hello"`, is read-only. Don't change it.

## Try it

1. Click **Try in sandbox** and run the example. Notice that "Millennium" is cut down to "Mill", safely.
2. Replace the first `snprintf` line with `strcpy(name, "a much longer name than sixteen");`
3. Run it with the sanitizers on. AddressSanitizer reports a **stack-buffer-overflow**. `strcpy` didn't know the array was only 16 bytes.
4. The cheat sheet [[Cheat Sheet - C Standard Library]] lists the safe string functions.

> [!sith] The dark side
> Using `strcpy`, `strcat`, `sprintf` or `gets` on text you don't control. They keep writing until the text ends, however small your array is. That's how the classic stack attack works. You'll see it in [[6.03 Buffer Overflows and How They're Exploited]].

## Check yourself

> [!question]- How many bytes does "Han" need?
> It needs four bytes. Three for the letters, and one for the '\0' at the end.

> [!question]- Why is strcmp(a, b) == 0 right, but a == b wrong?
> a == b compares the two addresses, not the text. strcmp compares the characters one by one, and returns 0 when they're the same.

> [!question]- What does snprintf return, and how do you tell the text was cut short?
> It returns how many characters the full text needed. If that number is the same as the array size or bigger, the text was cut short.
