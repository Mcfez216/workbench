# 1.06 printf and scanf Properly

> [!abstract] Why this matters
> Input is where your program meets the outside world. That's where bad data comes from, and where attackers come from too. Two habits make input in C safe. Check every read, and put a size limit on every string.

## printf: use the right code for the type

```c
printf("%d %ld %zu %.2f %c %s\n", 42, 42L, sizeof(int), 3.14159, 'x', "text");
```

Each `%` code must match the type of its value. If it doesn't, printf reads the wrong bytes and prints nonsense. When the format is written in your code, `-Wall` checks this for you.

## scanf: always check what it returns

```c
#include <stdio.h>

int main(void) {
    char name[32];
    int age;

    printf("Name and age: ");
    /* %31s: at most 31 characters (plus the '\0') into a 32-byte array */
    if (scanf("%31s %d", name, &age) != 2) {
        printf("That wasn't a name and a number.\n");
        return 1;
    }
    printf("%s is %d.\n", name, age);
    return 0;
}
```

- `scanf` returns how many values it read. If that's not 2 here, something went wrong. `age` never got a value, so don't use it.
- `%31s` reads at most 31 characters. That leaves room for the `'\0'` that ends the string, in a 32-byte array.
- Numbers need `&` in front, so scanf gets their address. Arrays like `name` don't need it, because an array already gives its address.
- `%s` stops at the first space. To read a whole line, use `fgets`.

## Reading a whole line, safely

```c
char line[128];
if (fgets(line, sizeof line, stdin) != NULL) {
    line[strcspn(line, "\n")] = '\0';   /* remove the newline (string.h) */
}
```

`fgets` keeps the newline at the end of the line. The second line removes it.

> [!sith] The dark side
> Writing `scanf("%s", name)` with no size limit. If someone types more letters than the array holds, scanf writes past its end. This is a stack buffer overflow, the most famous security bug there is. You'll see why in [[6.03 Buffer Overflows and How They're Exploited]].

## Check yourself

> [!question]- What does scanf return, and why check it?
> It returns how many values it read. If that's fewer than you asked for, some variables never got a value. Using them is undefined behaviour.

> [!question]- How do you stop scanf("%s") from overflowing a char[32]?
> Add a size limit that's one less than the array: %31s. That leaves room for the '\0' at the end.

> [!question]- Why does scanf need &age but not name?
> scanf needs to know where to store each value, so it needs addresses. &age is the address of an int. name is an array, and an array already gives the address of its first element.
