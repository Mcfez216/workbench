# 1.06 printf and scanf Properly

> [!abstract] Why this matters
> Input is where your program meets the outside world, and the outside world is where bad data (and attackers) come from. Two habits make C input safe: check every read, and limit every string.

## printf: match the conversion to the type

```c
printf("%d %ld %zu %.2f %c %s\n", 42, 42L, sizeof(int), 3.14159, 'x', "text");
```

A wrong conversion doesn't fail nicely: it reads the wrong bytes. `-Wall` checks it for you when the format is a fixed string.

## scanf: check what it returns

```c
#include <stdio.h>

int main(void) {
    char name[32];
    int age;

    printf("Name and age: ");
    /* %31s: at most 31 characters (plus the '\0') into a 32-byte array */
    if (scanf("%31s %d", name, &age) != 2) {
        printf("That wasn't a name and a number.\n");
        return 1;
    }
    printf("%s is %d.\n", name, age);
    return 0;
}
```

- `scanf` returns how many items it filled. Not 2? Something was wrong, and `age` has no value.
- Numbers need `&` (the address). Arrays like `name` don't: they already are one.
- `%s` stops at the first space; `fgets` reads a whole line.

## A whole line, safely

```c
char line[128];
if (fgets(line, sizeof line, stdin) != NULL) {
    line[strcspn(line, "\n")] = '\0';   /* remove the newline (string.h) */
}
```

## Try it

- **Try in sandbox**; type the input in the terminal when it asks. Try "Han" then "Solo" instead of a number.
- Learn → **Talking to the user**: three steps, a whole program.

> [!sith] The dark side
> `scanf("%s", name)` with no width: type more letters than the array holds and you've written past its end. That's a stack buffer overflow, the most famous security bug there is ([[6.03 Buffer Overflows and How They're Exploited]]).

## Check yourself

> [!question]- What does scanf return, and why check it?
> The number of items it successfully read. If it's less than expected, some variables were never set, and using them is undefined behaviour.

> [!question]- How do you stop scanf("%s") from overflowing a char[32]?
> Give it a width one less than the size: %31s, leaving room for the '\0'.

> [!question]- Why does scanf need &age but not name?
> scanf needs addresses to store into. &age is the address of an int; name is an array, which already converts to the address of its first element.
