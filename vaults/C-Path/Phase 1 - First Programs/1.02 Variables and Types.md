# 1.02 Variables and Types

> [!abstract] Why this matters
> In C, a variable's type decides how many bytes it uses, and how those bytes are read. If you pick the wrong type, numbers can wrap around or lose their decimals. C won't warn you when this happens.

## The basic types

| Type | What it holds | Usual size | printf code |
|---|---|---|---|
| `int` | Whole numbers, up to about ±2.1 billion | 4 bytes | `%d` |
| `long long` | Bigger whole numbers | 8 bytes | `%lld` |
| `unsigned int` | Whole numbers from 0 upwards | 4 bytes | `%u` |
| `size_t` | Sizes and counts | 8 bytes | `%zu` |
| `double` | Numbers with decimals | 8 bytes | `%f` |
| `char` | One character | 1 byte | `%c` |
| `bool`, from `<stdbool.h>` | true or false | 1 byte | `%d` |

## sizeof and the limits

`sizeof` tells you how many bytes a type uses. `INT_MIN` and `INT_MAX` are the smallest and biggest `int`.

```c
#include <limits.h>
#include <stdio.h>

int main(void) {
    printf("int:       %zu bytes, %d to %d\n", sizeof(int), INT_MIN, INT_MAX);
    printf("long long: %zu bytes\n", sizeof(long long));
    printf("double:    %zu bytes\n", sizeof(double));
    printf("char:      %zu byte\n", sizeof(char));

    int count = 0;          /* always give a variable a value */
    double average = 0.0;
    char grade = 'A';
    printf("%d %.1f %c\n", count, average, grade);
    return 0;
}
```

## Always give a variable a value

A local variable that hasn't been given a value holds whatever was left in that memory. It's random, and it can change every time you run the program.

```c
int total;      /* garbage */
total += 5;     /* undefined behaviour */
```

Using a value like this is **undefined behaviour**. That means the C standard doesn't say what happens. Anything can happen, so never do it.

## Try it

1. Click **Try in sandbox** and run the example.
2. Open it in Learn → Visualise memory. Before each line runs, look at what the variables hold.
3. Change `int count = 0;` to `int count;`, then use `count`. Read what `-Wall` warns you about.

> [!sith] The dark side
> Keeping a size or count in an `int`, then comparing it with `strlen()` or `sizeof`. Those give back an unsigned number, which can't be negative. So -1 turns into a huge number, and the comparison gives the wrong answer. Use `size_t` for sizes.

## Check yourself

> [!question]- How many bytes is an int on a typical 64-bit Linux system, and what can it hold?
> It's 4 bytes. It holds whole numbers from -2147483648 to 2147483647. These are INT_MIN and INT_MAX.

> [!question]- Which printf code prints a size_t?
> %zu prints a size_t.

> [!question]- What's in a local variable you didn't give a value to?
> Whatever was left in that memory before. Reading it is undefined behaviour, so the program could do anything.
