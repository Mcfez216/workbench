# 1.05 Functions

> [!abstract] Why this matters
> A function lets you solve one small problem at a time, and give it a name. In C, functions also teach you the most important fact about the language. When you call a function, it gets copies of your values.

## Functions get copies

```c
#include <stdio.h>

static void try_to_change(int x) {
    x = 99;              /* changes the copy only */
}

static int doubled(int x) {
    return x * 2;        /* the way to get a result out */
}

int main(void) {
    int n = 5;
    try_to_change(n);
    printf("n is still %d\n", n);
    n = doubled(n);
    printf("now n is %d\n", n);
    return 0;
}
```

When you call `try_to_change(n)`, C copies the value of `n` into `x`. Changing `x` only changes the copy. So `n` is still 5 afterwards. This is called **passing by value**.

gcc even warns about `try_to_change`. It says "parameter 'x' set but not used". The warning is right, because the change goes nowhere.

The way to get a result out of a function is to `return` it, like `doubled` does.

To let a function change your variable, you give it the variable's address. You'll learn that in Phase 2, in [[2.02 Pointers]].

## Prototypes, (void) and static

- A **prototype** is a line like `int doubled(int x);`. It tells the compiler a function exists, before its code appears. Prototypes usually go in header files.
- Write `int main(void)`, with `void`, to mean "no inputs". In older C, empty brackets `()` mean "unknown inputs", which is different.
- `static` in front of a function means only this file can see it. Use it for small helper functions.

## What a good C function looks like

- It does one job, and its name says what that job is.
- It's short, about 25 lines or fewer.
- It returns its result. If it can fail, it returns a value that tells the caller.
- It doesn't print anything, unless printing is its job.

> [!sith] The dark side
> Returning the address of a local variable. A local variable disappears when its function ends. The address then points at memory that the next function call will reuse. AddressSanitizer reports this as stack-use-after-return.

## Check yourself

> [!question]- If a function changes its int input, does the caller's variable change?
> No. The function's input is a copy. To change the caller's variable, you pass a pointer to it.

> [!question]- What does static mean in front of a function?
> It means only the code in the same .c file can use that function.

> [!question]- Why write int main(void) rather than int main()?
> In older C, empty brackets mean "unknown inputs", not "no inputs". Writing void says there are no inputs, so the compiler can check every call.
