# 1.05 Functions

> [!abstract] Why this matters
> Functions let you solve one small problem at a time and name it. In C they also teach the most important fact about the language: arguments are copied.

## Pass by value

```c
#include <stdio.h>

static void try_to_change(int x) {
    x = 99;              /* changes the copy only */
}

static int doubled(int x) {
    return x * 2;        /* the way to get a result out */
}

int main(void) {
    int n = 5;
    try_to_change(n);
    printf("n is still %d\n", n);
    n = doubled(n);
    printf("now n is %d\n", n);
    return 0;
}
```

Every argument is copied into the function's parameter. gcc even warns about `try_to_change`: *parameter 'x' set but not used*. It's right: the change goes nowhere. To let a function change your variable, you give it the variable's address: that's Phase 2 ([[2.02 Pointers]]).

## Prototypes and static

- A **prototype** (`int doubled(int x);`) declares a function before its definition, usually in a header.
- `(void)` in `int main(void)` means "no parameters". In C, `int f()` means "unknown parameters" (until C23): write `(void)`.
- **static** on a function means "only this file can see it": use it for helpers.

## A good C function

- One job, a name that says it, under ~25 lines.
- Returns its result; reports failure with a return value the caller checks.
- Doesn't print unless printing is its job.

## Try it

- **Try in sandbox**, then Learn → Visualise memory: watch `x` get its own box, separate from `n`.
- Learn → **First functions**, steps 1 to 3.

> [!sith] The dark side
> Returning the address of a local variable. The local disappears when the function returns; the address now points at memory the next call will reuse. ASan: stack-use-after-return.

## Check yourself

> [!question]- If a function changes its int parameter, does the caller's variable change?
> No: the parameter is a copy. To change the caller's variable, pass a pointer to it.

> [!question]- What does static mean on a function?
> The function is only visible inside its own .c file.

> [!question]- Why write int main(void) rather than int main()?
> In C before C23, () means "unspecified parameters", not "none"; (void) says there are none, so the compiler can check calls.
