# 1.03 Operators and Expressions

> [!abstract] Why this matters
> Most operators do what you'd expect. A handful don't, and those few cause a large share of beginner bugs: integer division, `=` versus `==`, and `++` in the wrong place.

## The surprises

```c
#include <stdio.h>

int main(void) {
    int a = 7, b = 2;
    printf("7 / 2   = %d\n", a / b);            /* 3: integer division drops the .5 */
    printf("7 %% 2   = %d\n", a % b);           /* 1: the remainder */
    printf("7.0 / 2 = %.1f\n", (double)a / b);  /* 3.5: one side a double */

    int i = 5;
    int x = i++;   /* x gets 5, then i becomes 6 */
    int y = ++i;   /* i becomes 7, then y gets 7 */
    printf("x=%d y=%d i=%d\n", x, y, i);

    if (a == 7) printf("== compares\n");
    /* if (a = 0) ... assigns 0, the condition is false: -Wall warns */
    return 0;
}
```

## Precedence: when in doubt, brackets

| Higher first | Operators |
|---|---|
| | `()` `[]` `->` `.` |
| | `!` `++` `--` unary `-` `*` `&` `sizeof` |
| | `*` `/` `%` |
| | `+` `-` |
| | `<` `<=` `>` `>=` |
| | `==` `!=` |
| | `&&` |
| | `\|\|` |
| lowest | `=` `+=` ... |

`a & 1 == 0` is `a & (1 == 0)`: bitwise operators sit below comparisons. Write `(a & 1) == 0`.

> [!sith] The dark side
> `average = sum / count;` with two ints, then wondering why it's always a whole number. Make one of them a double first.

## Check yourself

> [!question]- What is 7 / 2 in C, and how do you get 3.5?
> 3, because both are ints. Make one a double: 7.0 / 2 or (double)a / b.

> [!question]- What's the difference between i++ and ++i in an expression?
> i++ gives the old value and then increments; ++i increments first and gives the new value.

> [!question]- What does if (x = 5) do?
> Assigns 5 to x, and the condition is 5 (true): it's almost always a typo for ==, and -Wall warns about it.
