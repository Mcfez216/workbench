# 1.03 Operators and Expressions

> [!abstract] Why this matters
> Most operators do what you expect. A few don't, and they cause a lot of beginner bugs. This note covers those few: dividing whole numbers, `=` and `==`, and `++`.

## The surprises

```c
#include <stdio.h>

int main(void) {
    int a = 7, b = 2;
    printf("7 / 2   = %d\n", a / b);            /* 3: integer division drops the .5 */
    printf("7 %% 2   = %d\n", a % b);           /* 1: the remainder */
    printf("7.0 / 2 = %.1f\n", (double)a / b);  /* 3.5: one side a double */

    int i = 5;
    int x = i++;   /* x gets 5, then i becomes 6 */
    int y = ++i;   /* i becomes 7, then y gets 7 */
    printf("x=%d y=%d i=%d\n", x, y, i);

    if (a == 7) printf("== compares\n");
    /* if (a = 0) ... assigns 0, the condition is false: -Wall warns */
    return 0;
}
```

What the example shows:

- **Dividing two whole numbers drops the decimals.** 7 / 2 gives 3, not 3.5.
- `%` gives the **remainder**. 7 % 2 is 1.
- To get 3.5, make one side a `double` first.
- `i++` gives you the old value, *then* adds 1.
- `++i` adds 1 first, *then* gives you the new value.
- `==` compares two values. A single `=` changes a variable.

## Order of operations

Some operators happen before others. This is called **precedence**. The higher a row is, the sooner it happens.

| Order | Operators |
|---|---|
| First | `()` `[]` `->` `.` |
| | `!` `++` `--` minus sign `*` `&` `sizeof` |
| | `*` `/` `%` |
| | `+` `-` |
| | `<` `<=` `>` `>=` |
| | `==` `!=` |
| | `&&` |
| | `\|\|` |
| Last | `=` `+=` and the others like it |

If you're not sure, add brackets. For example, `a & 1 == 0` does the `==` first, which is not what you meant. Write `(a & 1) == 0` instead.

## Check yourself

> [!question]- What is 7 / 2 in C, and how do you get 3.5?
> It's 3, because both numbers are ints. To get 3.5, make one of them a double. For example, write 7.0 / 2, or (double)a / b.

> [!question]- What's the difference between i++ and ++i?
> i++ gives you the old value, then adds 1. ++i adds 1 first, then gives you the new value.

> [!question]- What does if (x = 5) do?
> It sets x to 5. The condition is then 5, which counts as true. This is almost always a typo for ==. The -Wall option warns about it.
