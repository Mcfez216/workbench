# 1.01 Why C and How It Compiles

> [!abstract] Why this matters
> C is small enough to learn completely and close enough to the machine that you see what really happens. Knowing how a .c file becomes a program turns the most confusing errors into obvious ones.

## Why C

- **It runs everything underneath**: Linux, Windows' kernel, your router, your car's microcontrollers, Python's interpreter.
- **Security starts here**: buffer overflows, use-after-free and format-string bugs are C bugs. You can't defend what you can't read.
- **It's small**: about 30 keywords and a short standard library. The hard part isn't the language; it's memory.

## From text to program

```
hello.c ──preprocessor──► (expanded text) ──compiler──► hello.o ──linker──► hello
```

1. **Preprocessor**: `#include <stdio.h>` pastes the header's declarations in; `#define` names are replaced.
2. **Compiler**: checks your code and turns it into machine code: an object file.
3. **Linker**: joins your object file with the C library (where `printf` actually lives) into a program.

```c
#include <stdio.h>

int square(int x);   /* declaration: "this exists" */

int main(void) {
    printf("%d\n", square(7));
    return 0;        /* 0 tells the shell "it worked" */
}

int square(int x) {  /* definition: the actual code */
    return x * x;
}
```

## Try it

1. **Try in sandbox** (switch on C), Ctrl+F9.
2. Delete the definition of `square` and run again: `undefined reference to 'square'`. That's the **linker**: the compiler was satisfied by the declaration, but nothing defines it.
3. Now delete the declaration line instead (keep the definition at the bottom): a compiler error or warning about an implicit declaration. In C, you declare before you use.
4. Learn → **First functions**.

> [!sith] The dark side
> Ignoring "implicit declaration of function" warnings. Older C let you call undeclared functions and guessed their type (wrongly, often). Modern C forbids it; treat the warning as an error.

## Check yourself

> [!question]- Where does printf's code actually come from?
> The C library (libc). stdio.h only declares printf; the linker connects your call to the definition in libc.

> [!question]- What does return 0 at the end of main mean?
> The program's exit status: 0 means success to the shell or whatever ran it; anything else means failure.

> [!question]- Why must a function be declared before it's called in C?
> The compiler reads top to bottom and needs to know the function's parameter and return types to check and compile the call.
