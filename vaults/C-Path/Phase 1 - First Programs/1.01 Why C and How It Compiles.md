# 1.01 Why C and How It Compiles

> [!abstract] Why this matters
> C is small enough to learn all of it. It's also close to the hardware, so you can see what really happens inside the computer. Once you know how a .c file becomes a program, the most confusing errors start to make sense.

## Why learn C

- **It runs underneath almost everything.** Linux, the core of Windows, your router and Python itself are all written in C.
- **Security starts here.** Many famous security bugs are C bugs. You can't defend against a bug you can't read.
- **The language is small.** It has about 30 keywords. The hard part isn't the words. It's managing memory.

## From text to program

```
hello.c ──preprocessor──► (expanded text) ──compiler──► hello.o ──linker──► hello
```

Three programs run, one after the other:

1. The **preprocessor** handles lines that start with `#`. For example, `#include <stdio.h>` pastes in the declarations from that file.
2. The **compiler** checks your code. Then it turns it into machine code, and saves it in an **object file** (`hello.o`).
3. The **linker** joins your object file with the C library into one program. The C library is where `printf`'s code really lives.

## An example

A **declaration** tells the compiler a function exists. A **definition** is the function's actual code.

```c
#include <stdio.h>

int square(int x);   /* declaration: "this exists" */

int main(void) {
    printf("%d\n", square(7));
    return 0;        /* 0 tells the shell "it worked" */
}

int square(int x) {  /* definition: the actual code */
    return x * x;
}
```

## Try it

1. Click **Try in sandbox**, with the switch on C. Press Ctrl+F9. It prints 49.
2. Delete the definition of `square` at the bottom. Run it again.
3. You'll see `undefined reference to 'square'`. This error comes from the **linker**. The compiler was happy because of the declaration, but no code for `square` exists anywhere.
4. Put the definition back. Now delete the declaration line near the top instead.
5. Run it. Now the **compiler** complains, because you used `square` before saying it exists. In C, you must declare a function before you use it.
6. Open Learn → **First functions** for some practice.

> [!sith] The dark side
> Ignoring the warning "implicit declaration of function". Old C let you call a function it hadn't seen yet. It guessed the function's types, and often guessed wrong. Modern C doesn't allow this. Treat this warning as an error.

## Check yourself

> [!question]- Where does printf's code actually come from?
> It comes from the C library, called libc. The file stdio.h only declares printf. The linker connects your call to the real code in libc.

> [!question]- What does return 0 at the end of main mean?
> It's the program's exit status. 0 tells whatever started the program that it worked. Any other number means something failed.

> [!question]- Why must a function be declared before it's called in C?
> The compiler reads your file from top to bottom. To check a call, it needs to know the function's input and output types already.
