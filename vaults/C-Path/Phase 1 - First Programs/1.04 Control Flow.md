# 1.04 Control Flow

> [!abstract] Why this matters
> Decisions and loops let a program do more than one fixed thing. C's versions are simple. The bugs happen at the edges: a loop that runs one time too many, a missing `break`, or a loop that never ends.

## Decisions and loops

**Control flow** means the order your program's lines run in. These are the tools that change it.

```c
#include <stdio.h>

int main(void) {
    int fuel = 35;

    if (fuel > 50) {
        printf("Ready for the Kessel Run.\n");
    } else if (fuel > 20) {
        printf("Enough for a short hop.\n");
    } else {
        printf("Refuel first.\n");
    }

    char cmd = 'j';
    switch (cmd) {
    case 'j':
        printf("Jumping to hyperspace.\n");
        break;          /* without break, it falls into the next case */
    case 'l':
        printf("Landing.\n");
        break;
    default:
        printf("Unknown command.\n");
        break;
    }

    /* loops: count up, count down, until something happens */
    for (int i = 0; i < 3; ++i) printf("for %d\n", i);

    int countdown = 3;
    while (countdown > 0) {
        printf("%d...\n", countdown);
        --countdown;
    }

    int tries = 0;
    do {
        ++tries;         /* a do-while always runs at least once */
    } while (tries < 2);
    printf("tries = %d\n", tries);
    return 0;
}
```

- `if`, `else if` and `else` choose one path.
- `switch` picks a `case` that matches a value. Each case needs a `break` at the end.
- `for` repeats a set number of times.
- `while` repeats as long as its condition is true.
- `do ... while` is the same, but it always runs at least once.

## Good loop habits

- Count from 0 and stop with `<`. So `for (i = 0; i < n; ++i)` runs exactly n times.
- `break` leaves the loop straight away. `continue` skips to the next round.
- Every `while` loop needs something inside it that will make its condition false one day. Otherwise it never ends.

## Try it

1. Click **Try in sandbox** and run the example.
2. Delete the first `break`, in the `case 'j':` part. Run it again.
3. It now prints "Jumping" and "Landing". Without the `break`, the code carried on into the next case. This is called **falling through**.
4. For practice, open Learn → **Loops**, and do `sum_to` and `is_prime`.

> [!sith] The dark side
> Writing `for (i = 0; i <= n; ++i)` for an array with n elements. The `<=` makes it run one time too many. The last round reads past the end of the array, and AddressSanitizer reports a buffer overflow.

## Check yourself

> [!question]- What happens if a switch case has no break?
> The program carries on into the next case's code. This is called falling through, and it's usually a bug. When you mean it, newer C lets you write `[[fallthrough]]` to say so.

> [!question]- How many times does for (i = 0; i < n; ++i) run?
> It runs exactly n times. i goes from 0 up to n - 1.

> [!question]- What's special about a do-while loop?
> It always runs at least once, because it checks its condition at the end, not the start.
