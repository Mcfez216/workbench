# 1.04 Control Flow

> [!abstract] Why this matters
> Decisions and loops are how a program does anything more than one thing. C's versions are simple; the bugs are at the edges: the off-by-one, the missing `break`, the loop that never ends.

## Decisions

```c
#include <stdio.h>

int main(void) {
    int fuel = 35;

    if (fuel > 50) {
        printf("Ready for the Kessel Run.\n");
    } else if (fuel > 20) {
        printf("Enough for a short hop.\n");
    } else {
        printf("Refuel first.\n");
    }

    char cmd = 'j';
    switch (cmd) {
    case 'j':
        printf("Jumping to hyperspace.\n");
        break;          /* without break, it falls into the next case */
    case 'l':
        printf("Landing.\n");
        break;
    default:
        printf("Unknown command.\n");
        break;
    }

    /* loops: count up, count down, until something happens */
    for (int i = 0; i < 3; ++i) printf("for %d\n", i);

    int countdown = 3;
    while (countdown > 0) {
        printf("%d...\n", countdown);
        --countdown;
    }

    int tries = 0;
    do {
        ++tries;         /* a do-while always runs at least once */
    } while (tries < 2);
    printf("tries = %d\n", tries);
    return 0;
}
```

## Loop habits

- Count from 0 and stop with `<`: `for (i = 0; i < n; ++i)` runs exactly n times.
- `break` leaves the loop; `continue` skips to the next round.
- Every `while` needs something inside that eventually makes the condition false.

## Try it

- **Try in sandbox**, then delete the first `break` and run: watch it fall through.
- Learn → **Loops**: `sum_to` and `is_prime`.

> [!sith] The dark side
> `for (i = 0; i <= n; ++i)` over an array of n elements: one too many. The last round reads past the end, and ASan calls it a buffer overflow.

## Check yourself

> [!question]- What happens if a switch case has no break?
> Execution falls through into the next case's code, which is usually a bug (C23 has `[[fallthrough]]` for when it's on purpose).

> [!question]- How many times does for (i = 0; i < n; ++i) run?
> Exactly n times, with i from 0 to n - 1.

> [!question]- What's special about a do-while loop?
> Its body always runs at least once, because the condition is checked at the end.
