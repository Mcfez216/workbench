# How the notes are written

Plain, calm English. Easy to read when you're tired, distracted or new to this.

## The rules

1. **Short sentences.** One idea in each one. If a sentence has a colon or a
   semicolon joining two ideas, make it two sentences.
2. **No brackets full of extra ideas.** If it matters, give it its own sentence.
   If it doesn't, leave it out.
3. **Explain every technical word the first time it appears in a note.** Say
   what it means in everyday words, then use it. For example: "Dereference
   means *go to that address and use what's there*."
4. **Say "you".** Talk to the reader as a person.
5. **Steps get numbers.** Anything you do in order is a numbered list, one
   action per step, and it says what you should see.
6. **No idioms or clever phrases.** Say the plain thing. Not "makes it click",
   but "makes it easier to understand".
7. **Answers are full sentences.** A "check yourself" answer should make sense
   on its own, read days later on a flashcard.
8. **One example before the rule.** Show it working, then name it.
9. **Keep the code comments short and plain too.**

## The shape of a note

- **Why this matters**: two or three short sentences.
- **The idea**: small sections, each with a heading that says what it's about.
- **An example you can run.**
- **Try it**: numbered steps.
- **The dark side**: one common mistake, what goes wrong, and how to avoid it.
- **Check yourself**: questions with full-sentence answers.
- **Next**: a link to the next note.
