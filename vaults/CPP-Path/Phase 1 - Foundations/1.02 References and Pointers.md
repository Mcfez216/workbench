# 1.02 References and Pointers

> [!abstract] Why this matters
> Functions get copies of their arguments. References and pointers let a function work on the caller's own object instead, and they're how C++ avoids copying big things. Most of the bugs in this whole path are about one of them outliving what it refers to.

## A reference is another name

```cpp
int n = 41;
int& r = n;   // r IS n, under another name
r += 1;       // n is 42 now
```

A reference must be set when it's made, can't be null, and can't be pointed at something else later.

## A pointer is an address

```cpp
int n = 41;
int* p = &n;   // p holds n's address
*p += 1;       // follow the address: n is 42
p = nullptr;   // a pointer can point at nothing
```

## Side by side

```cpp
#include <iostream>

void bumpRef(int& x) { ++x; }        // can't be null, can't be reseated
void bumpPtr(int* x) { if (x) ++*x; } // can be null: check it

int main() {
    int n = 40;
    bumpRef(n);
    bumpPtr(&n);
    bumpPtr(nullptr);   // allowed: the function checks
    std::cout << "n = " << n << '\n';
    return 0;
}
```

## Which one?

| Situation | Use |
|---|---|
| Read a big object | `const T&` |
| Change the caller's object | `T&` |
| "Maybe nothing" is a real answer | `T*` (or `std::optional`) |
| Ownership | neither: see [[2.04 Smart Pointers]] |

> [!sith] The dark side
> Returning a reference or pointer to a local variable. The local dies when the function returns; the reference points at whatever uses that memory next. ASan reports it as stack-use-after-return.

## Check yourself

> [!question]- Name two things a pointer can do that a reference can't.
> Be null (nullptr), and be changed to point at a different object.

> [!question]- Why pass a std::string as const std::string& instead of by value?
> By value copies the whole string (maybe allocating memory). A const reference refers to the caller's string with no copy, and const promises not to change it.

> [!question]- What's wrong with `int& f() { int x = 1; return x; }`?
> It returns a reference to a local variable that's destroyed when f returns: the caller gets a dangling reference.
