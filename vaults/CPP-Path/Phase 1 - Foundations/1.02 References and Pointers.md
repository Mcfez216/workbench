# 1.02 References and Pointers

> [!abstract] Why this matters
> When you call a function, it gets copies of your values. References and pointers let a function work on your own object instead. They also let C++ avoid copying big things. Many bugs in this path come from a reference or pointer that lasts longer than the thing it points to.

## A reference is another name

```cpp
int n = 41;
int& r = n;   // r IS n, under another name
r += 1;       // n is 42 now
```

A **reference** is a second name for an existing variable. Here, `r` and `n` are the same variable.

- You must give a reference its variable when you make it.
- It can't be empty.
- It can't be changed to name a different variable later.

## A pointer is an address

```cpp
int n = 41;
int* p = &n;   // p holds n's address
*p += 1;       // follow the address: n is 42
p = nullptr;   // a pointer can point at nothing
```

A **pointer** holds the address of a variable, meaning where it is in memory.

- `&n` gives the address of `n`.
- `*p` goes to that address and uses the value there.
- A pointer can also be `nullptr`, which means it points to nothing.

## Side by side

```cpp
#include <iostream>

void bumpRef(int& x) { ++x; }        // can't be null, can't be reseated
void bumpPtr(int* x) { if (x) ++*x; } // can be null: check it

int main() {
    int n = 40;
    bumpRef(n);
    bumpPtr(&n);
    bumpPtr(nullptr);   // allowed: the function checks
    std::cout << "n = " << n << '\n';
    return 0;
}
```

`bumpPtr` checks for `nullptr` before using the pointer. `bumpRef` doesn't need to, because a reference can never be empty.

## Which one to use

| Situation | Use |
|---|---|
| Read a big object without copying it | `const T&` |
| Change the caller's object | `T&` |
| "Nothing" is a real possible answer | `T*`, or `std::optional` |
| Owning memory | Neither. See [[2.04 Smart Pointers]]. |

> [!sith] The dark side
> Returning a reference or pointer to a local variable. The local variable is destroyed when the function ends. The reference then points at memory that will be used for something else. AddressSanitizer reports this as stack-use-after-return.

## Check yourself

> [!question]- Name two things a pointer can do that a reference can't.
> A pointer can be empty, written nullptr. A pointer can also be changed to point at a different object.

> [!question]- Why pass a std::string as const std::string& instead of by value?
> Passing by value copies the whole string, which can take time and memory. A const reference uses the caller's string with no copy. The const promises the function won't change it.

> [!question]- What's wrong with `int& f() { int x = 1; return x; }`?
> It returns a reference to a local variable. That variable is destroyed when f ends, so the caller gets a reference to something that no longer exists.
