# 1.01 Why CPP and the Compile-Link Model

> [!abstract] Why this matters
> C++ gives you control over exactly what the machine does, with abstractions that cost nothing when you don't use them. The price is that you need to know how your text becomes a program. Once you do, half of all confusing errors stop being confusing.

## Why C++

- **Speed and control**: no garbage collector, no virtual machine. You decide where data lives and when it goes away.
- **Everywhere**: from microcontrollers to game engines, browsers, databases, compilers, trading systems.
- **Security matters here**: because C++ trusts you, its bugs are exploitable. Knowing both sides is a career.

## Three stages

```
hello.cpp ──preprocessor──► (one big file) ──compiler──► hello.o ──linker──► hello
```

1. **Preprocessor**: follows `#include` by pasting the header's text in, expands macros.
2. **Compiler**: turns that one translation unit into machine code, an **object file** (`.o`). It checks types and syntax. It only needs **declarations** of the things you call.
3. **Linker**: joins all the object files and libraries, matching each call to a **definition**. If a definition is missing: `undefined reference to ...`.

```cpp
#include <iostream>   // the declaration of std::cout comes from here

int square(int x);    // a declaration: "this exists somewhere"

int main() {
    std::cout << square(7) << '\n';
    return 0;
}

int square(int x) {   // the definition: the actual code
    return x * x;
}
```

## Try it

1. **Try in sandbox** on the code above; Ctrl+F9 runs it.
2. Delete the definition of `square` at the bottom and run again. The error is from the **linker**, not the compiler: it compiled fine, but nothing defines `square`. Press **?** next to it in Problems.
3. Learn → **First functions**: your first exercise.

> [!holocron] Errors have an author
> "expected ;" and "was not declared" come from the compiler: your file. "undefined reference" comes from the linker: something missing from the build. Reading which one it is tells you where to look.

> [!sith] The dark side
> Fixing an "undefined reference" by adding another `#include`. Headers only declare. The fix is a definition: the right .cpp file in the build, or the right library linked.

## Check yourself

> [!question]- What are the three stages from source file to program?
> Preprocessing (includes and macros pasted in), compiling (one .cpp at a time into an object file) and linking (object files and libraries joined, calls matched to definitions).

> [!question]- What's the difference between a declaration and a definition?
> A declaration says something exists and what its type is (`int square(int);`). A definition provides it: the function body, or the storage for a variable. You can declare many times, but define once.

> [!question]- Is "undefined reference to `square(int)`" a compiler or a linker error, and what does it mean?
> A linker error: `square` was declared (so the compiler was happy) but no object file or library given to the linker defines it.
