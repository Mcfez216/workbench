# 1.01 Why CPP and the Compile-Link Model

> [!abstract] Why this matters
> C++ lets you control exactly what the computer does. Its helpful features cost nothing if you don't use them. The price is that you need to know how your code becomes a program. Once you do, many confusing errors start to make sense.

## Why learn C++

- **Speed and control.** Nothing runs in the background to clean up memory. You decide where data is kept, and when it goes away.
- **It's everywhere.** Game engines, web browsers, databases and small devices all use it.
- **Security matters here.** C++ trusts you completely, so its bugs can be used by attackers. People who understand both sides are in demand.

## Three stages

```
hello.cpp ──preprocessor──► (one big file) ──compiler──► hello.o ──linker──► hello
```

1. The **preprocessor** handles lines that start with `#`. For `#include`, it pastes in the text of that header file.
2. The **compiler** checks your code and turns it into machine code. It saves this in an **object file** (`.o`). It only needs to know that the functions you call *exist*. This is called a **declaration**.
3. The **linker** joins all the object files and libraries together. It matches each function call with that function's actual code, called its **definition**. If a definition is missing, you get `undefined reference to ...`.

## An example

```cpp
#include <iostream>   // the declaration of std::cout comes from here

int square(int x);    // a declaration: "this exists somewhere"

int main() {
    std::cout << square(7) << '\n';
    return 0;
}

int square(int x) {   // the definition: the actual code
    return x * x;
}
```

## Try it

1. Click **Try in sandbox**, then press Ctrl+F9. It prints 49.
2. Delete the definition of `square` at the bottom. Run it again.
3. You get an error from the **linker**, not the compiler. The code compiled fine, but no code for `square` exists. Click **?** next to the error in Problems to read about it.
4. For practice, open Learn → **First functions**.

> [!holocron] Which tool wrote the error?
> Errors like "expected ;" and "was not declared" come from the compiler. They mean something is wrong in your file. "undefined reference" comes from the linker. It means something is missing from the build. Knowing which one it is tells you where to look.

> [!sith] The dark side
> Trying to fix "undefined reference" by adding another `#include`. A header only says that something exists. The fix is to add the missing code: the right .cpp file in the build, or the right library.

## Check yourself

> [!question]- What are the three stages from source file to program?
> First, preprocessing pastes in the header files. Second, compiling turns each .cpp file into an object file. Third, linking joins the object files and libraries, and matches every call to its code.

> [!question]- What's the difference between a declaration and a definition?
> A declaration says that something exists, and what its type is. For example, `int square(int);`. A definition gives the actual code, or the storage for a variable. You can declare something many times, but define it only once.

> [!question]- Is "undefined reference to `square(int)`" a compiler error or a linker error?
> It's a linker error. square was declared, so the compiler was happy. But nothing given to the linker contains square's code.
