# 1.07 Headers, Namespaces and the ODR

> [!abstract] Why this matters
> Real programs are many files. Headers let files share declarations; namespaces stop names colliding; and one rule, the ODR, explains most "multiple definition" errors you'll ever see.

## Splitting a program

```cpp
// temperature.hpp: what it is (declarations)
#pragma once

namespace weather {
double to_celsius(double kelvin);
}
```

```cpp
// temperature.cpp: how it works (definitions)
#include "temperature.hpp"

namespace weather {
double to_celsius(double kelvin) { return kelvin - 273.15; }
}
```

```cpp
// main.cpp: uses it
#include <iostream>
#include "temperature.hpp"

int main() {
    std::cout << weather::to_celsius(300.0) << '\n';
    return 0;
}
```

Both .cpp files are compiled separately; the linker joins them ([[1.01 Why CPP and the Compile-Link Model]]). In CMake, both go in `add_executable(app main.cpp temperature.cpp)`.

## #pragma once

Stops a header's contents being pasted twice into the same file (directly or through other headers). Every header gets one.

## Namespaces

Group names so `weather::to_celsius` and `physics::to_celsius` can both exist. `std::` is the standard library's.

## The One Definition Rule (ODR)

Each function and global variable is **defined exactly once** in the whole program. Put a function body in a header that two .cpp files include, and the linker sees two: `multiple definition of`. Fixes: keep the body in one .cpp, or mark it `inline` (allowed in headers), or put it in a class body (implicitly inline).

## Try it

- In the workbench: File → New file → Class (.hpp + .cpp). Alt+F12 jumps between the two halves.
- Learn → **Structs** (C) shows the same split.

> [!sith] The dark side
> `using namespace std;` in a header: every file that includes it gets the whole std namespace dumped in, and names start colliding far from the cause. In a .cpp file it's tolerable; in a header, never.

## Check yourself

> [!question]- What goes in a header, and what goes in the .cpp file?
> The header has declarations (function prototypes, class definitions, inline functions, templates); the .cpp has the definitions (function bodies, global variables).

> [!question]- What is the One Definition Rule?
> Every non-inline function and global variable must be defined exactly once in the whole program; defining it twice is a "multiple definition" link error.

> [!question]- Why never put using namespace std; in a header?
> It leaks into every file that includes the header, causing name clashes in code that never asked for it.
