# 1.07 Headers, Namespaces and the ODR

> [!abstract] Why this matters
> Real programs are made of many files. Header files let those files share declarations. Namespaces stop names clashing. And one rule, called the ODR, explains most "multiple definition" errors you'll ever see.

## Splitting a program into files

The **header** file says *what* exists:

```cpp
// temperature.hpp: what it is (declarations)
#pragma once

namespace weather {
double to_celsius(double kelvin);
}
```

The **source** file says *how* it works:

```cpp
// temperature.cpp: how it works (definitions)
#include "temperature.hpp"

namespace weather {
double to_celsius(double kelvin) { return kelvin - 273.15; }
}
```

And `main.cpp` uses it:

```cpp
// main.cpp: uses it
#include <iostream>
#include "temperature.hpp"

int main() {
    std::cout << weather::to_celsius(300.0) << '\n';
    return 0;
}
```

Each .cpp file is compiled on its own. Then the linker joins them, as in [[1.01 Why CPP and the Compile-Link Model]]. In CMake, you list both files: `add_executable(app main.cpp temperature.cpp)`.

## #pragma once

Put `#pragma once` at the top of every header. It stops the header being pasted in twice, which can happen when headers include other headers.

## Namespaces

A **namespace** groups names together. So `weather::to_celsius` and `physics::to_celsius` can both exist without clashing. The standard library's namespace is `std::`.

## The One Definition Rule

The **One Definition Rule**, or ODR, says each function and global variable must be **defined exactly once** in the whole program.

If you put a function's body in a header, and two .cpp files include it, the linker sees two copies. You get `multiple definition of`. To fix it, do one of these:

- Keep the body in one .cpp file.
- Or mark the function `inline`, which is allowed in headers.
- Or write the function inside a class, which counts as inline too.

## Try it

1. Choose File → New file → Class. The workbench makes a .hpp and a .cpp file for you.
2. Press Alt+F12 to jump between the two halves.
3. For practice, open Learn → **Structs**. It's a C exercise that uses the same split.

> [!sith] The dark side
> Writing `using namespace std;` in a header. Every file that includes that header gets all of std's names, and clashes appear far away from the cause. It's sometimes OK in a .cpp file. In a header, never.

## Check yourself

> [!question]- What goes in a header, and what goes in the .cpp file?
> The header has the declarations: function prototypes, class definitions, inline functions and templates. The .cpp file has the definitions: function bodies and global variables.

> [!question]- What is the One Definition Rule?
> Every normal function and global variable must be defined exactly once in the whole program. Defining one twice gives a "multiple definition" error from the linker.

> [!question]- Why never put using namespace std; in a header?
> It spreads into every file that includes the header. That causes name clashes in code that never asked for it.
