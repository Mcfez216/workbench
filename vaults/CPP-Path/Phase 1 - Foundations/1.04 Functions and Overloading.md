# 1.04 Functions and Overloading

> [!abstract] Why this matters
> Functions let you break a problem into pieces small enough to get right. In C++, several functions can share a name, as long as their inputs are different. This reads well, but you need to know which one gets picked.

## A good function

- It does **one** thing, and its name says what.
- It gets what it needs as inputs, and returns its result.
- It's short enough to see all at once, often under 20 lines.

## Same name, different inputs

Several functions with the same name are called **overloads**.

```cpp
#include <iostream>
#include <string>

// overloads: same name, different parameters
void show(int x) { std::cout << "int " << x << '\n'; }
void show(double x) { std::cout << "double " << x << '\n'; }
void show(const std::string& s) { std::cout << "string " << s << '\n'; }

// a default argument
std::string greet(const std::string& name, const std::string& greeting = "Hello") {
    return greeting + ", " + name + "!";
}

int main() {
    show(3);                     // int
    show(3.0);                   // double
    show(std::string("three"));  // string
    std::cout << greet("Luke") << '\n';
    std::cout << greet("Leia", "Help me") << '\n';
    return 0;
}
```

`greet` also shows a **default value**. If you don't give a greeting, it uses "Hello".

## How the compiler picks

The compiler looks at the types of the values you pass in. It picks the best match. An exact match beats one that needs a conversion.

If two overloads match equally well, you get an **ambiguous call** error. For example, `show(3.0f)` passes a float, which turns into a double easily. `show('a')` would pick the `int` version.

## Try it

1. Click **Try in sandbox** and run it.
2. Add the line `show(3L);`. `3L` is a `long`.
3. Build it. Is it ambiguous? Think about why. A long can turn into an int or a double, and neither is a better match.
4. For practice writing small functions, open Learn → **Loops**.

> [!sith] The dark side
> Giving back results through lots of reference inputs, like `void compute(int in, int& out1, int& out2)`. Return a value instead, or a small struct. It's clearer, and just as fast.

## Check yourself

> [!question]- When is a call to an overloaded function ambiguous?
> When two or more versions match equally well, so the compiler can't choose between them.

> [!question]- What's better than several "output" reference inputs?
> Return a value. For several results, return a small struct with named members.
