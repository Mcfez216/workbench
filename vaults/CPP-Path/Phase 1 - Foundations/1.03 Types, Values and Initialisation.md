# 1.03 Types, Values and Initialisation

> [!abstract] Why this matters
> Every value has a type. The type decides how big it is, and what it can hold. Giving a variable its first value safely is harder than it looks in C++. A variable with no value is one of the most common bugs there is.

## The types you'll use most

| Type | What it holds | Usual size |
|---|---|---|
| `int` | Whole numbers, up to about ±2.1 billion | 32 bits |
| `long long` or `std::int64_t` | Bigger whole numbers | 64 bits |
| `std::size_t` | Sizes and positions. Never negative. | 64 bits |
| `double` | Numbers with decimals, about 15 digits | 64 bits |
| `bool` | true or false | 1 byte |
| `char` | One character | 1 byte |
| `std::string` | Text | Grows as needed |

## Give values with braces

Giving a variable its first value is called **initialising** it.

```cpp
#include <iostream>

int main() {
    int a{5};          // braces: the modern default
    double b{2.5};
    int c{};           // {} means zero
    // int d{2.5};     // error: braces refuse to lose the .5 ("narrowing")
    int e = 2.5;       // compiles, quietly becomes 2
    auto f = 10LL;     // auto: the type of the value (long long here)
    std::cout << a << ' ' << b << ' ' << c << ' ' << e << ' ' << f << '\n';
    return 0;
}
```

- Curly braces, like `int a{5}`, are the modern way.
- `int c{}` means zero.
- Braces refuse to lose information. `int d{2.5}` is an error, because an int can't hold the .5. This loss is called **narrowing**.
- `int e = 2.5` compiles, but `e` quietly becomes 2.
- `auto` lets the compiler work out the type from the value.

## No value means a random value

```cpp
int count;        // no value: whatever bytes were there
count = count + 1; // undefined: anything can happen
```

A variable with no starting value holds whatever was left in that memory. Using it is **undefined behaviour**, which means anything can happen.

Always give a variable a value when you make it. `-Wall` warns about many of these mistakes. Valgrind catches the rest.

## Try it

1. Click **Try in sandbox** and run the first example.
2. Remove the `//` in front of `int d{2.5};`. Build it again, and read the error.
3. Open any example in Learn → Visualise memory. Before a line runs, its variable shows a leftover value.

> [!sith] The dark side
> Mixing numbers that can be negative with ones that can't. `-1 < v.size()` is **false**. That's because `v.size()` can't be negative, so -1 is turned into a huge number first. Keep positions as `std::size_t`, or check for a negative number before you convert it.

## Check yourself

> [!question]- Why is it better that int x{2.5} fails to compile, while int x = 2.5 compiles?
> Braces refuse to lose the .5, so you find the problem while compiling. With =, the .5 is silently dropped, and that becomes a hidden bug.

> [!question]- What value does a local int have if you don't give it one?
> No value you can rely on. It holds whatever was in that memory before. Reading it is undefined behaviour.

> [!question]- Why is -1 < v.size() false?
> v.size() is a size_t, which can't be negative. So C++ turns -1 into a size_t first, and it becomes the biggest possible size_t.
