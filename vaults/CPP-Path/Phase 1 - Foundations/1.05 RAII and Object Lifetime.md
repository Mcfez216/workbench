# 1.05 RAII and Object Lifetime

> [!abstract] Why this matters
> This is the most important idea in C++. A **resource** is something you must give back, like memory, an open file, or a lock. If an object looks after each resource, C++ gives it back for you automatically. It does this every time, even when something goes wrong. That's why good C++ rarely leaks.

## Constructors and destructors

- An object's **constructor** runs when the object is made.
- Its **destructor** runs when the object goes away. A destructor is written `~Name()`.

For a local variable, the destructor runs when its block ends. That happens at the closing `}`, at a `return`, or when an error is thrown past it.

## RAII

RAII stands for "Resource Acquisition Is Initialisation". It's a long name for a simple idea:

1. Get the resource in the constructor.
2. Give it back in the destructor.

```cpp
#include <chrono>
#include <iostream>
#include <string>

class ScopeTimer {
public:
    explicit ScopeTimer(std::string label)
        : label_(std::move(label)), start_(std::chrono::steady_clock::now()) {}

    ~ScopeTimer() {   // runs however the scope ends
        auto us = std::chrono::duration_cast<std::chrono::microseconds>(
            std::chrono::steady_clock::now() - start_);
        std::cout << label_ << ": " << us.count() << " us\n";
    }

private:
    std::string label_;
    std::chrono::steady_clock::time_point start_;
};

int work(int n) {
    ScopeTimer t("work");
    if (n < 0) return -1;      // early return: the timer still reports
    long sum = 0;
    for (int i = 0; i < n; ++i) sum += i;
    return static_cast<int>(sum % 1000);
}

int main() {
    work(1000000);
    work(-1);
    return 0;
}
```

`ScopeTimer` starts timing when it's made. Its destructor prints the time. In `work`, the timer reports even when the function returns early.

## The order things are destroyed in

Objects in a block are destroyed in the **reverse** order they were made. Think of a stack of plates: the last one on is the first one off.

## You already use RAII

`std::string`, `std::vector`, `std::ifstream`, `std::unique_ptr` and `std::lock_guard` all give back what they hold in their destructor. That's why good C++ never calls `close()` or `delete` by hand.

## Try it

1. Click **Try in sandbox** and run it. Both calls print a time, even the one that returns early.
2. Add a second `ScopeTimer` inside `work`, with a different label.
3. Run it, and look at the order the two timers report in.

> [!holocron] The pattern behind it all
> Whenever you catch yourself thinking "I must remember to give back X", write a small class whose destructor gives back X instead.

> [!sith] The dark side
> Using `new` and then forgetting the `delete` on one path. An early return, or an error in between, and the memory leaks. With RAII, there's nothing to remember.

## Check yourself

> [!question]- What does RAII stand for, and what does it promise?
> Resource Acquisition Is Initialisation. An object gets a resource in its constructor and gives it back in its destructor. So the resource is always given back, however the block ends, including early returns and errors.

> [!question]- In what order are local objects destroyed?
> In the reverse order they were made.
