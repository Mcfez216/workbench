# 1.06 Classes and Invariants

> [!abstract] Why this matters
> A class isn't just a box of data: it's a promise that its data always makes sense. Keep the promise in one place (the class) and the rest of the program can stop checking.

## An invariant

A rule that's true for every valid object. A temperature is never below absolute zero. A date is a real date. A bank balance never goes negative.

- The **constructor** makes it true (or refuses to make the object).
- **Member functions** keep it true.
- **private** data means nothing else can break it.

```cpp
#include <iostream>
#include <stdexcept>

class Temperature {
public:
    explicit Temperature(double kelvin) : kelvin_(kelvin) {
        if (kelvin < 0.0) throw std::invalid_argument("below absolute zero");
    }

    double kelvin() const { return kelvin_; }
    double celsius() const { return kelvin_ - 273.15; }

    void cool(double by) {
        kelvin_ = (by >= kelvin_) ? 0.0 : kelvin_ - by;   // keeps the invariant
    }

private:
    double kelvin_;   // invariant: kelvin_ >= 0
};

int main() {
    Temperature hoth(200.0);   // the ice planet
    hoth.cool(500.0);
    std::cout << "Hoth: " << hoth.celsius() << " C\n";
    try {
        Temperature impossible(-5.0);
    } catch (const std::invalid_argument& e) {
        std::cout << "refused: " << e.what() << '\n';
    }
    return 0;
}
```

## The small words

| Word | Means |
|---|---|
| `public:` / `private:` | who may use what |
| `const` after a member function | it promises not to change the object |
| `explicit` | the constructor won't be used for silent conversions |
| `struct` | a class whose members are public by default: use it for plain data with no invariant |

## Try it

- **Try in sandbox**. Then try to write `hoth.kelvin_ = -1;` in main: the compiler stops you.
- Learn → **A first class**.

> [!sith] The dark side
> A getter and a setter for every member. `setKelvin(-5)` bypasses the invariant. Offer operations that mean something (`cool`, `heat`), not raw access.

## Check yourself

> [!question]- What is a class invariant, and who is responsible for it?
> A condition that's always true for a valid object. The constructor establishes it, the member functions preserve it, and private data stops other code from breaking it.

> [!question]- What does const after a member function's parameter list mean?
> The function promises not to modify the object, so it can be called on const objects and references.

> [!question]- When should you use struct instead of class?
> For plain data with no invariant to protect, where every member can be set to anything.
