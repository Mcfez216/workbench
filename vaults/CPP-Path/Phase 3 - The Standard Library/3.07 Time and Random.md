# 3.07 Time and Random

> [!abstract] Why this matters
> Timing how long something takes, and making random numbers, both look easy. Both also have a classic wrong way. `<chrono>` and `<random>` are the right way, and they're short once you've seen them.

## An example

```cpp
#include <chrono>
#include <iostream>
#include <random>
#include <thread>

int main() {
    using namespace std::chrono_literals;
    using Clock = std::chrono::steady_clock;   // steady: never jumps when the clock is changed

    auto start = Clock::now();
    std::this_thread::sleep_for(20ms);         // units are part of the type
    auto took = std::chrono::duration_cast<std::chrono::milliseconds>(Clock::now() - start);
    std::cout << "took about " << took.count() << " ms\n";

    std::mt19937 rng(std::random_device{}());   // seed once
    std::uniform_int_distribution<int> d6(1, 6); // even odds, 1 to 6 inclusive
    std::cout << "rolls:";
    for (int i = 0; i < 5; ++i) std::cout << ' ' << d6(rng);
    std::cout << '\n';

    std::mt19937 replay(42);                    // a fixed seed gives the same sequence every run:
    std::cout << "seeded: " << d6(replay) << '\n';   // great for tests
    return 0;
}
```

- `steady_clock` measures time. It never jumps, even if someone changes the computer's clock.
- `20ms` is twenty milliseconds. The unit is part of the type, so you can't mix up seconds and milliseconds.
- `std::mt19937` makes random numbers. You give it a starting number, called a **seed**, once.
- `uniform_int_distribution<int> d6(1, 6)` turns them into fair dice rolls from 1 to 6.
- A fixed seed, like `42`, gives the same numbers every time. That's useful for tests.

## Try it

1. Click **Try in sandbox** and run it a few times.
2. The dice rolls change every run. The seeded one stays the same.

> [!sith] The dark side
> Using `rand() % 6` for anything that matters. The numbers aren't very random, and the odds come out slightly uneven. And never use either generator for passwords, keys or tokens, because they can be predicted. Security needs the operating system's own random source.

## Check yourself

> [!question]- Why use steady_clock to measure how long something takes?
> It only ever moves forward, at a steady speed. The normal system clock can jump if someone changes the time.

> [!question]- Why give a random generator a fixed seed in tests?
> It makes the same numbers every run, so you can repeat the test and get the same result.

> [!question]- Is std::mt19937 safe for making passwords?
> No. After seeing some of its numbers, someone can predict the rest. Use a secure random source for passwords.
