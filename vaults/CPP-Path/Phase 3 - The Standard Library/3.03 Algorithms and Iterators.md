# 3.03 Algorithms and Iterators

> [!abstract] Why this matters
> The `<algorithm>` header has over a hundred tested, fast loops with names: sort, find, count, remove, accumulate. A named algorithm says what the loop is for; a hand-written loop makes the reader work it out.

## Iterators: a position in a container

`begin()` points at the first element, `end()` one past the last. Every algorithm takes a range as a pair `[first, last)`, so it works on any container.

```cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <string>
#include <vector>

struct Pilot { std::string name; int kills; };

int main() {
    std::vector<int> scores{42, 7, 99, 7, 13, 64};

    std::sort(scores.begin(), scores.end());                         // 7 7 13 42 64 99
    auto total = std::accumulate(scores.begin(), scores.end(), 0);
    auto sevens = std::count(scores.begin(), scores.end(), 7);
    auto big = std::find_if(scores.begin(), scores.end(), [](int s) { return s > 50; });

    // erase-remove: remove() shuffles the keepers forward, erase() trims the tail
    scores.erase(std::remove(scores.begin(), scores.end(), 7), scores.end());
    // C++20 says it in one call: std::erase(scores, 7);

    std::cout << "total " << total << ", sevens " << sevens << ", first over 50: " << *big << '\n';
    for (int s : scores) std::cout << s << ' ';
    std::cout << '\n';

    std::vector<Pilot> squad{{"Wedge", 7}, {"Biggs", 2}, {"Luke", 9}};
    auto best = std::max_element(squad.begin(), squad.end(),
                                 [](const Pilot& a, const Pilot& b) { return a.kills < b.kills; });
    std::cout << "ace: " << best->name << '\n';
    return 0;
}
```

## The ones to learn first

`sort`, `find` / `find_if`, `count` / `count_if`, `any_of` / `all_of`, `min_element` / `max_element`, `accumulate`, `transform`, `remove_if` + `erase`, `reverse`, `unique`, `binary_search` / `lower_bound` (on sorted data).

## Try it

- **Try in sandbox**. Rewrite the `find_if` as a for loop: notice how much more there is to read.
- Learn → **Algorithms and lambdas**.

> [!sith] The dark side
> `std::remove` alone, without `erase`. It doesn't shrink the container; it just moves the kept elements to the front and leaves junk at the end. The size is unchanged.

## Check yourself

> [!question]- What does end() point to?
> One past the last element: it's a marker, not an element, and must never be dereferenced.

> [!question]- Why do you need erase after remove?
> remove only moves the kept elements forward and returns the new logical end; erase actually removes the leftover tail.

> [!question]- What must be true before you call binary_search or lower_bound?
> The range must be sorted (by the same comparison).
