# 3.01 Containers - vector, array, deque

> [!abstract] Why this matters
> A **container** is an object that holds a collection of values. `std::vector` is the one you'll use most, by far. Knowing how it grows explains how fast it is, and one of its classic bugs.

## Three containers to know first

| Container | Size | Good for |
|---|---|---|
| `std::array<T, N>` | Fixed while compiling | Small fixed sets. It never uses the heap. |
| `std::vector<T>` | Grows | Almost everything. Its elements sit side by side in memory. |
| `std::deque<T>` | Grows at both ends | Adding and removing at the front as well as the back. |

## How a vector grows

A vector has two numbers:

- its **size**, which is how many elements it holds,
- its **capacity**, which is how many fit before it needs more memory.

When the size reaches the capacity, the vector gets a bigger block of memory. It's usually 1.5 or 2 times bigger. Then it moves every element across, and frees the old block.

```cpp
#include <array>
#include <deque>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    std::size_t lastCap = 0;
    for (int i = 0; i < 40; ++i) {
        v.push_back(i);
        if (v.capacity() != lastCap) {
            std::cout << "size " << v.size() << " -> capacity " << v.capacity() << '\n';
            lastCap = v.capacity();
        }
    }

    std::vector<int> planned;
    planned.reserve(1000);          // one allocation up front, if you know the size
    std::cout << "reserved: " << planned.capacity() << '\n';

    std::array<int, 3> moons{1, 2, 3};   // lives on the stack
    std::deque<int> queue{2, 3};
    queue.push_front(1);                 // cheap at the front, unlike vector
    std::cout << moons.size() << ' ' << queue.front() << '\n';
    return 0;
}
```

## Try it

1. Click **Try in sandbox** and run it. Watch the capacity jump each time the vector grows.
2. Add `v.reserve(40);` just before the loop. Run it again. Now it only grows once, because `reserve` asked for enough room up front.
3. Open a small vector in Learn → **Visualise memory**. You'll see its pointer, size and capacity, and the block of memory they describe.

> [!sith] The dark side
> Keeping a pointer, reference or iterator to an element, then calling `push_back`. If the vector grows, every element moves. Your pointer then points at freed memory. AddressSanitizer reports this as heap-use-after-free.

## Check yourself

> [!question]- What's the difference between a vector's size and capacity?
> Size is how many elements it holds. Capacity is how many it has room for before it needs more memory.

> [!question]- Why can push_back make a pointer to an element stop working?
> If the size reaches the capacity, the vector moves all its elements to a new, bigger block and frees the old one. The pointer still points at the old block.

> [!question]- When would you choose std::array over std::vector?
> When the number of elements is fixed and known while compiling. A std::array never uses the heap, and its size is part of its type.
