# 3.01 Containers - vector, array, deque

> [!abstract] Why this matters
> `std::vector` is the container you'll use most of all, by a long way. Knowing how it grows, and when it moves its elements, explains most of its performance and one of its classic bugs.

## The three sequence containers you'll meet first

| Container | Size | Good at |
|---|---|---|
| `std::array<T, N>` | fixed at compile time | small fixed sets; no heap at all |
| `std::vector<T>` | grows | almost everything; elements side by side in memory |
| `std::deque<T>` | grows at both ends | adding and removing at the front too |

## How vector grows

A vector has a **size** (elements in use) and a **capacity** (room already allocated). When size reaches capacity, it allocates a bigger block (usually 1.5x or 2x), moves everything across and frees the old one.

```cpp
#include <array>
#include <deque>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v;
    std::size_t lastCap = 0;
    for (int i = 0; i < 40; ++i) {
        v.push_back(i);
        if (v.capacity() != lastCap) {
            std::cout << "size " << v.size() << " -> capacity " << v.capacity() << '\n';
            lastCap = v.capacity();
        }
    }

    std::vector<int> planned;
    planned.reserve(1000);          // one allocation up front, if you know the size
    std::cout << "reserved: " << planned.capacity() << '\n';

    std::array<int, 3> moons{1, 2, 3};   // lives on the stack
    std::deque<int> queue{2, 3};
    queue.push_front(1);                 // cheap at the front, unlike vector
    std::cout << moons.size() << ' ' << queue.front() << '\n';
    return 0;
}
```

## Try it

- **Try in sandbox**: watch the capacity jump. Then add `v.reserve(40);` before the loop: one line of output.
- Learn → **Visualise memory** on a small vector: the pointer, size and capacity, and the heap block they describe.

> [!sith] The dark side
> Keeping a pointer, reference or iterator into a vector, then calling `push_back`. If it reallocates, everything moved, and your pointer points at freed memory. ASan reports it as heap-use-after-free.

## Check yourself

> [!question]- What's the difference between a vector's size and capacity?
> Size is how many elements it holds; capacity is how many it has room for before it must allocate again.

> [!question]- Why can push_back invalidate a pointer to an element?
> If size reaches capacity, the vector moves all its elements to a new, bigger block and frees the old one.

> [!question]- When would you choose std::array over std::vector?
> When the number of elements is fixed and known at compile time: no heap allocation, and the size is part of the type.
