# 3.06 I/O Streams and Files

> [!abstract] Why this matters
> Almost every real program reads input it doesn't control: a file, a user, a network. Doing it safely means checking every read, and C++ streams make that a one-line habit.

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    const std::filesystem::path log = "crew.txt";

    {   // write: the file closes itself at the end of this block (RAII)
        std::ofstream out(log);
        if (!out) { std::cerr << "can't write " << log << '\n'; return 1; }
        out << "Rey 19\nFinn 23\nPoe 32\nbad line\n";
    }

    std::ifstream in(log);
    if (!in) { std::cerr << "can't read " << log << '\n'; return 1; }
    std::string line;
    int total = 0, lines = 0;
    while (std::getline(in, line)) {           // stops cleanly at the end of the file
        std::istringstream fields(line);
        std::string name;
        int age;
        if (fields >> name >> age) {           // check every read
            total += age;
            ++lines;
        } else {
            std::cerr << "skipping: " << line << '\n';
        }
    }
    std::cout << lines << " crew, average age " << (lines ? total / lines : 0) << '\n';
    std::cout << std::filesystem::file_size(log) << " bytes\n";
    std::filesystem::remove(log);
    return 0;
}
```

## The habits

- Check that the file opened.
- Loop with `while (std::getline(...))` or `while (in >> x)`, never `while (!in.eof())`.
- Parse each line with an `istringstream`, so one bad line can't derail the rest.
- `std::filesystem` handles paths, sizes and directories portably.

> [!sith] The dark side
> `while (!in.eof())`. eof only turns true after a read has already failed, so the loop runs one extra time on a stale or garbage value.

## Check yourself

> [!question]- Why is while (!in.eof()) wrong?
> eof becomes true only after a read fails, so the body runs once more with a failed read; loop on the read itself instead.

> [!question]- Why parse each line with an istringstream?
> A bad line only fails its own small stream; the main input stays in a good state and the next line reads normally.

> [!question]- Who closes an ofstream?
> Its destructor, when it goes out of scope (RAII).
