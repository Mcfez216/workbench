# 3.06 I/O Streams and Files

> [!abstract] Why this matters
> Almost every real program reads input it doesn't control. That might be a file, a person typing, or the network. Doing it safely means checking every read. C++ streams make that a one-line habit.

## An example

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    const std::filesystem::path log = "crew.txt";

    {   // write: the file closes itself at the end of this block (RAII)
        std::ofstream out(log);
        if (!out) { std::cerr << "can't write " << log << '\n'; return 1; }
        out << "Rey 19\nFinn 23\nPoe 32\nbad line\n";
    }

    std::ifstream in(log);
    if (!in) { std::cerr << "can't read " << log << '\n'; return 1; }
    std::string line;
    int total = 0, lines = 0;
    while (std::getline(in, line)) {           // stops cleanly at the end of the file
        std::istringstream fields(line);
        std::string name;
        int age;
        if (fields >> name >> age) {           // check every read
            total += age;
            ++lines;
        } else {
            std::cerr << "skipping: " << line << '\n';
        }
    }
    std::cout << lines << " crew, average age " << (lines ? total / lines : 0) << '\n';
    std::cout << std::filesystem::file_size(log) << " bytes\n";
    std::filesystem::remove(log);
    return 0;
}
```

1. The first block writes four lines to `crew.txt`. The file closes itself at the end of the block.
2. Then it opens the file again, and reads it one line at a time with `getline`.
3. Each line is split into a name and an age with an `istringstream`. That's a stream that reads from a string.
4. If a line doesn't have a name and a number, it's reported and skipped.

## Good habits

- Check that the file opened.
- Loop with `while (std::getline(...))` or `while (in >> x)`. Never with `while (!in.eof())`.
- Read each line with its own `istringstream`. Then one bad line can't stop the rest from being read.
- Use `std::filesystem` for paths, file sizes and folders. It works the same on every system.

> [!sith] The dark side
> Looping with `while (!in.eof())`. `eof` only becomes true *after* a read has already failed. So the loop runs one extra time, using a value that was never read.

## Check yourself

> [!question]- Why is while (!in.eof()) wrong?
> eof only becomes true after a read fails. So the loop runs one more time with a failed read. Loop on the read itself instead.

> [!question]- Why read each line with its own istringstream?
> If a line is bad, only that small stream fails. The main input stays fine, and the next line reads normally.

> [!question]- Who closes an ofstream?
> Its destructor does, automatically, when it goes out of scope. That's RAII.
