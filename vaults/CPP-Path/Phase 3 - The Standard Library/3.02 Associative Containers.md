# 3.02 Associative Containers

> [!abstract] Why this matters
> "Look this up by name" is one of the commonest jobs in programming. Maps and sets do it in one line, and choosing ordered or unordered decides whether you also get sorting.

## The four you'll use

| Container | Holds | Order | Lookup |
|---|---|---|---|
| `std::map<K, V>` | key → value | sorted by key | O(log n) |
| `std::unordered_map<K, V>` | key → value | none | O(1) on average |
| `std::set<K>` | unique keys | sorted | O(log n) |
| `std::unordered_set<K>` | unique keys | none | O(1) on average |

```cpp
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <unordered_map>

int main() {
    std::map<std::string, int> bounty{{"Han", 25000}, {"Chewie", 10000}};
    bounty["Lando"] = 5000;                    // [] inserts if missing
    bounty.insert_or_assign("Han", 30000);     // explicit: insert or replace

    for (const auto& [name, credits] : bounty)  // sorted by name
        std::cout << name << ": " << credits << '\n';

    if (auto it = bounty.find("Boba"); it == bounty.end())
        std::cout << "no bounty on Boba\n";    // find doesn't insert

    std::unordered_map<std::string, int> sightings;
    for (std::string planet : {"Tatooine", "Hoth", "Tatooine", "Endor", "Tatooine"})
        ++sightings[planet];                   // count things in one line
    std::cout << "Tatooine seen " << sightings["Tatooine"] << " times\n";

    std::set<int> codes{5, 1, 5, 3};           // duplicates dropped, sorted
    std::cout << codes.size() << " unique, smallest " << *codes.begin() << '\n';
    std::cout << std::boolalpha << codes.contains(3) << '\n';   // C++20
    return 0;
}
```

## Try it

- **Try in sandbox**. Then print `bounty.size()` after an `if (bounty["Boba"] == 0)` check: the lookup with `[]` added Boba.
- Project [[Projects/Start Here|P05 Log Analyzer]] counts with an unordered_map.

> [!sith] The dark side
> Using `[]` to check whether a key exists: it silently inserts a default value. Use `find`, `contains` or `count` to ask; use `[]` only when you mean "insert if missing".

## Check yourself

> [!question]- When would you choose std::map over std::unordered_map?
> When you need the keys in sorted order (or ordered operations like lower_bound); otherwise unordered_map is usually faster.

> [!question]- Why is m[key] a bad way to check whether a key exists?
> It inserts the key with a default value if it isn't there.

> [!question]- What does a std::set do with duplicates?
> It keeps only one of each value.
