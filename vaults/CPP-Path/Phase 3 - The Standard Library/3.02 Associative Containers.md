# 3.02 Associative Containers

> [!abstract] Why this matters
> "Look this up by name" is one of the most common jobs in programming. Maps and sets do it in one line. Choosing a sorted or unsorted one decides whether you also get the keys in order.

## The four you'll use

A **key** is what you look things up by, like a name.

| Container | Holds | Kept in order? | Lookup speed |
|---|---|---|---|
| `std::map<K, V>` | key → value | Yes, sorted by key | Fast |
| `std::unordered_map<K, V>` | key → value | No | Fastest, on average |
| `std::set<K>` | Each key once | Yes, sorted | Fast |
| `std::unordered_set<K>` | Each key once | No | Fastest, on average |

## An example

```cpp
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <unordered_map>

int main() {
    std::map<std::string, int> bounty{{"Han", 25000}, {"Chewie", 10000}};
    bounty["Lando"] = 5000;                    // [] inserts if missing
    bounty.insert_or_assign("Han", 30000);     // explicit: insert or replace

    for (const auto& [name, credits] : bounty)  // sorted by name
        std::cout << name << ": " << credits << '\n';

    if (auto it = bounty.find("Boba"); it == bounty.end())
        std::cout << "no bounty on Boba\n";    // find doesn't insert

    std::unordered_map<std::string, int> sightings;
    for (std::string planet : {"Tatooine", "Hoth", "Tatooine", "Endor", "Tatooine"})
        ++sightings[planet];                   // count things in one line
    std::cout << "Tatooine seen " << sightings["Tatooine"] << " times\n";

    std::set<int> codes{5, 1, 5, 3};           // duplicates dropped, sorted
    std::cout << codes.size() << " unique, smallest " << *codes.begin() << '\n';
    std::cout << std::boolalpha << codes.contains(3) << '\n';   // C++20
    return 0;
}
```

- `bounty["Lando"] = 5000` adds Lando. If he's already there, it changes his value.
- `find` looks for a key without adding it. If the key isn't there, it returns `end()`.
- `++sightings[planet]` counts things in one line.
- A `set` drops duplicates and keeps the rest sorted.

> [!sith] The dark side
> Using `[]` to check whether a key exists. If it doesn't exist, `[]` quietly adds it, with a default value. To ask, use `find`, `contains` or `count`. Only use `[]` when you mean "add it if it's missing".

## Check yourself

> [!question]- When would you choose std::map over std::unordered_map?
> When you need the keys in sorted order. Otherwise, unordered_map is usually faster.

> [!question]- Why is m[key] a bad way to check whether a key exists?
> If the key isn't there, m[key] adds it with a default value.

> [!question]- What does a std::set do with duplicates?
> It keeps only one of each value.
