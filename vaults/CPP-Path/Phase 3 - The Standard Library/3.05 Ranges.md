# 3.05 Ranges

> [!abstract] Why this matters
> C++20 **ranges** let you pass a whole container, instead of `begin()` and `end()`. You can also chain steps together into a **pipeline**. For example: "keep the even ones, square them, take two". It reads easily, and makes no extra copies.

## An example

```cpp
#include <algorithm>
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> v{5, 2, 8, 1, 9, 4, 6};

    std::ranges::sort(v);                       // no begin()/end() needed
    auto it = std::ranges::find(v, 8);
    std::cout << "found " << *it << '\n';

    // a lazy pipeline: nothing happens until the loop asks for values
    auto pipeline = v
        | std::views::filter([](int x) { return x % 2 == 0; })
        | std::views::transform([](int x) { return x * x; })
        | std::views::take(2);
    for (int x : pipeline) std::cout << x << ' ';   // 4 16
    std::cout << '\n';

    for (int i : std::views::iota(1, 6)) std::cout << i;   // 12345
    std::cout << '\n';
    for (int x : std::views::reverse(v)) std::cout << x << ' ';
    std::cout << '\n';
    return 0;
}
```

- `std::ranges::sort(v)` sorts the whole vector. No `begin()` or `end()` needed.
- The `|` symbol joins steps into a pipeline:
  - `filter` keeps the even numbers,
  - `transform` squares them,
  - `take(2)` keeps the first two.
- `iota(1, 6)` counts from 1 to 5.
- `reverse` goes through the vector backwards.

## Views are lazy

The steps in a pipeline are called **views**. A view doesn't hold any values. It only describes how to make them from something else. Nothing happens until a loop asks for the next value. This is called being **lazy**.

So the pipeline never builds an extra vector. But it also means a view must not last longer than the container it looks at.

## Try it

1. Click **Try in sandbox** and run it. It needs C++20, which is the workbench's default.
2. Add `| std::views::drop(1)` to the end of the pipeline. Run it again, and see what changes.
3. Compare this with the older way in [[3.03 Algorithms and Iterators]].

> [!sith] The dark side
> Making a view of a temporary container, then using the view later. Often this won't even compile. That's the library protecting you, so read the error.

## Check yourself

> [!question]- What does "views are lazy" mean?
> They don't work anything out or store anything when they're made. Each value is made only when a loop asks for it.
