# 3.05 Ranges

> [!abstract] Why this matters
> C++20 ranges let you pass a whole container instead of `begin(), end()`, and chain steps like "keep the even ones, square them, take three" into a readable pipeline that does no extra copying.

```cpp
#include <algorithm>
#include <iostream>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> v{5, 2, 8, 1, 9, 4, 6};

    std::ranges::sort(v);                       // no begin()/end() needed
    auto it = std::ranges::find(v, 8);
    std::cout << "found " << *it << '\n';

    // a lazy pipeline: nothing happens until the loop asks for values
    auto pipeline = v
        | std::views::filter([](int x) { return x % 2 == 0; })
        | std::views::transform([](int x) { return x * x; })
        | std::views::take(2);
    for (int x : pipeline) std::cout << x << ' ';   // 4 16
    std::cout << '\n';

    for (int i : std::views::iota(1, 6)) std::cout << i;   // 12345
    std::cout << '\n';
    for (int x : std::views::reverse(v)) std::cout << x << ' ';
    std::cout << '\n';
    return 0;
}
```

## Views are lazy

A view doesn't hold values; it describes how to produce them from something else. The pipeline above never builds a temporary vector. That also means a view must not outlive the container it looks at.

## Try it

- **Try in sandbox** (it needs `-std=c++20`, the workbench default). Add `| std::views::drop(1)` to the pipeline.
- Compare with the iterator versions in [[3.03 Algorithms and Iterators]].

> [!sith] The dark side
> Building a view over a temporary (`auto evens = make_vector() | std::views::filter(...)` then using it later). Many such cases won't compile, which is the library protecting you; listen to it.

## Check yourself

> [!question]- What does "views are lazy" mean?
> They don't compute or store anything when created; values are produced one at a time as you iterate.

> [!question]- What's the ranges version of std::sort(v.begin(), v.end())?
> std::ranges::sort(v).
