# 3.04 Strings and string_view

> [!abstract] Why this matters
> `std::string` owns its text and manages its memory, so the C-string bugs mostly vanish. `std::string_view` lets functions read text without copying it, which is fast but brings one new rule to remember.

```cpp
#include <iostream>
#include <string>
#include <string_view>

// reads text it doesn't own: accepts string, literals and parts of strings, no copies
std::size_t count_vowels(std::string_view s) {
    std::size_t n = 0;
    for (char c : s)
        if (std::string_view("aeiouAEIOU").find(c) != std::string_view::npos) ++n;
    return n;
}

int main() {
    std::string quote = "Do or do not. There is no try.";

    std::cout << quote.size() << " chars\n";
    auto dot = quote.find('.');                     // position, or std::string::npos
    std::string first = quote.substr(0, dot);       // a new string (a copy)
    std::string_view rest(quote);
    rest.remove_prefix(dot + 2);                    // a view: no copy

    quote += " - Yoda";                             // grows as needed
    std::cout << first << '\n' << count_vowels(first) << " vowels\n";
    std::cout << std::stoi("42") + 1 << ' ' << std::to_string(3.5) << '\n';
    std::cout << std::boolalpha << quote.starts_with("Do") << '\n';   // C++20
    (void)rest;   // careful: += above may have moved quote's text, so rest may now dangle
    return 0;
}
```

## The rule for string_view

A `string_view` is a pointer and a length into **someone else's** text. Use it for parameters. Don't store it, and don't return one that points into a local or temporary string.

## Try it

- **Try in sandbox**. Print `rest` after the `+=`: it may print garbage, or ASan may flag it. That's the dangling view.
- Cheat sheet: [[Cheat Sheet - CPP and STL]].

> [!sith] The dark side
> `std::string_view v = make_name();` where make_name returns a `std::string`. The temporary string dies at the end of the line; the view points at freed memory.

## Check yourself

> [!question]- Why take std::string_view as a parameter instead of const std::string&?
> It accepts string literals and substrings without building a std::string first, so there's no allocation or copy.

> [!question]- What does find return when it doesn't find anything?
> std::string::npos (the largest size_t value).

> [!question]- When is a string_view dangerous?
> When it outlives the text it points into: a temporary string, a local string returned from a function, or a string that was changed so its buffer moved.
