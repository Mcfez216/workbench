# 3.04 Strings and string_view

> [!abstract] Why this matters
> `std::string` owns its text, and manages its memory for you. So most of the bugs from C strings go away. `std::string_view` lets a function read text without copying it. It's fast, but it comes with one new rule to remember.

## An example

```cpp
#include <iostream>
#include <string>
#include <string_view>

// reads text it doesn't own: accepts string, literals and parts of strings, no copies
std::size_t count_vowels(std::string_view s) {
    std::size_t n = 0;
    for (char c : s)
        if (std::string_view("aeiouAEIOU").find(c) != std::string_view::npos) ++n;
    return n;
}

int main() {
    std::string quote = "Do or do not. There is no try.";

    std::cout << quote.size() << " chars\n";
    auto dot = quote.find('.');                     // position, or std::string::npos
    std::string first = quote.substr(0, dot);       // a new string (a copy)
    std::string_view rest(quote);
    rest.remove_prefix(dot + 2);                    // a view: no copy

    quote += " - Yoda";                             // grows as needed
    std::cout << first << '\n' << count_vowels(first) << " vowels\n";
    std::cout << std::stoi("42") + 1 << ' ' << std::to_string(3.5) << '\n';
    std::cout << std::boolalpha << quote.starts_with("Do") << '\n';   // C++20
    (void)rest;   // careful: += above may have moved quote's text, so rest may now dangle
    return 0;
}
```

- `size()` gives the number of characters.
- `find` gives the position of what it found. If it finds nothing, it gives `std::string::npos`.
- `substr` makes a new string from part of another. That's a copy.
- A `string_view` only *looks at* text that belongs to someone else. It makes no copy.
- `+=` adds text to the end. The string grows as needed.

## The rule for string_view

A `string_view` is just a pointer and a length, into someone else's text. So:

- Do use it for function inputs, like `count_vowels` does.
- Don't keep it for later.
- Don't return one that points into a local or temporary string.

## Try it

1. Click **Try in sandbox** and run it.
2. Print `rest` after the `+=` line.
3. It may print nonsense, or AddressSanitizer may report a problem. The `+=` may have moved `quote`'s text, so `rest` now points at freed memory.
4. The cheat sheet [[Cheat Sheet - CPP and STL]] has more.

> [!sith] The dark side
> Writing `std::string_view v = make_name();`, where `make_name` returns a `std::string`. That string is temporary. It's destroyed at the end of the line, and `v` points at freed memory.

## Check yourself

> [!question]- Why take std::string_view as an input instead of const std::string&?
> It accepts text in quotes, and parts of strings, without building a std::string first. So no memory is used and nothing is copied.

> [!question]- What does find return when it doesn't find anything?
> It returns std::string::npos, a special "not found" value.

> [!question]- When is a string_view dangerous?
> When it lasts longer than the text it looks at. For example, text from a temporary string, a local string that was returned, or a string that was changed so its text moved.
