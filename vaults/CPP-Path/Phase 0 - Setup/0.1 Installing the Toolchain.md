# 0.1 Installing the Toolchain

> [!abstract] Why this matters
> A compiler turns your text into a program; the other tools find your mistakes for you. Ten minutes of setup now saves hours of guessing later.

## What you need, and what each one does

| Tool | Job |
|---|---|
| `g++` and `clang++` | compilers: C++ source in, program out |
| `cmake` and `ninja` | build system: works out what to compile, in what order |
| `gdb` | debugger: pause a program, look inside, step through it |
| `clangd` | the editor's brain: completion, errors as you type, go to definition |
| `clang-tidy`, `cppcheck` | static analysers: read your code for bugs |
| `valgrind` | runs a program and watches every memory access |
| `git` | remembers every version of your code |

## Check them

In the workbench: **Help → Which tools are installed?** It ticks off what's there and gives the one command that installs the rest.

Or in a terminal (F5):

```bash
g++ --version
cmake --version
gdb --version
```

## The two tools you'll thank later

**AddressSanitizer** (ASan) and **UndefinedBehaviorSanitizer** (UBSan) are built into the compiler. A program built with `-fsanitize=address,undefined` stops the moment it misuses memory or does something undefined, and says which line. Debug builds in this path always have them on.

> [!holocron] Why this matters so much in C++
> In most languages, reading past the end of an array is an error. In C++ it usually just reads whatever is there, and the program carries on with garbage. The sanitizers turn those silent bugs into loud ones.

## Try it

Open the sandbox (F4), load the example **Break it: use after free (ASan)** and press Ctrl+F9. The line turns red and Problems says what happened. That's the sanitizer working.

> [!sith] The dark side
> Turning the sanitizers off because "the program works without them". It doesn't: it just stopped telling you.

## Check yourself

> [!question]- What does a compiler do, and what does a build system do?
> The compiler turns one source file into machine code. The build system (CMake here) works out which files need compiling, with which flags, in what order, and links the results into programs.

> [!question]- What does AddressSanitizer do when your program reads freed memory?
> It stops the program at that moment and prints a report: what kind of bad access, where it happened, and where the memory was allocated and freed.
