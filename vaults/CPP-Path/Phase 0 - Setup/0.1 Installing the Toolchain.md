# 0.1 Installing the Toolchain

> [!abstract] Why this matters
> A compiler turns your code into a program. The other tools find your mistakes for you. Ten minutes of setting up now saves hours of guessing later.

## The tools, and what each one does

A **toolchain** is the set of programs you use to turn code into a working program.

| Tool | What it does |
|---|---|
| `g++` and `clang++` | Compilers. They turn your C++ code into a program. |
| `cmake` and `ninja` | A build system. It works out what to compile, and in what order. |
| `gdb` | A debugger. It pauses your program so you can look inside it. |
| `clangd` | Helps the editor. It shows suggestions and errors while you type. |
| `clang-tidy`, `cppcheck` | Code checkers. They read your code and point out likely bugs. |
| `valgrind` | Runs your program and watches every memory access. |
| `git` | Keeps every version of your code. |

## Check you have them

In the workbench, open **Help → Which tools are installed?** It ticks off what you have. For anything missing, it gives you the one command that installs it.

Or check in a terminal. Press F5 to open one, then type:

```bash
g++ --version
cmake --version
gdb --version
```

## Two tools you'll be glad of

**AddressSanitizer** (ASan) and **UndefinedBehaviorSanitizer** (UBSan) are checkers built into the compiler. A program built with `-fsanitize=address,undefined` stops the moment it misuses memory. It also stops if it does something the C++ rules don't allow. Either way, it tells you the line. In this path, Debug builds always have them turned on.

> [!holocron] Why this matters so much in C++
> In most languages, reading past the end of an array gives you an error. In C++, it usually just reads whatever is stored there. The program carries on with wrong values, and nobody notices. The sanitizers turn these quiet bugs into loud ones.

## Try it

1. Press F4 to open the sandbox.
2. Load the example **Break it: use after free (ASan)**.
3. Press Ctrl+F9.
4. The line turns red, and the Problems panel says what happened. That's the sanitizer working.

> [!sith] The dark side
> Turning the sanitizers off because "the program works without them". It doesn't really work. It just stopped telling you about the problem.

## Check yourself

> [!question]- What does a compiler do, and what does a build system do?
> A compiler turns one source file into machine code. A build system, like CMake, works out which files need compiling, with which options, and in what order. Then it joins the results into programs.

> [!question]- What does AddressSanitizer do when your program reads freed memory?
> It stops the program at that moment and prints a report. The report says what kind of bad access it was, where it happened, and where the memory was made and freed.
