# 0.3 Neovim and Editor Keys

> [!abstract] Why this matters
> Optional. If you already think in Vim or Emacs keys, the workbench speaks them; if you don't, the standard keys are fine and you can skip this note.

## Choose your keys

Options → Editor keys: **Standard** (Ctrl+S, Ctrl+C...), **Vim**, or **Emacs**. With Vim or Emacs keys, the function keys and Ctrl+Shift combinations still reach the workbench.

## Vim keys that do workbench things

| Type | Does |
|---|---|
| `:w` | save |
| `:CMakeBuild` or `\cb` | build |
| `:CTestAll` or `\ct` | all tests |
| `:CTestHere` or `\cf` | the test under the cursor |
| `gd` / `gr` | go to definition / references |
| `:A` | switch between header and source |
| `:Format` | format the file |

## The same in a real Neovim

The same commands exist in a Neovim setup with clangd (via nvim-lspconfig) and a few lines of Lua mapping `\cb` to `cmake --build build`. You don't need it for this path: the workbench does all of it.

> [!sith] The dark side
> Spending your first week configuring an editor instead of writing C++. Pick something, start, change it later.

## Check yourself

> [!question]- In Vim mode, how do you build and run all the tests?
> `\cb` (or `:CMakeBuild`) builds; `\ct` (or `:CTestAll`) runs every test.
