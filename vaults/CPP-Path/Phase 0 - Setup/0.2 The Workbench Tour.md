# 0.2 The Workbench Tour

> [!abstract] Why this matters
> Six keys cover nearly everything you'll do. Learn them once, and you can stop thinking about the tools and think about your code.

## The six keys

| Key | What it does |
|---|---|
| **F9** | Build. |
| **Ctrl+F9** | Build and run the program you're in. |
| **F7** | Run the tests. In an exercise, it checks your work. |
| **Ctrl+Shift+D** | Start the debugger, stopped at the line your cursor is on. |
| **F4** | Open the sandbox, a scratch file for trying things out. |
| **Ctrl+Shift+P** | Find any command by typing its name. |

Everything else is in the menus. Press F10 to open them.

## Where things are

- **On the left**: Files, Learn (the exercises), Outline, Tests, Git, and Guides (this vault).
- **In the middle**: your files. Shift+click opens a file beside the one you're in.
- **At the bottom**: Terminal, Build output and Problems. Every problem has a **?** button that explains it in plain words.
- **At the top**: the C / C++ switch. Keep it on C++ for this vault.

## A calm setup

- **Settings → Comfort** has a quiet mode, where messages wait in an inbox instead of popping up. It also has less movement on screen, more space between lines, and a reading font.
- **Ctrl+Shift+G** is focus mode. It shows one task and a timer, and hides everything else.
- **Learn → Where was I?** shows what you were doing last time.

## Try it

1. Choose File → Copy the vault's code. Accept `~/cpp-path`.
2. Press Alt+F9 to set up the project. The first time, it downloads Catch2, a test library, so give it a minute.
3. Press F9, then F7. Green ticks appear in the Tests sidebar.
4. Open Learn → First functions. It's your first exercise. F7 checks it.

> [!sith] The dark side
> Reading three notes without running anything. Run every example. Break it on purpose, then run it again.

## Check yourself

> [!question]- What does F7 do inside an exercise, and what does it do everywhere else?
> Inside an exercise, it builds your file with the exercise's tests, and shows which checks pass. Everywhere else, it runs the project's tests.

> [!question]- How do you see an error explained in plain words?
> Click the ? next to it in the Problems panel.
