# 0.2 The Workbench Tour

> [!abstract] Why this matters
> Six keys cover nearly everything you'll do. Learn them once and your hands stop needing your attention.

## The six keys

| Key | Does |
|---|---|
| **F9** | build |
| **Ctrl+F9** | build and run the program you're in |
| **F7** | run the tests (in an exercise: check it) |
| **Ctrl+Shift+D** | debug with gdb, stopped at the line your cursor is on |
| **F4** | the sandbox: a scratch file for trying things |
| **Ctrl+Shift+P** | find any command by name |

Everything else is in the menus (F10) and the command palette.

## Where things are

- **Left**: Files, Learn (exercises), Outline, Tests, Git, Guides (this vault).
- **Middle**: your files, side by side if you like (Shift+click opens beside).
- **Bottom**: Terminal, Build output, Problems. Every problem has a **?** that explains it in plain words.
- **Top**: the C / C++ switch. Keep it on C++ for this vault.

## A calm setup

- Settings → Comfort: quiet mode (messages wait in an inbox), reduced motion, relaxed spacing, a reading font.
- Ctrl+Shift+G: focus mode. One task, a timer, everything else hidden.
- Learn → Where was I?: what you were doing last time.

## Try it

1. File → Copy the vault's code. Accept `~/cpp-path`.
2. Alt+F9 (configure: the first time it downloads Catch2, the test library, so give it a minute).
3. F9, then F7. Green ticks in the Tests sidebar.
4. Learn → First functions: your first exercise. F7 checks it.

> [!sith] The dark side
> Reading three notes without running anything. Run every example, break it on purpose, run it again.

## Check yourself

> [!question]- What does F7 do inside an exercise, and what does it do elsewhere?
> Inside an exercise it compiles your file with the exercise's tests and says which checks pass. Elsewhere it runs the project's tests with ctest.

> [!question]- How do you see an error explained in plain words?
> Press the ? next to it in the Problems panel.
