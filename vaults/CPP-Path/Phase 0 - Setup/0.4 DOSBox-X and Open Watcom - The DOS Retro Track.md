# 0.4 DOSBox-X and Open Watcom - The DOS Retro Track

> [!abstract] Why this matters
> Entirely optional, and entirely fun: compile a program the way it was done on a 1991 PC, and run it in an emulated one. It also shows that C and C++ run almost anywhere, which is a big part of why they matter.

## What you need

- **Open Watcom 2**: a compiler for DOS that still runs on Linux. In the vault's code: `bash scripts/install-open-watcom.sh` (it installs to `~/opt/open-watcom-2`).
- **DOSBox-X**: a PC emulator. Ubuntu: `sudo apt install dosbox-x`.

## Build and run

1. Open `_code/dos/hello.cpp` (your copy: `~/cpp-path/dos/hello.cpp`).
2. Tools → DOS retro track → compile and run in DOSBox-X.

```cpp
#include <iostream>

int main() {
    std::cout << "Hello from 1991. Remember: 640K ought to be enough for anybody.\n";
    return 0;
}
```

## What's different in DOS

- File names are 8.3: `HELLOWLD.EXE`, not `hello_world`. Longer names get shortened to `HELLOW~1.EXE`.
- 16-bit by default: an `int` is 16 bits there, so 32767 + 1 wraps. Your Linux int is 32 bits.
- No sanitizers, no memory protection: a wild pointer can scribble over the operating system itself. You'll appreciate Phase 0's tools afterwards.

> [!sith] The dark side
> Assuming `int` is always 32 bits. It's "at least 16". Use `std::int32_t` when the size matters.

## Check yourself

> [!question]- Why does the same C++ program print a different result for INT_MAX in DOS and on Linux?
> `int` is 16 bits with a 16-bit DOS compiler (INT_MAX is 32767) and 32 bits on Linux (2147483647). The standard only promises at least 16 bits.
