# 0.4 DOSBox-X and Open Watcom - The DOS Retro Track

> [!abstract] Why this matters
> This one is optional, and just for fun. You'll build a program the way people did on a PC in 1991, and run it on a pretend old PC. It also shows that C and C++ run almost anywhere. That's a big part of why they matter.

## What you need

- **Open Watcom 2** is a compiler for DOS, the system PCs ran before Windows. It still runs on Linux. To install it, run `bash scripts/install-open-watcom.sh` in the vault's code. It goes into `~/opt/open-watcom-2`.
- **DOSBox-X** pretends to be an old PC. On Ubuntu, install it with `sudo apt install dosbox-x`.

## Build and run

1. Open `_code/dos/hello.cpp`. Your copy is in `~/cpp-path/dos/hello.cpp`.
2. Choose Tools → DOS retro track, and build and run it in DOSBox-X.

```cpp
#include <iostream>

int main() {
    std::cout << "Hello from 1991. Remember: 640K ought to be enough for anybody.\n";
    return 0;
}
```

## What's different in DOS

- File names can only have 8 letters, a dot, and 3 more, like `HELLOWLD.EXE`. Longer names get cut down to something like `HELLOW~1.EXE`.
- An `int` is 16 bits on DOS, so 32767 + 1 wraps around. On Linux, an `int` is 32 bits.
- Nothing protects memory, and there are no checkers. A bad pointer can write over the operating system itself. You'll be glad of Phase 0's tools afterwards.

> [!sith] The dark side
> Assuming an `int` is always 32 bits. The rules only promise "at least 16". When the size matters, use `std::int32_t`. Its size is in its name.

## Check yourself

> [!question]- Why does the same C++ program show a different INT_MAX on DOS and on Linux?
> A 16-bit DOS compiler makes an int 16 bits, so INT_MAX is 32767. On Linux an int is 32 bits, so INT_MAX is 2147483647. The C++ rules only promise at least 16 bits.
