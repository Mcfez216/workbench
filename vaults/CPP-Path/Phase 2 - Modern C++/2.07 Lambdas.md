# 2.07 Lambdas

> [!abstract] Why this matters
> A lambda is a small function written exactly where you need it: how to compare, what to look for, what to do with each item. They make the standard algorithms pleasant to use.

## The shape

```
[captures](parameters) { body }
```

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> crew{"Rey", "Finn", "Poe", "BB-8"};

    // no captures: a comparison by length
    std::sort(crew.begin(), crew.end(), [](const std::string& a, const std::string& b) {
        return a.size() < b.size();
    });

    // capture by value: the lambda keeps its own copy of minLen
    std::size_t minLen = 4;
    auto longOnes = std::count_if(crew.begin(), crew.end(), [minLen](const std::string& s) { return s.size() >= minLen; });

    // capture by reference: the lambda changes total itself
    std::size_t total = 0;
    std::for_each(crew.begin(), crew.end(), [&total](const std::string& s) { total += s.size(); });

    for (const auto& c : crew) std::cout << c << ' ';
    std::cout << "\nlong names: " << longOnes << ", letters: " << total << '\n';
    return 0;
}
```

## Captures

| Capture | Means |
|---|---|
| `[]` | nothing from outside |
| `[x]` | a copy of x |
| `[&x]` | x itself, by reference |
| `[=]` / `[&]` | everything used, by copy / by reference |
| `[this]` | the current object's members |

## Try it

- **Try in sandbox**. Change `[&total]` to `[total]`: why won't it compile? (A copy captured by value is const in the lambda.)
- Learn → **Algorithms and lambdas**.

> [!sith] The dark side
> Capturing by reference in a lambda that outlives the scope (stored, or run later on another thread). When it runs, the variables are gone: a dangling reference. Capture by value for anything kept.

## Check yourself

> [!question]- What's the difference between [x] and [&x]?
> [x] captures a copy of x when the lambda is made; [&x] refers to the original x, so changes are seen both ways, and x must still exist when the lambda runs.

> [!question]- When is capturing by reference dangerous?
> When the lambda is stored or run later, after the captured variables have gone out of scope.
