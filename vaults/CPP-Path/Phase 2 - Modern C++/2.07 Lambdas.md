# 2.07 Lambdas

> [!abstract] Why this matters
> A **lambda** is a small function you write right where you need it. For example, how to compare two things, or what to look for. Lambdas make the standard algorithms easy to use.

## The shape of a lambda

```
[captures](parameters) { body }
```

- The square brackets list the outside variables the lambda can use. This is called **capturing**.
- The round brackets are its inputs, like any function.
- The curly brackets are its code.

## An example

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> crew{"Rey", "Finn", "Poe", "BB-8"};

    // no captures: a comparison by length
    std::sort(crew.begin(), crew.end(), [](const std::string& a, const std::string& b) {
        return a.size() < b.size();
    });

    // capture by value: the lambda keeps its own copy of minLen
    std::size_t minLen = 4;
    auto longOnes = std::count_if(crew.begin(), crew.end(), [minLen](const std::string& s) { return s.size() >= minLen; });

    // capture by reference: the lambda changes total itself
    std::size_t total = 0;
    std::for_each(crew.begin(), crew.end(), [&total](const std::string& s) { total += s.size(); });

    for (const auto& c : crew) std::cout << c << ' ';
    std::cout << "\nlong names: " << longOnes << ", letters: " << total << '\n';
    return 0;
}
```

## Capturing

| Capture | What it means |
|---|---|
| `[]` | Use nothing from outside. |
| `[x]` | Use a copy of x. |
| `[&x]` | Use x itself, by reference. |
| `[=]` | Use a copy of anything it needs. |
| `[&]` | Use anything it needs, by reference. |
| `[this]` | Use the current object's members. |

## Try it

1. Click **Try in sandbox** and run it.
2. Change `[&total]` to `[total]`, and build it.
3. It won't build. A copied variable can't be changed inside a lambda.
4. For practice, open Learn → **Algorithms and lambdas**.

> [!sith] The dark side
> Capturing by reference in a lambda that runs later. For example, one you store, or run on another thread. By the time it runs, the variables may be gone, and the reference points at nothing. For anything you keep, capture by copy.

## Check yourself

> [!question]- What's the difference between [x] and [&x]?
> [x] takes a copy of x when the lambda is made. [&x] uses the real x, so changes are seen both ways. With [&x], x must still exist when the lambda runs.

> [!question]- When is capturing by reference dangerous?
> When the lambda is kept and run later, after the variables it captured have been destroyed.
