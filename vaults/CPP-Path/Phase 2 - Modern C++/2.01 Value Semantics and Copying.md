# 2.01 Value Semantics and Copying

> [!abstract] Why this matters
> In C++, assigning an object copies it, unlike Java or Python where you copy a reference. That makes code easier to reason about (nobody else can change your copy), but it also means a careless copy of a big vector can cost real time.

## A copy is a copy

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> crew{"Han", "Chewie"};
    std::vector<std::string> copy = crew;   // a whole new vector, new strings
    copy.push_back("Lando");

    std::cout << "crew: " << crew.size() << ", copy: " << copy.size() << '\n';   // 2, 3

    std::vector<std::string>& same = crew;  // a reference: no copy
    same.push_back("Luke");
    std::cout << "crew now: " << crew.size() << '\n';                              // 3
    return 0;
}
```

## When copies happen

| Code | Copies? |
|---|---|
| `T b = a;` | yes |
| `void f(T x)` called with `f(a)` | yes |
| `void f(const T& x)` | no |
| `for (auto s : v)` | yes, every element |
| `for (const auto& s : v)` | no |
| `return local;` | no: moved, or built in place |

## Try it

- **Try in sandbox**, then Learn → Visualise memory: the copy gets its own block on the heap.
- Change a function in your last exercise to take `const std::string&`: same result, no copy.

> [!sith] The dark side
> `for (auto item : bigVector)` copies every element. Write `for (const auto& item : bigVector)` unless you really want copies.

## Check yourself

> [!question]- What does T b = a; do for a std::vector?
> Makes a complete, independent copy: new memory and copies of every element. Changing b doesn't affect a.

> [!question]- Why write for (const auto& x : v) instead of for (auto x : v)?
> The first refers to each element; the second copies each one, which costs time for strings, vectors and other big types.
