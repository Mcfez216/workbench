# 2.01 Value Semantics and Copying

> [!abstract] Why this matters
> In C++, assigning one object to another makes a full copy. Java and Python work differently: there, both names share one object. Copies make code easier to think about, because nobody else can change your copy. But copying a big vector by mistake can cost real time.

## A copy is a separate thing

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> crew{"Han", "Chewie"};
    std::vector<std::string> copy = crew;   // a whole new vector, new strings
    copy.push_back("Lando");

    std::cout << "crew: " << crew.size() << ", copy: " << copy.size() << '\n';   // 2, 3

    std::vector<std::string>& same = crew;  // a reference: no copy
    same.push_back("Luke");
    std::cout << "crew now: " << crew.size() << '\n';                              // 3
    return 0;
}
```

- `copy = crew` makes a whole new vector, with new strings. Adding to `copy` doesn't change `crew`.
- `same` is a reference, not a copy. It's another name for `crew`. Adding through `same` changes `crew`.

## When copies happen

| Code | Does it copy? |
|---|---|
| `T b = a;` | Yes. |
| `f(a)`, where `f` takes `T x` | Yes. |
| `f(a)`, where `f` takes `const T& x` | No. |
| `for (auto s : v)` | Yes, every element. |
| `for (const auto& s : v)` | No. |
| `return local;` | No. It's moved out, or built straight in the caller's variable. |

> [!sith] The dark side
> `for (auto item : bigVector)` copies every element, one by one. Write `for (const auto& item : bigVector)` unless you really want copies.

## Check yourself

> [!question]- What does T b = a; do for a std::vector?
> It makes a complete, separate copy, with its own memory and a copy of every element. Changing b doesn't change a.

> [!question]- Why write for (const auto& x : v) instead of for (auto x : v)?
> The first uses each element where it is. The second copies each element, which takes time for strings, vectors and other big types.
