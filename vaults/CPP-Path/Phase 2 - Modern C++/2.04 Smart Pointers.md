# 2.04 Smart Pointers

> [!abstract] Why this matters
> Smart pointers own heap objects and delete them for you. They remove leaks, double frees and most use-after-frees by design, which is a big part of why modern C++ is much safer than C.

## The three

| Type | Ownership | Use when |
|---|---|---|
| `std::unique_ptr<T>` | exactly one owner | the default |
| `std::shared_ptr<T>` | shared, counted | several owners, no clear last one |
| `std::weak_ptr<T>` | not an owner | watching a shared_ptr without keeping it alive (breaks cycles) |

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Ship {
    explicit Ship(const char* n) : name(n) { std::cout << name << " launched\n"; }
    ~Ship() { std::cout << name << " docked\n"; }
    const char* name;
};

int main() {
    auto solo = std::make_unique<Ship>("Falcon");          // one owner
    std::vector<std::unique_ptr<Ship>> fleet;
    fleet.push_back(std::move(solo));                      // ownership moves into the vector
    std::cout << "solo is " << (solo ? "set" : "empty") << '\n';

    auto rebel = std::make_shared<Ship>("Home One");       // shared owners
    auto copy = rebel;
    std::cout << "owners of Home One: " << rebel.use_count() << '\n';
    return 0;   // everything docks here, in reverse order: no delete anywhere
}
```

## Rules of thumb

- Make them with `std::make_unique` / `std::make_shared`, never `new`.
- Pass `T&` or `T*` to functions that only **use** the object; pass the smart pointer only to code that takes or shares **ownership**.
- `unique_ptr` costs nothing over a raw pointer. `shared_ptr` costs a counter and atomic updates.

- **Try in sandbox** (also the sandbox example "Smart pointers").

> [!sith] The dark side
> Two `shared_ptr`s pointing at each other: neither count reaches zero, nothing is freed. A leak with smart pointers. Make one side a `weak_ptr`.

## Check yourself

> [!question]- When should you choose unique_ptr over shared_ptr?
> By default: whenever one owner is enough. shared_ptr is for genuinely shared ownership, and costs a reference count.

> [!question]- How do you pass an object to a function that only uses it, not owns it?
> As a reference (T& / const T&) or a raw pointer if it may be null: not as a smart pointer.

> [!question]- How can shared_ptr still leak?
> A cycle: two objects holding shared_ptrs to each other keep each other's count above zero. Breaking it with a weak_ptr fixes it.
