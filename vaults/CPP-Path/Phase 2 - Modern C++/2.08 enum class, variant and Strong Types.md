# 2.08 enum class, variant and Strong Types

> [!abstract] Why this matters
> The more your types say, the more mistakes the compiler catches: a speed passed as a distance, a state that can't exist, a "one of these" handled as "any of these". Small types are free in C++ and pay for themselves fast.

## enum class

```cpp
enum class Side { Light, Dark };   // scoped: write Side::Light, and no silent int conversion
```

Unlike plain `enum`, an `enum class` doesn't convert to `int` by accident, and its names don't leak into the surrounding scope.

## std::variant: exactly one of several types

```cpp
#include <iostream>
#include <string>
#include <variant>
#include <vector>

enum class Side { Light, Dark };

struct Jedi { std::string name; };
struct Sith { std::string name; int rage; };
struct Droid { std::string model; };

using Character = std::variant<Jedi, Sith, Droid>;

// a "strong type": a double that knows it's a distance
struct Parsecs { double value; };
double fuel_for(Parsecs d) { return d.value * 1.5; }

int main() {
    std::vector<Character> cast{Jedi{"Luke"}, Sith{"Vader", 9}, Droid{"R2-D2"}};
    for (const auto& c : cast) {
        std::visit([](const auto& who) {
            using T = std::decay_t<decltype(who)>;
            if constexpr (std::is_same_v<T, Jedi>) std::cout << who.name << ": light side\n";
            else if constexpr (std::is_same_v<T, Sith>) std::cout << who.name << ": dark side, rage " << who.rage << '\n';
            else std::cout << who.model << ": beeps\n";
        }, c);
    }
    std::cout << "fuel: " << fuel_for(Parsecs{12}) << '\n';
    // fuel_for(12.0);   // won't compile: a bare number isn't a distance
    Side s = Side::Light;
    std::cout << (s == Side::Light ? "light\n" : "dark\n");
    return 0;
}
```

## Try it

- **Try in sandbox**. Add a fourth alternative to the variant without handling it in the `visit`: the last `else` catches it. Better: make each branch explicit.
- Uncomment `fuel_for(12.0)`: the compiler refuses a bare number.

> [!sith] The dark side
> "Stringly typed" code: a state as a string ("open", "Open", "OPEN"...) or a bool parameter nobody can read at the call site (`connect(true, false)`). Use an enum class.

## Check yourself

> [!question]- Name two advantages of enum class over a plain enum.
> Its values don't convert to int implicitly, and its names are scoped (Side::Light), so they don't clash with other names.

> [!question]- What does std::variant<A, B, C> hold?
> Exactly one value, of type A, B or C, and it knows which; std::visit handles each case.

> [!question]- What is a "strong type", and what does it prevent?
> A small wrapper type (struct Parsecs { double value; }) that gives meaning to a plain value, so passing the wrong kind of number becomes a compile error.
