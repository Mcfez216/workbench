# 2.08 enum class, variant and Strong Types

> [!abstract] Why this matters
> The more your types say, the more mistakes the compiler can catch. For example, passing a speed where a distance is expected. Small types like these cost nothing in C++, and they save you a lot of bugs.

## enum class

```cpp
enum class Side { Light, Dark };   // scoped: write Side::Light, and no silent int conversion
```

An `enum class` is a list of named values. You write `Side::Light`. A plain `enum` turns into an int without asking, but an `enum class` doesn't. Its names also don't clash with other names.

## std::variant: exactly one of several types

```cpp
#include <iostream>
#include <string>
#include <variant>
#include <vector>

enum class Side { Light, Dark };

struct Jedi { std::string name; };
struct Sith { std::string name; int rage; };
struct Droid { std::string model; };

using Character = std::variant<Jedi, Sith, Droid>;

// a "strong type": a double that knows it's a distance
struct Parsecs { double value; };
double fuel_for(Parsecs d) { return d.value * 1.5; }

int main() {
    std::vector<Character> cast{Jedi{"Luke"}, Sith{"Vader", 9}, Droid{"R2-D2"}};
    for (const auto& c : cast) {
        std::visit([](const auto& who) {
            using T = std::decay_t<decltype(who)>;
            if constexpr (std::is_same_v<T, Jedi>) std::cout << who.name << ": light side\n";
            else if constexpr (std::is_same_v<T, Sith>) std::cout << who.name << ": dark side, rage " << who.rage << '\n';
            else std::cout << who.model << ": beeps\n";
        }, c);
    }
    std::cout << "fuel: " << fuel_for(Parsecs{12}) << '\n';
    // fuel_for(12.0);   // won't compile: a bare number isn't a distance
    Side s = Side::Light;
    std::cout << (s == Side::Light ? "light\n" : "dark\n");
    return 0;
}
```

- A `std::variant<Jedi, Sith, Droid>` holds exactly one value. It can be a Jedi, a Sith or a Droid, and it knows which.
- `std::visit` runs your code with whichever one it holds.
- `Parsecs` is a **strong type**. It's a small struct that gives a plain number a meaning. Now `fuel_for` only accepts a distance, not any number.

## Try it

1. Click **Try in sandbox** and run it.
2. Remove the `//` in front of `fuel_for(12.0);`, and build it. The compiler refuses a plain number.
3. Put the `//` back. Add a fourth type to the variant, but don't handle it in `visit`. The last `else` catches it. It's better to handle each type by name.

> [!sith] The dark side
> Keeping a state as text, like "open", "Open" or "OPEN", which is easy to get wrong. Or calling a function with true and false values nobody can understand, like `connect(true, false)`. Use an `enum class` instead.

## Check yourself

> [!question]- Name two advantages of enum class over a plain enum.
> Its values don't turn into an int without you asking. And its names stay inside it, like Side::Light, so they don't clash with other names.

> [!question]- What does a std::variant<A, B, C> hold?
> Exactly one value, of type A, B or C. It knows which one it holds. std::visit handles each case.

> [!question]- What is a strong type, and what does it prevent?
> A small type that gives a plain value a meaning, like struct Parsecs { double value; }. It stops you passing the wrong kind of number, because that becomes a compile error.
