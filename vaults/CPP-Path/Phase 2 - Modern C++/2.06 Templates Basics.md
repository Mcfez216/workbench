# 2.06 Templates Basics

> [!abstract] Why this matters
> Templates let you write code once for any type: that's how `std::vector<T>` works for ints, strings and your own classes. You'll mostly use templates rather than write them, but knowing how they work makes their (famous) error messages readable.

## A function template

```cpp
#include <concepts>
#include <iostream>
#include <string>

template <typename T>
T largest(const T& a, const T& b) {
    return (a < b) ? b : a;
}

// C++20 concepts: say what the type must be able to do
template <std::integral T>
T half(T x) { return x / 2; }

template <typename T>
struct Pair {            // a class template
    T first, second;
    T sum() const { return first + second; }
};

int main() {
    std::cout << largest(3, 9) << '\n';                                 // T = int
    std::cout << largest(std::string("Han"), std::string("Leia")) << '\n';  // T = std::string
    std::cout << half(11) << '\n';
    // half(2.5);   // error: double doesn't satisfy std::integral, and the message says so
    Pair<double> p{1.5, 2.25};
    std::cout << p.sum() << '\n';
    return 0;
}
```

The compiler writes a separate version for each type you use (instantiation). That's why templates live in headers: the compiler needs the whole body to write a new version.

## Reading template errors

When a template breaks deep inside the library, the compiler prints the chain of "required from here". **The first line in your own file is the one that matters**. The workbench's Problems list already jumps there and folds the library's notes underneath.

## Try it

- **Try in sandbox**, then uncomment `half(2.5);`: a short, clear error, thanks to the concept.
- Learn → **Algorithms and lambdas** uses templates you don't see.

> [!sith] The dark side
> Writing a template where an overload or a plain function would do. Templates are powerful, but every new one is more compile time and harder error messages.

## Check yourself

> [!question]- Why are templates usually defined in header files?
> The compiler needs the template's full definition wherever it's used, to generate code for each type.

> [!question]- What does a concept like std::integral do?
> Constrains a template parameter: the template only accepts types that satisfy it, and misuse gives a short, direct error.

> [!question]- In a long template error, which line do you read first?
> The first one that points at your own code (the "required from here" in your file).
