# 2.05 const, constexpr and consteval

> [!abstract] Why this matters
> `const` is a promise the compiler checks: "this won't change". `constexpr` goes further: "work this out while compiling". Both turn whole kinds of bugs into compile errors. The second can also make programs faster, for free.

## const: this won't change

```cpp
const int maxCrew = 6;              // can't be changed
void print(const std::string& s);   // the function promises not to change s
int Ship::fuel() const;             // this member function doesn't change the object
const int* p;                       // the int can't be changed through p
int* const q = &x;                  // q itself can't be re-pointed
```

To read a pointer declaration, go from right to left. `const int*` reads as "pointer to an int that's const".

## constexpr: work it out while compiling

```cpp
#include <array>
#include <iostream>

constexpr long long factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}

constexpr int parsecs = 12;   // a compile-time constant

int main() {
    constexpr long long f10 = factorial(10);    // computed by the compiler
    static_assert(f10 == 3628800);              // checked while compiling
    std::array<int, factorial(4)> slots{};      // sizes must be compile-time: 24
    std::cout << f10 << ' ' << slots.size() << " Kessel Run in " << parsecs << " parsecs\n";
    std::cout << factorial(5) << '\n';          // also callable at run time
    return 0;
}
```

- A `constexpr` function **can** run while compiling, if its inputs are known then. If they aren't, it runs normally when the program runs.
- A `consteval` function (C++20) **must** run while compiling.
- `static_assert` checks something while compiling. If it's false, the build fails.

In the example, the compiler works out `factorial(10)` itself. The finished program just contains the answer.

## Try it

1. Click **Try in sandbox** and run it.
2. Change `3628800` in the `static_assert` to any other number. Now the program won't build.
3. Change it back. Turn on the sandbox's **Assembly** view. `f10` is just a number in there. No multiplying is left.

> [!sith] The dark side
> Using `const_cast` to change something that was made const. This is undefined behaviour. The compiler may have already assumed the value never changes.

## Check yourself

> [!question]- What does a const member function promise?
> That calling it won't change the object. This means it can be called on const objects too.

> [!question]- What's the difference between a constexpr function and a consteval function?
> A constexpr function runs while compiling when it can, or else while the program runs. A consteval function must always run while compiling.

> [!question]- What is static_assert for?
> Checking something while compiling. If the check is false, the build fails with your message.
