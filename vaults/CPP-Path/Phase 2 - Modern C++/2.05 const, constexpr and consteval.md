# 2.05 const, constexpr and consteval

> [!abstract] Why this matters
> `const` is a promise the compiler enforces: this won't change. `constexpr` goes further: work this out while compiling. Both turn whole classes of bugs into compile errors, and the second makes some programs faster for free.

## const: won't change

```cpp
const int maxCrew = 6;              // can't be changed
void print(const std::string& s);   // the function promises not to change s
int Ship::fuel() const;             // this member function doesn't change the object
const int* p;                       // the int can't be changed through p
int* const q = &x;                  // q itself can't be re-pointed
```

Read pointer declarations right to left: `const int*` is "pointer to const int".

## constexpr: work it out at compile time

```cpp
#include <array>
#include <iostream>

constexpr long long factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}

constexpr int parsecs = 12;   // a compile-time constant

int main() {
    constexpr long long f10 = factorial(10);    // computed by the compiler
    static_assert(f10 == 3628800);              // checked while compiling
    std::array<int, factorial(4)> slots{};      // sizes must be compile-time: 24
    std::cout << f10 << ' ' << slots.size() << " Kessel Run in " << parsecs << " parsecs\n";
    std::cout << factorial(5) << '\n';          // also callable at run time
    return 0;
}
```

- A `constexpr` function **can** run at compile time when its arguments are known then; otherwise it runs normally.
- `consteval` (C++20) **must** run at compile time.
- `static_assert` checks a condition while compiling: a failed one is a compile error.

## Try it

- **Try in sandbox**, then change `3628800` in the static_assert: the program no longer compiles.
- Turn on the sandbox's **Assembly** view: `f10` is just a number in the code, no multiplication left.

> [!sith] The dark side
> Casting `const` away with `const_cast` to change something that was declared const. That's undefined behaviour, and the compiler may have already assumed it never changes.

## Check yourself

> [!question]- What does a const member function promise?
> That calling it doesn't modify the object (so it can be called on const objects).

> [!question]- What's the difference between constexpr and consteval functions?
> A constexpr function can be evaluated at compile time when possible, or at run time otherwise; a consteval function must always be evaluated at compile time.

> [!question]- What is static_assert for?
> Checking a condition at compile time: if it's false, compilation fails with your message.
