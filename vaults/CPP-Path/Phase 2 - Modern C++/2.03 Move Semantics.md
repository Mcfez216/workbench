# 2.03 Move Semantics

> [!abstract] Why this matters
> **Moving** lets one object hand over its memory to another, instead of copying it. That's why returning a big vector from a function is cheap. It's also why a `unique_ptr` can be passed around at all.

## Copy or move

```cpp
#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main() {
    std::vector<std::string> a{"one", "two", "three"};
    std::vector<std::string> b = std::move(a);   // b takes a's buffer: no strings copied

    std::cout << "a has " << a.size() << ", b has " << b.size() << '\n';
    // a is valid but unspecified: it's legal to reuse it after assigning
    a = {"fresh"};
    std::cout << "a reused: " << a[0] << '\n';
    return 0;
}
```

`b = std::move(a)` gives `a`'s memory to `b`. No strings are copied.

After the move, `a` is still a valid vector, but you can't rely on what's in it. It's fine to give it new contents, as the example does.

## What std::move really does

On its own, nothing. It just marks the object as "you may take my contents". The thing receiving it does the actual taking. Usually it copies the memory address across, and sets the old object's address to empty.

## When moves happen by themselves

- When you return a local variable: `return result;`
- When you pass a temporary value: `v.push_back(std::string("x"));`
- And whenever you write `std::move` yourself.

## Handing something over

```cpp
void keep(std::vector<int> data);   // by value: the caller decides copy or move
keep(myData);                       // copies
keep(std::move(myData));            // moves: myData is now empty-ish
```

A function that takes its input by value lets the caller choose. Pass the variable, and it's copied. Pass `std::move` of it, and it's moved, which leaves your variable more or less empty.

> [!sith] The dark side
> Using an object after moving from it, as if it still had its contents. After a move, only give the object new contents, or let it be destroyed.

> [!sith] Also dark
> Writing `return std::move(local);`. This stops the compiler from building the result straight in the caller's variable. Just write `return local;`.

## Check yourself

> [!question]- What does std::move do by itself?
> Nothing while the program runs. It marks an object as "may be moved from", so a move constructor or move assignment gets chosen instead of a copy.

> [!question]- What state is an object in after it's been moved from?
> It's still valid, but you can't rely on its contents. You can give it new contents, or let it be destroyed.

> [!question]- Why shouldn't you write return std::move(local);?
> It stops the compiler skipping the copy altogether. A plain return local; is already a move at worst.
